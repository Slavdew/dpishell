# Договор: управление обходом на роутере из Windows-приложения

Версия API 1, 2026-10-16. Сторона роутера — пакет `dpishell` (`06-router-spec.md`), сторона ПК — DpiShell для Windows. Документ — единственный источник формата: меняется только с увеличением `api`.

## 1. Как это устроено

- На роутере работает `rpcd` (штатная часть OpenWRT). Через него страница DpiShell в меню роутера вызывает методы объекта `dpishell`. Windows-приложение вызывает **те же методы тем же путём** — отдельного сервера для приложения нет.
- Транспорт: JSON-RPC 2.0, `POST http://<адрес роутера>/ubus`, `Content-Type: application/json`.
- Роутер принимает запросы только из домашней сети (uhttpd слушает LAN, fw4 закрывает WAN).

## 2. Поиск роутера

1. Адрес по умолчанию — основной шлюз IPv4 активного адаптера (у пользователя сейчас `192.168.1.1`; после сторонняя прошивка OpenWrt обычно `192.168.1.1`). В настройках можно указать свой адрес (IP или имя, без схемы и пути).
2. `GET http://<адрес>/dpishell/status.json`, таймаут 1 с, без входа. Роутер с DpiShell — если `product == "dpishell-router"`. Формат — `06-router-spec.md` §5.2 + поле `"api": 1`.
3. Нет ответа / 404 / другой `product` — «На роутере DpiShell не найден». Приложение работает как раньше, только с ПК.
4. `api` у роутера больше, чем знает приложение — «Обновите приложение», разрешено только чтение статуса. Меньше — «Обновите пакет на роутере».

## 3. Вход

```json
→ {"jsonrpc":"2.0","id":1,"method":"call","params":["00000000000000000000000000000000","session","login",{"username":"root","password":"<пароль>","timeout":600}]}
← {"jsonrpc":"2.0","id":1,"result":[0,{"ubus_rpc_session":"c1ed6c7b…","timeout":600,"expires":600,…}]}
```
- Пароль — пароль администратора роутера (тот же, что для меню). Хранится на ПК через DPAPI (`ProtectedData`, `CurrentUser`), в логи и отчёты не попадает.
- Сессия живёт `timeout` секунд с последнего вызова. Код `6` (нет доступа) в ответе на любой вызов — войти заново один раз; снова `6` — «Неверный пароль или сессия», запросить пароль.
- `result[0] == 6` на `login` — неверный пароль.

## 4. Вызов метода

```json
→ {"jsonrpc":"2.0","id":2,"method":"call","params":["<ubus_rpc_session>","dpishell","<метод>",{…аргументы…}]}
← {"jsonrpc":"2.0","id":2,"result":[0,{…ответ…}]}
```
- `result[0]` — код ubus: `0` успех, `2` неверные аргументы, `4` метода/объекта нет (пакет не установлен или старый), `6` нет доступа, `7` таймаут, `5` ответа нет.
- Ошибка уровня DpiShell при коде `0`: `{"error":{"code":"busy","text":"Идёт подбор"}}`. Коды: `busy`, `not_installed` (ядро не загружено), `invalid` (с полем `field`), `conflict` (работает чужой обход), `core_mismatch` (хеш ядра), `failed` (с `text`).
- Таймаут HTTP — 10 с. Долгие операции (подбор, проверка, загрузка ядра) только запускаются и возвращаются сразу; ход — опросом `status`/`select_progress` раз в 1 с.

## 5. Методы

Время — ISO 8601 UTC. Идентификаторы стратегий — как в `strategies.json` / `user-strategies.json`.

### 5.1 Чтение

**`status`** `{}` →
```json
{ "api": 1, "version": "0.1.0", "engine": "zapret1",
  "core": { "version": "v72.13", "installed": true, "hash_ok": true },
  "enabled": true, "strategy": "alt10", "backups": ["alt9", "alt13"],
  "last_check": { "at": "2026-10-16T21:00:00Z", "source": "timer", "ok": true,
                  "groups": [ { "id": "youtube", "ok": true }, { "id": "discord", "ok": true } ] },
  "fail_streak": 0,
  "schedule": { "enabled": true, "hours": 6 },
  "jobs": { "select": false, "check": false, "core_install": false, "dns_analyze": false },
  "warnings": [ { "code": "flow_offload", "text": "Включён flow offloading" } ] }
```
`source`: `manual` | `timer` | `app`. Коды `warnings`: `flow_offload`, `ipv6`, `dns_spoofed`, `conflict`, `core_missing`, `switched_backup` (сработала запасная стратегия, в `text` — какая), `dns_fallback` (защищённый DNS недоступен, временно DNS провайдера).

**`strategies`** `{}` → `{ "catalog_version": 3, "items": [ { "id": "alt10", "title": "general (ALT10)", "source": "catalog|user", "runs": 7, "passed": 6 } ] }` — порядок как в списке выбора (по статистике).

**`select_progress`** `{}` →
```json
{ "running": true, "index": 4, "total": 20, "message": "alt3: YouTube",
  "rows": [ { "id": "alt", "group_share": 1.0, "target_share": 0.88, "avg_s": 0.74, "error": null } ],
  "finished_at": null, "best": null, "restore_at": null }
```
После завершения — `best` (id) и `restore_at`: время, когда роутер вернёт прежнюю стратегию, если не вызвать `apply`.

**`targets_get`** `{}` → `{ "items": [ { "url": "https://example.com/", "important": true } ] }` — только «Свои адреса» роутера.

**`lists_get`** `{ "name": "user-general" | "user-exclude" }` → `{ "lines": ["example.com"] }`.

**`diag`** `{}` → `{ "conflicts": [ { "kind": "service", "name": "zapret2", "running": true } ], "flow_offload": false, "ipv6_wan": false, "dns": { "spoofed": true, "checked_at": "…" }, "overlay_free_kb": 18000 }`.

**`report`** `{}` → `{ "text": "…" }` — то же, что «Сохранить отчёт» на странице.

**`dns_status`** `{}` → `{ "mode": "provider" | "doh", "spoofed": true, "checked_at": "…", "servers": [ { "name": "Google", "doh_ok": true, "ms": 38 }, { "name": "Cloudflare", "doh_ok": true, "ms": 41 } ], "fallback_active": false }` — `fallback_active`: оба DoH пропали, временно работает DNS провайдера (06-router-spec §3.8).

### 5.2 Действия

| Метод | Аргументы | Что делает | Ответ |
|---|---|---|---|
| `enable` | `{}` | включает обход с текущей стратегией | `{}` или `error` |
| `disable` | `{}` | выключает | `{}` |
| `strategy_set` | `{ "id": "alt9" }` | выбор стратегии; при включённом обходе — перезапуск | `{}` |
| `check_now` | `{}` | запускает проверку (результат — в `status.last_check`, `source: app`) | `{ "started": true }` |
| `select_start` | `{ "groups": ["youtube","discord","user"], "mode": "full" \| "quick", "depth": "main" \| "deep" }` | запускает подбор | `{ "started": true }` |
| `select_cancel` | `{}` | останавливает, возвращает прежнее | `{}` |
| `apply` | `{ "id": "alt9", "backups": ["alt13"] }` | применяет итог подбора | `{}` |
| `schedule_set` | `{ "enabled": true, "hours": 6 }` (`hours` ∈ 1, 3, 6, 12, 24) | таймер проверки | `{}` |
| `targets_set` | `{ "items": [ { "url": "…", "important": true } ] }` | свои адреса (до 50) | `{}` |
| `lists_set` | `{ "name": "user-general", "lines": [ … ] }` | свои списки (домены по шаблону, до 5000 строк) | `{}` |
| `strategies_user_set` | `{ "items": [ { "id": "u-…", "title": "…", "roles": { "google": "…" } } ] }` | загрузить найденные на ПК стратегии (§6) | `{}` или `error: invalid` |
| `dns_analyze` | `{}` | анализ DNS (06-router-spec §3.8), результат — в `dns_status` | `{ "started": true }` |
| `dns_enable` | `{}` | включить защищённый DNS для всей сети, прежние настройки сохраняются | `{}` или `error` |
| `dns_restore` | `{}` | вернуть DNS как было | `{}` |
| `conflict_stop` | `{ "name": "zapret2" }` (только имя из `diag.conflicts`) | остановить и отключить чужой обход | `{}` |
| `core_install` | `{}` | загрузить ядро по манифесту | `{ "started": true }` |

Роутер проверяет всё сам: стратегии — по `options.json`, домены — по шаблону, длины — по лимитам. Командной строки и путей от клиента не принимает.

## 6. Что приложение делает с этим (для Windows-стороны)

- **Настройки → «Роутер»**: адрес (по умолчанию «Автоматически — основной шлюз»), пароль, кнопка «Подключиться», строка состояния («Подключено, DpiShell 0.1.0» / «DpiShell на роутере не найден» / «Неверный пароль»).
- **Главный экран**, если роутер найден и обход на нём включён: блок «Обход делает роутер — стратегия N, проверено в 14:00». Кнопки: Включить/Выключить на роутере, Проверить, Подобрать на роутере, выбор стратегии. Обход на этом ПК при этом по умолчанию выключен; включить можно с предупреждением о двойной обработке.
- **Подбор на роутере**: тот же диалог, что для ПК (группы, режим, глубина), таблица из `select_progress`, «Применить на роутере».
- **Стратегия с ПК → на роутер**: найденную глубоким поиском на ПК стратегию можно отправить на роутер (`strategies_user_set` + `strategy_set`). Путь ПК → провайдер идёт через роутер, поэтому стратегия, найденная на ПК при выключенном обходе на роутере, обычно подходит и роутеру; после отправки — `check_now`.
- **Свои адреса и списки роутера** — отдельная вкладка «На роутере» в тех же экранах, с ПК не синхронизируются автоматически (кнопка «Скопировать с ПК»).
- **DNS роутера**: в разделе DNS — «Для всей сети (роутер)»: `dns_status`, «Проверить», «Включить защищённый DNS» с теми же последствиями, что на странице роутера, «Вернуть как было».
- **Диагностика**: раздел «Роутер» — `diag`, кнопки «Остановить» у конфликтов, «Сохранить отчёт роутера».
- Сеть сменилась (ноутбук ушёл из дома) — роутер не найден, блок пропадает, приложение работает как обычно.

## 7. Тестирование без роутера

Роутерной стороны пока нет. Для тестов Windows-стороны — фейковый сервер в памяти (`HttpListener` или `TestServer`), который отвечает по этому документу: примеры ответов — разделы 3–5 дословно. Случаи для тестов: роутер не найден; `status.json` без `api`; неверный пароль; истёкшая сессия (`6` → повторный вход → успех); метод отсутствует (`4`); `busy`; подбор от `running: true` до `best` и `restore_at`.

## 8. Вопросы Windows-стороны (2026-10-16, к согласованию)

Формат не менялся; ниже — как приложение ведёт себя сейчас там, где договор молчит, и что нужно подтвердить.

1. **`status.json` без поля `api`** (случай из §7). §2.4 описывает только «больше» и «меньше». Сейчас приложение считает отсутствие `api` старым пакетом: «Обновите пакет на роутере», только чтение статуса. Подтвердить или указать иное.
2. **«Нет доступа» при истёкшей сессии.** По договору — `result[0] == 6`. Штатный `uhttpd-mod-ubus` при неверной/истёкшей сессии отвечает ошибкой JSON-RPC `{"error":{"code":-32002,"message":"Access denied"}}`, без `result`. Приложение сейчас принимает оба варианта как код 6 (повторный вход один раз). Какой из них роутер возвращает на самом деле — зафиксировать в §3–4.
3. **`strategies_user_set`, формат стратегии.**
   - `id`: приложение шлёт `u-` + id на ПК, например `u-found-261016-2213-2`. Допустимые символы и длина?
   - Значения ролей на ПК содержат подстановку `{fake}/<файл>.bin` (например `--dpi-desync-fake-tls={fake}/tls_clienthello_www_google_com.bin`) и `!` (встроенный фейк). Принимает ли роутер эту же запись и тот же набор файлов `fake/`? Если нет — в каком виде отправлять.
   - Набор ролей на ПК: `quic`, `discord_udp`, `discord_media`, `google`, `general`, `ipset_udp`, `ipset_tcp`. Совпадает ли с ролями роутера (§4.2 `06-router-spec.md`)? Роли, которых у роутера нет, — отбрасывать на ПК или роутер вернёт `invalid`?
4. **`error.field` при `invalid`** — что в нём: имя аргумента (`items`), путь (`items[3].url`)? Нужно, чтобы показать пользователю, какая строка не понравилась роутеру.
5. **`select_start` с `depth: "deep"`** — это глубокий поиск по `02-spec.md` §4.7 (генерация кандидатов) или «основные + расширенный каталог»? Сколько длится — чтобы показать оценку времени.
6. **Подбор, запущенный с другого устройства.** Если `jobs.select == true`, а приложение подбор не запускало, — показывать ход (`select_progress`) и разрешать `select_cancel`? Приложение сейчас так и делает.
