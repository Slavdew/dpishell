# Аудит функций Flowseal/zapret: игровой режим, IP-списки, hosts

Источники: `Flowseal/zapret-discord-youtube` @ `eb16c14` (ссылки `service.bat:N`, `general.bat:N`, `README.md:N`), `bol-van/zapret` master (`readme.md:N` = `docs/readme.md`, `windows.md:N` = `docs/windows.md`, `ipset/*`), PR/issues Flowseal, RDAP (`rdap.org`), DoH (`dns.google`). Как эти функции сделаны в DpiShell — [../dev/architecture.md](../dev/architecture.md); проверка взятых данных — [../vetting.md](../vetting.md).

## Итог

1. **Игровой режим** — берём во вторую версию как переключатель «Игры» с тремя вариантами (TCP+UDP / TCP / UDP). Это два профиля winws на порты 1024–65535 по IP-списку с `--dpi-desync-any-protocol=1` и `--dpi-desync-cutoff`. Без загруженного IP-списка он ничего не делает (у Flowseal по умолчанию тоже: заглушка `203.0.113.113/32`). Цена: все UDP-пакеты на верхних портах (торренты, uTP) идут через winws в user mode — до 100 % ядра CPU (`windows.md:97-101`), пользователи Flowseal жалуются на +200–500 мс пинга (discussion #4049). По умолчанию выключен, Flowseal тоже выключил «из-за массы проблем» (README.md:145, #4049).
2. **IP-списки (ipset)** — берём с режимами «Выкл / По списку / Все адреса». «Все адреса» (`any`) = обход для любого IP без проверки домена — ломает много сайтов (README.md:201), только как временный тест с автовозвратом.
3. **Список Flowseal `ipset-service.txt`** — это не список заблокированного, а **полные дампы префиксов ~100 автономных систем** (Cloudflare, Amazon, Google Cloud, Azure, Akamai, Hetzner, OVH, Lumen, Cogent, Telia, NTT…; PR #17737) с `stat.ripe.net`: 26 038 IPv4 + 7 010 IPv6, **10,3 % всего IPv4**, есть `3.0.0.0/8`, `8.0.0.0/9`. Ведёт один человек (V3nilla, репозиторий `V3nilla/IPSets-For-Bypass-in-Russia`), принимает Flowseal по PR раз в 1–2 месяца. Берём, но через **свой манифест с sha256** (список меняется редко, хеш на каждую нашу версию данных работает) + валидация при загрузке (формат, запрет приватных/`/0`, лимит на долю адресного пространства, лимит на отличие от прошлой версии).
4. **hosts** — Flowseal подменяет адреса GitHub (на чужой Fastly-узел в Филиппинах вместо выданных DNS `185.199.108-111.133`), Telegram Web и Discord (`discord.com` → 4 из 5 IP Cloudflare, без заблокированного `162.159.136.232`). Это обход **блокировок по IP**, DoH этого **не закрывает** (DoH чинит подмену DNS, а не недоступность IP). Записи устаревают: сегодня с этой машины `162.159.136.232` отвечает 200, а `149.154.167.220` для `web.telegram.org` и Fastly-IP для `raw.githubusercontent.com` — не отвечают. Делать — **только как отдельную кнопку «Починить адреса» с предпросмотром, своим размеченным блоком, резервной копией, живой проверкой каждой записи (TLS-рукопожатие к IP с SNI домена и проверкой сертификата) и «Вернуть как было»**; по умолчанию выключено; при провале проверки записи не ставить. Defender помечает правку hosts как `SettingsModifier:Win32/HostsFileHijack` — нужна заметная подсказка, исключения в Defender сами не добавляем.
5. **Нам самим важно**: наши обновления (`data.json`, `core.json`) идут с `raw.githubusercontent.com`, который блокируют по IP (PR #17088) — нужен запасной адрес (релизы GitHub через `objects.githubusercontent.com` тоже Fastly/185.199; значит — зеркало вне GitHub или встроенные данные как запас).
6. Из прочего берём: `discord.media` (уже есть), проверку обновлений по `version.txt`-подобному манифесту (манифест данных), диагностику конфликтов (Killer, Intel Connectivity, Check Point, SmartByte, Adguard, кириллица/OneDrive в пути, TCP timestamps, BFE), «Проверить всё» по `targets.txt`. Не берём: `--hostlist-auto` (v3, под вопрос), `--ssid-filter/--nlm-filter` (управляем из приложения), «DPI checkers» (сторонний JSON с чужого сайта исполнять не будем), очистку кэша Discord (сомнительно, но дёшево — вопрос).

## 1. Игровой режим (game filter)

**Что делает.** Обычно обход смотрит только на порты сайтов (80/443 и несколько других). Игры и голосовые программы ходят на случайные порты 1024–65535, по своим протоколам без имени сайта внутри. «Игровой режим» заставляет winws обрабатывать и эти порты, но только к адресам из IP-списка, и подсовывать DPI приманки в первых пакетах каждого соединения.

**Как у Flowseal.**
- Файл `utils/game_filter.enabled` c `mode=disabled|all|tcp|udp`, `tcp=1024-65535`, `udp=1024-65535` (`service.bat:733-784, 892-898`); диапазоны проверяются (`service.bat:855-889`: числа ≤ 65535, начало ≤ конец). Выключен → подставляется порт `12` (заглушка, `service.bat:742-744`).
- Диапазон добавляется в `--wf-tcp`/`--wf-udp` (`general.bat:16`) — WinDivert отдаёт winws **весь** трафик этих портов (LAN-адреса отсечены фильтром WinDivert, `windows.md:91`).
- Два профиля (`general.bat:24-25`):
  - TCP: `--filter-tcp=<диапазон> --ipset=ipset-all.txt --ipset-exclude=… <десинк общей роли> --dpi-desync-any-protocol=1 --dpi-desync-cutoff=n3`;
  - UDP: `--filter-udp=<диапазон> --ipset=… --dpi-desync=fake --dpi-desync-repeats=12 --dpi-desync-any-protocol=1 --dpi-desync-fake-unknown-udp=ACTIVE_GAME_UDP.bin --dpi-desync-cutoff=n2` (в ALT4 — `repeats=10`, TCP `fake,multisplit`).
- Смысл опций: `--dpi-desync-any-protocol=1` — применять десинк ко всем пакетам с данными, а не только к HTTP/TLS (`readme.md:245`); `--dpi-desync-cutoff=nN` — прекратить после N исходящих пакетов (`readme.md:261, 746-750`), иначе приманки шли бы в каждом пакете игры; `--dpi-desync-fake-unknown-udp` — свой фейк вместо 64 нулей (`readme.md:793`). Для неизвестного протокола split-позиция = 5 (`readme.md:525`); с `badseq` при any-protocol советуют increment `0x80000000` (`readme.md:349`).
- Требует перезапуска winws (`service.bat:828`). Фейк для UDP меняется пунктом «Replace active fakes» (`service.bat:931-1041`).
- **Работает только при загруженном IP-списке**: профили с `--ipset=ipset-all.txt`, а в релизе список — заглушка (`lists/ipset-all.txt` = `203.0.113.113/32`, режим `none`). README.md:197-199: «обновите ipset и включите Game Filter».

**Риски.**
- CPU/скорость: user-mode обработка всего UDP верхних портов — торренты, uTP, «до 100 % одного ядра», обрезание гигабита, шум кулера (`windows.md:97-101`). Flowseal: «IPset и GameFilter снижает скорость… поднимает пинг на 200–500 мс» (discussion #4049); «Game Filter отключён по умолчанию из-за большого количества проблем» (там же); README.md:145 — при проблемах с игрой/приложением сначала выключить.
- Ломает не-игровое: любой протокол к адресам из списка (а список — 10 % IPv4, включая Amazon/Azure/Google Cloud) получает приманки в первых 2–3 пакетах: VPN/WireGuard к хостеру, RDP, SSH, почта, игры, у которых DPI нет. Фейки TCP с `badseq` при потоковой передаче и потерях могут мешать (`readme.md:345-349`).
- Автопроверить нельзя: нет универсальной «цели» игры; проверяется только «включилось, winws жив, `--dry-run` прошёл» и опрос пользователя «стало лучше?». Для Discord-голоса есть отдельный профиль (`--filter-l7=discord,stun`, `readme.md:789`) — он не требует игрового режима.

**Для каких игр.** Flowseal: гайд #10241 (Apex, Titanfall 2, WWZ, Fortnite…), Roblox #6800. Общий рецепт README.md:192-203: обновить ipset → включить game filter → если нет, `ipset any` временно → найти IP игры и добавить в `ipset-all.txt`. Исследовать каждую игру «нет возможности» (README.md:194).

**Как у нас.** Роли `game_tcp`, `game_udp` в каталоге (`Strategies.cs` RoleOrder, `WfTcp/WfUdp` + диапазон при включении), переключатель «Игры: выкл / TCP+UDP / только TCP / только UDP», при включении автоматически загружается IP-список; статус «работает по N адресам из списка». Как сделано — [../dev/architecture.md](../dev/architecture.md), «Игровой режим».

## 2. IP-списки: режимы `none / loaded / any`

**У Flowseal** статус определяется содержимым `lists/ipset-all.txt` (`service.bat:1045-1061`): файл пуст → `any`; содержит `203.0.113.113/32` → `none`; иначе `loaded`. Переключение по кругу `loaded → none → any → loaded` (`service.bat:1064-1107`) через переименование в `.backup`; из `any` в `loaded` без `.backup` нельзя («Update list first», `service.bat:1099`).

**Что значит.** Профили `ipset_udp`/`ipset_tcp` (`general.bat:22-23`) и игровые (`:24-25`) фильтруют по `--ipset`. Пустой include-лист = отсутствие ограничения (для hostlist — `readme.md:1658-1660`; для ipset Flowseal полагается на то же, в docs zapret для ipset прямо не проверено) → `any` = обход для **любого** адреса на 80/443/8443 TCP и 443 UDP без имени сайта (hostlist-exclude ещё действует). `none` = профили ничего не ловят. `loaded` = только адреса списка.

**Когда нужен обход по IP, а не по домену.** Когда в трафике нет имени: Discord voice (UDP, но его ловит `--filter-l7=discord,stun`), игры, приложения с TLS без SNI/с ESNI, HTTP/3 к IP, а также когда провайдер режет **по IP** (там обход не поможет вовсе — нужна смена IP, см. hosts). Зачем Flowseal такой широкий список: блокировка «16 КБ» (замедление TLS-соединений к зарубежным хостерам — PR #12317) бьёт по целым AS, домены заранее неизвестны.

**Чем опасен `any`.** Приманки во все соединения: сайты «через раз» (README.md:201: «появятся проблемы с открытием многих сайтов… не используйте на постоянной основе»), банковские/госсайты с чувствительным DPI, принтеры/NAS в интернете; скрипт тестов Flowseal сам переключает в `any` на время тестов и предупреждает (`utils/test zapret.ps1:382-385`). У нас — только «Временно, на 10 минут, для проверки» с автовозвратом и явным предупреждением.

## 3. Обновление IP-списка

**Откуда у Flowseal.** `service.bat:1116` качает `raw.githubusercontent.com/Flowseal/zapret-discord-youtube/refs/heads/main/.service/ipset-service.txt` (curl или PowerShell `Invoke-WebRequest`, без проверки содержимого, перезапись на месте — `:1120-1135`). Тот же файл с CRLF лежит как `lists/ipset-all.txt.backup` (в релизе). Ветка `main`, не релиз: хеша/подписи нет, меняется без версии.

**Кто и как составляет.** PR от V3nilla раз в 1–2 месяца (2025-10 → 2026-09: 10 PR; последний #17737 от 2026-09-26, +6456/−4612 строк). Источник — `V3nilla/IPSets-For-Bypass-in-Russia`: префиксы автономных систем с `stat.ripe.net`, «AS Parser» складывает CIDR; список ~100 AS в теле PR #17737 (Cloudflare 13335, Amazon 16509, Google 15169, Microsoft 8075, Akamai ×20, Hetzner, OVH, DigitalOcean, Lumen 3356, Cogent 174, Telia 1299, NTT 2914, Riot 6507, i3D/Discord 49544…). Валидации в репозитории не описано.

**Размер/формат.** 539 879 байт, 33 048 строк, `ip/len` IPv4 и IPv6 по одной на строку, без комментариев, без дублей, без приватных сетей. Префиксы IPv4: 2×`/8` (`3.0.0.0/8` Amazon), 2×`/9` (`4.0.0.0/9`, `8.0.0.0/9`), …, 11 757×`/24`, 285×`/32`. Сумма — 443 млн адресов = **10,32 % IPv4**. winws читает файл сам, перечитывает при изменении без перезапуска (`readme.md:284`), поддерживает gzip.

**Как у zapret (Linux).** `ipset/get_*.sh` (`readme.md:1555-1651`): antifilter.download (`ip.lst`, `ipsum.lst`, `allyouneed.lst` — агрегаты реестра РКН), antifilter.network `ipsmart.lst`, `1andrevich/Re-filter-lists` (`get_refilter_ipsum.sh:10`), rublacklist (домены → `mdig`). Это списки **заблокированного** (реестр), а не хостеров — иная логика, чем у V3nilla. Защиты в скриптах: `--max-filesize 41943040`, «файл меньше 100 КБ — подозрителен, выход» (`antifilter.helper:8-14`), `cut_local` отбрасывает `192.168./127./10.` (`def.sh:219-226`), `ip2net` «отсекает неправильные записи» (`readme.md:1630`), `sort -u`; обновлять не чаще раза в 2 суток (`readme.md:1601`). На Windows ничего этого нет — Flowseal качает «как есть».

**Что плохого может быть в списке.** `0.0.0.0/0`, `::/0` или `/1–/4` = фактически `any`; приватные/служебные сети (`10/8`, `192.168/16`, `127/8`, `169.254/16`, `224/4`, `fc00::/7`) = приманки в LAN/мультикаст; адреса DNS-серверов (`1.1.1.0/24`, `8.8.8.0/24` — в списке **есть** `1.0.0.0/24`, `1.1.1.0/24`!) — попадают под профиль `ipset_udp` на 443 (DoH) и TCP 443 — это, видимо, намеренно (Cloudflare AS), но делает DoH-проверки зависимыми от стратегии; мусор/не-CIDR строки (winws может отказать загружать); резкий рост (в 10 раз) — ошибка парсера; подмена файла на пути (HTTP без проверки → MITM на DPI; HTTPS без pin — доверие CA Windows).

**Как закрепить источник и проверять.**
- Хеш **можно**: мы публикуем данные сами через `data.json` (манифест данных) с sha256 на каждую версию; список обновляется раз в 1–2 месяца — ручная ревизия PR V3nilla/Flowseal при подготовке нашей версии. Не пинимся на `main` Flowseal напрямую.
- Автопроверка при подготовке и при загрузке на машине (одинаковый код): регулярка `^(\d{1,3}\.){3}\d{1,3}/\d{1,2}$` или IPv6 `/\d{1,3}`; разбор и нормализация (host-биты = 0); запрет префиксов короче `/8` (IPv4) и `/19` (IPv6) и всего списка `ipset-exclude.txt`; сумма IPv4 ≤ 15 % (сейчас 10,3 %; порог — вопрос); строк 1 000–100 000; размер 50 КБ–4 МБ; отличие от прошлой версии ≤ 40 % строк (иначе «нужна ручная проверка»); без дублей. Нарушение — список отклонён, остаётся прошлый, в журнал.
- Хранить `ipset-all.txt` + `ipset-all.prev.txt` + дату; показывать «N подсетей, обновлён <дата>, покрывает X % адресов».

## 4. Обновление hosts

**Что кладёт Flowseal** (`.service/hosts`, 82 строки, последнее изменение 2026-09-20): `github.com → 140.82.121.3`; 18 имён `*.githubusercontent.com` (raw, objects, release-assets, avatars0-8, camo, media, gist, cloud, private-user-images) → `146.75.22.132` и `2606:50c0:8000::154`; 35 имён Telegram (`web.telegram.org`, `t.me`, `telegram.org`, `api.telegram.org`, `cdn1-6.telesco.pe`, `oauth.telegram.org`…) → `149.154.167.220`; `discord.com`, `updates.discord.com` → 4 IP Cloudflare `162.159.{138,137,128,135}.x`.

**Зачем** (по PR, не по README): PR #17088 — IP `185.199.108-111.133` (GitHub Pages/githubusercontent) заблокированы, поэтому взят IPv6 из `raw.githubusercontent.com` и «IPv4 от Fastly с Филиппин» (узел CDN, который DNS для этих имён не выдаёт); PR #16741 — `162.159.136.232` «наглухо заблокирован по TCP и UDP на ТСПУ», Discord 3–5 минут запускается, пока не переберёт IP; hosts оставляет 4 рабочих. Telegram (PR #15948, коммиты «tg hosts», «new telegram hosts») — для веб-версии: DNS даёт `149.154.167.99`, hosts ведёт на `.220` в той же сети Telegram. README.md:74 обещает «починку веб версии телеграма и подключения к голосовому чату Discord» — про голос в PR/файле ничего нет (voice-серверы `*.discord.gg` в hosts отсутствуют); заявление не подтверждено, строки Discord чинят запуск клиента.

**Как применяет пользователь.** `service.bat:1143-1209`: качает файл с cache-buster, сравнивает только первую и последнюю строку с системным hosts (`:1174-1193`), если не найдены — открывает Notepad с файлом и проводник на `drivers\etc`, пользователь копирует вручную от администратора (README.md:105-109). Автоматически hosts не пишется — сознательно.

**Проверка владельцев IP (RDAP, 2026-10-17).** `140.82.121.3` — GITHU (ARIN `NET-140-82-112-0-1`); `146.75.22.132` — FASTLY (`146.75.0.0/16`); `2606:50c0:8000::154` — GITHU (`2606:50c0:8000::/46`); `149.154.167.220` — `Telegram_Messenger_Network` (RIPE, `149.154.164.0/22`); `162.159.x` — Cloudflare (`CLOUD14`). Все IP принадлежат ожидаемым компаниям или их CDN — подмены на чужие серверы нет.

**Проверка записей вживую** (один провайдер, один момент времени — не общий вывод): адрес `github.com@140.82.121.3` отвечал с валидным сертификатом; «заблокированный» по PR адрес Discord `162.159.136.232` отвечал 200 (блокировка снята или зависит от провайдера — запись устарела); для `web.telegram.org`/`t.me@149.154.167.220` TLS-рукопожатие не проходило; `raw.githubusercontent.com` не отвечал ни по адресу из hosts, ни по DNS-овому. Вывод: часть записей за 4 недели устаревает или зависит от провайдера, а проверка «первая/последняя строка есть в hosts» этого не замечает — поэтому каждая запись должна проверяться на месте перед установкой.

**Риски правки hosts.**
- Перехват: кто контролирует файл-источник, тот направляет `github.com`/`t.me` куда угодно (компрометация аккаунта/репозитория, MITM при скачивании). TLS спасает от подмены содержимого, но не от отказа в обслуживании и не для HTTP.
- Устаревание: CDN-узлы и Cloudflare-IP меняются; запись в hosts «вечная», DNS-балансировка и геолокация отключаются (Fastly в Филиппинах — задержка).
- Антивирусы: Defender `SettingsModifier:Win32/HostsFileHijack` / `PossibleHostsFileHijack` — Microsoft советует добавить hosts в исключения (support.microsoft.com, «Hosts file is detected as malware»), что мы делать за пользователя не должны.
- Конфликты: блокировщики рекламы (AdGuard, hosts-списки), корпоративные политики, другие «фиксы» (Flowseal, GoodbyeDPI-гайды) пишут в тот же файл; Flowseal сравнивает строки, не разбирая чужие блоки.
- Flowseal сам предупреждает, что записи `youtube.com` в hosts ломают YouTube (`service.bat:588-597`).
- Права/атомарность: запись требует администратора; половинная запись при сбое; кодировка/BOM и CRLF.

**Безопасный вариант у нас** (как сделано — [../dev/architecture.md](../dev/architecture.md), «Починить адреса»): отдельная кнопка, выключено по умолчанию; свой блок `# DpiShell begin … # DpiShell end` с датой и версией, чужие строки не трогаем, при удалении убираем только свой блок; перед записью — предпросмотр «домен → адрес → владелец → проверка»; резервная копия `hosts.<дата>.bak` в нашей папке данных и «Вернуть как было»; **белый список доменов** (только `github.com`, `*.githubusercontent.com`, Telegram, `discord.com`, `updates.discord.com` — список в нашем манифесте); **для каждой записи живая проверка**: TCP 443 к IP, TLS с SNI домена, сертификат валиден для домена (это доказывает, что узел легитимно обслуживает домен — сильнее, чем ASN), плюс RDAP-владелец из ожидаемого набора; не прошло — запись не ставится/снимается; ежедневная перепроверка блока, устаревшие снимаются с уведомлением; предупреждение про Defender до записи. Данные — наш манифест с sha256 (файл маленький, меняется раз в месяц — хеш работает), источник для ревизии — PR Flowseal.

**Сравнение с DoH ([dns.md](dns.md)).** DoH устраняет **подмену ответов DNS** (NXDOMAIN, заглушки) — для `youtube.com`, `discord.com` у провайдера с ложным DNS. Записи Flowseal решают другую задачу — **IP заблокирован на ТСПУ**: DoH честно выдаст `185.199.108.133`, и он так же не ответит. Что закрывается DoH: ничего из списка Flowseal напрямую; косвенно — Discord получит все 5 IP и сам переберёт (3–5 минут, PR #16741). Что не закрывается: GitHub-загрузки при блокировке по IP, Telegram Web. Альтернативы без hosts: для **наших** загрузок — свой клиент сам выбирает IP/зеркало (не нужен hosts); для браузера/клиентов — только hosts или локальный DNS-прокси (вне рамок). Итог: hosts — отдельная необязательная функция для двух случаев (GitHub, Telegram Web), а не замена DNS-блоку.
