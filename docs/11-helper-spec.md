# ТЗ: окно без прав администратора + помощник (служба)

Версия 0.1, 2026-10-17. Решение пользователя: окно открывается без прав администратора; права запрашиваются **один раз** — при установке помощника; данные ПК и роутер доступны сразу.

## 1. Что без прав, что через помощника

| Без прав (окно само) | Через помощника (служба, SYSTEM) |
|---|---|
| Проверка сайтов («Проверить сейчас»), DNS-проверка | Включить/выключить обход на ПК (служба winws или процесс) |
| Статистика подборов, список стратегий, найденные | Подбор, глубокий поиск (запускают winws) |
| Состояние служб (`sc query`, реестр `ImagePath` — читаются без прав) | Починить адреса (запись hosts), временные метки TCP |
| Обнаружение чужих обходов (процессы — без командной строки чужих elevated-процессов; стратегию узнаёт помощник) | IP-списки, игровой режим (меняют аргументы службы) |
| Управление роутером (сеть + пароль роутера) | Установка/восстановление ядра, «Удалить полностью», «Остановить» чужой обход |
| Тема, настройки окна, свои адреса — черновик до сохранения | Запись в `%ProgramData%\DpiShell` (папка только SYSTEM+Администраторы) |

Кнопки второй колонки до установки помощника — со значком щита; нажатие → «Нужен помощник DpiShell: один запрос прав администратора, дальше без вопросов» → установка → действие продолжается.

## 2. Помощник

- Тот же `DpiShell.exe` с ключом `--helper`, работающий как служба Windows `DpiShellHelper` (SYSTEM, автозапуск). Копия исполняемого файла и `data\` — в `%ProgramData%\DpiShell\helper\` (папка закрыта правами: иначе обычный пользователь подменил бы файл, который система запускает от SYSTEM).
- Установка: окно запускает `DpiShell.exe --install-helper` с `runas` (единственный UAC) → копирование, `sc create`, права на канал, запуск. Обновление приложения новее помощника → тот же путь (UAC — только при обновлении версии).
- Служба обхода (`DpiShell`, winws) остаётся отдельной, как сейчас: помощник управляет ею, но не заменяет её. «Режим службы» выключен → winws запускает помощник как процесс в своём объекте задания и гасит, когда окно отключилось от канала (и при остановке помощника).

## 3. Канал и команды

- Именованный канал `\\.\pipe\DpiShell.Helper`. Доступ (DACL): SYSTEM, Администраторы, **пользователь, установивший помощника** (SID сохраняется при установке). Помощник дополнительно проверяет клиента (`GetNamedPipeClientProcessId` → SID токена) — другие пользователи компьютера управлять не могут.
- Формат: строки JSON (`{"id":1,"cmd":"enable","args":{"strategy":"alt9"}}` → `{"id":1,"ok":true,…}`), события хода подбора — сообщения с тем же `id` и `"progress":{…}` до финального ответа; отмена — `{"cmd":"cancel","target":<id>}`.
- **Белый список команд** с проверкой аргументов: `status`, `enable {strategy}`, `disable`, `set_run_mode {service:bool}`, `select {quick, groups}`, `search {base, groups}`, `cancel`, `ipset_mode`, `all_addresses_start/stop`, `game_mode`, `ipset_update {from: manifest|file-content}`, `user_ipset_set`, `user_targets_set`, `hosts_check/preview/apply/revert/recheck`, `stop_foreign`, `core_repair`, `remove_all`, `clear_history`, `read_results` (только наши файлы, адреса уже скрыты), `details` (только чтение: состояние hosts, свои подсети, проверка ядра, найденные стратегии), `choose {strategy}` (выбрать стратегию, не включая обход). Идентификаторы стратегий — из каталога; **командной строки, путей и произвольных файлов помощник не принимает** (тот же принцип, что в договоре с роутером). Обновление IP-списка из файла — окно передаёт содержимое, помощник прогоняет валидатор.
- Окно без помощника — те же экраны, данные «только чтение» (состояние, статистика из своей копии результатов — см. §4).

## 4. Данные

- Папка `%ProgramData%\DpiShell` остаётся закрытой. Окну без прав нужны: состояние, каталог+найденные, статистика, результаты (без адресов) — их отдаёт помощник командой `status`/`read_results`; до установки помощника — каталог из поставки, статистики нет («появится после первого подбора»).
- Настройки окна (тема, закрытие, адрес и пароль роутера под DPAPI CurrentUser) — в `%LocalAppData%\DpiShell\window.json` (принадлежат пользователю, админ не нужен). Обходные настройки (стратегия, режимы, свои адреса) — у помощника.

## 5. Безопасность (проверить тестами)

- Канал: подключение от процесса другого пользователя — отказ; неизвестная команда, лишние поля, id стратегии не из каталога, путь в аргументах — отказ с кодом `invalid`.
- Исполняемый файл службы — только из закрытой папки; при старте помощник проверяет свои права на папку (`IsHardened`) и хеш ядра.
- Пароль роутера не идёт через помощника вовсе (роутером управляет окно).

## 6. Порядок работ

1. Ядро: протокол (модели команд/ответов, валидация), сервер канала (в тестах — в процессе, без службы), клиент; тесты безопасности.
2. Хост службы `--helper`, установка `--install-helper` (UAC), удаление.
3. Окно: `asInvoker` вместо `requireAdministrator`; все действия второй колонки — через клиента; щит и установка по первому требованию; настройки окна в `%LocalAppData%`.
4. Живая проверка пользователем: установка (один UAC), включение/выключение, подбор, закрытие окна в режиме без службы, перезагрузка.
