# Протокол окно ↔ помощник (Windows)

Окно DpiShell работает без прав администратора. Всё, что требует прав, делает служба-помощник `DpiShellHelper`; права запрашиваются один раз — при её установке. Здесь — что через кого делается, формат канала, белый список команд и правила безопасности. Реализация: `src/DpiShell.Core/Helper/` (`HelperProtocol.cs`, `HelperCommands.cs`, `HelperServer.cs`, `HelperInstaller.cs`, `HelperCompat.cs`), тесты — `tests/DpiShell.Tests/Helper*Tests.cs`.

## 1. Что без прав, что через помощника

| Без прав (окно само) | Через помощника (служба, SYSTEM) |
|---|---|
| Проверка сайтов («Проверить сейчас»), DNS-проверка | Включить/выключить оптимизацию на ПК (служба winws или процесс) |
| Статистика подборов, список стратегий, найденные | Подбор, глубокий поиск (запускают winws) |
| Состояние служб (`sc query`, реестр `ImagePath` — читаются без прав) | Починить адреса (запись hosts), временные метки TCP |
| Обнаружение чужих обходов (процессы — без командной строки чужих elevated-процессов; стратегию узнаёт помощник) | IP-списки, игровой режим (меняют аргументы службы) |
| Управление роутером (сеть + пароль роутера) | Установка/восстановление ядра, «Удалить полностью», «Остановить» похожую программу |
| Тема, настройки окна, свои сайты — черновик до сохранения; системный прокси «для этого пользователя» (HKCU) и свой список прокси | Запись в `%ProgramData%\DpiShell` (папка только SYSTEM+Администраторы); DNS этого компьютера; обновление данных; системный прокси для всей машины, для пользователя «с правами администратора», прокси WinHTTP |

Кнопки второй колонки до установки помощника — со значком щита; нажатие → «Нужен помощник DpiShell: один запрос прав администратора, дальше без вопросов» → установка → действие продолжается.

## 2. Помощник

- Тот же `DpiShell.exe` с ключом `--helper`, работающий как служба Windows `DpiShellHelper` (SYSTEM, автозапуск). Копия исполняемого файла и `data\` — в `%ProgramData%\DpiShell\helper\` (папка закрыта правами: иначе обычный пользователь подменил бы файл, который система запускает от SYSTEM).
- Установка: окно запускает `DpiShell.exe --install-helper` с `runas` (единственный UAC) → копирование, `sc create`, права на канал, запуск. Приложение новее помощника → тот же путь (UAC — только при смене версии). Занятый exe службы заменяется после её остановки (`DeleteWhenReleased`).
- Служба оптимизации (`DpiShell`, winws) остаётся отдельной: помощник управляет ею, но не заменяет её. «Режим службы» выключен → winws запускает помощник как процесс в своём объекте задания и гасит, когда окно отключилось от канала (и при остановке помощника).

## 3. Канал и команды

- Именованный канал `\\.\pipe\DpiShell.Helper`. Доступ (DACL): SYSTEM, Администраторы, **пользователь, установивший помощника** (SID сохраняется при установке). Помощник дополнительно проверяет клиента (олицетворение → SID токена) — другие пользователи компьютера управлять не могут. Для действий на весь компьютер — ещё и образ процесса клиента (§5, «Действия на весь компьютер», API 1.14).
- Формат: строки JSON (`{"id":1,"cmd":"enable","args":{"strategy":"alt9"}}` → `{"id":1,"ok":true,…}`), одна строка UTF-8 = один объект, конец — `\n`. После подключения окно шлёт `{"hello":{"protocol":1}}`, помощник отвечает `{"hello":{"protocol":1,"api":"1.14","version":"<версия программы>","machine":true}}` (версии — §6; `machine` — с 1.14, §5). События хода подбора — сообщения с тем же `id` и `"progress":{…}` до финального ответа; отмена — `{"cmd":"cancel","target":<id>}`. Одновременно выполняется одна операция, кроме команд только для чтения (`status`, `details`, `dns_status`, `hosts_preview`, `read_results`, `rec_status`, `app_profiles`, `cancel`).
- **Белый список команд** с проверкой аргументов (`HelperCommands.Specs`):
  - состояние и выбор: `status`, `details` (только чтение: состояние hosts, свои подсети, проверка ядра, найденные стратегии), `read_results` (только наши файлы, свои сайты уже скрыты), `clear_history`, `choose {strategy}` (выбрать стратегию, не включая оптимизацию);
  - оптимизация: `enable {strategy}`, `disable`, `set_run_mode {service:bool}`, `select {quick, groups, dns?}`, `search {base, groups, dns?}`, `cancel`;
  - свои стратегии ([architecture.md](architecture.md), «Свои стратегии»): `strategy_add {title, roles, source}` (`source` — `user|pasted`; `title` — до 60 знаков без управляющих; `roles` — объект «роль: параметры», роли и параметры помощник проверяет белым списком `WinwsArgs.Problem`, файлы fake — по своей папке фейков; id назначает он; ответ — сохранённая стратегия), `strategy_delete {strategy}` (только из `user-strategies.json`, выбранную сейчас — нельзя), `strategy_check {strategy, groups?}` (долгая: проверка сайтов только для одной стратегии, ответ — отчёт подбора из одной строки);
  - режимы: `ipset_mode`, `all_addresses_start/stop`, `game_mode`, `ipset_update {from: manifest|file-content}`, `user_ipset_set`, `user_targets_set`, `user_exclude_set {lines}` (API 1.10: сайты, которые на этом ПК открываются без оптимизации, — весь список целиком, до 200 строк; строгий разбор домена, как у `user_targets_set`; ответ `{saved, rejected}`; помощник пишет `user-exclude.txt` (его читают общие роли и IP-списки) и добавляет сайты в `state.json`: сборка ставит их как `--hostlist-exclude-domains` во все роли каталога, в том числе YouTube и `discord.media`, где файла нет, — командная строка без исключений остаётся прежней; работающая оптимизация перезапускается, не поднялась — список возвращается; список приходит и в `status.userExclude`);
  - настройки папкой файлов (API 1.11, формат — `docs/settings-export.md`): `settings_export_read` (только чтение: свои сайты, исключения, стратегии, продвинутый режим, профили, подсети, свои строки hosts, выбранный DNS и сведения о ПК для проверки чужого файла — какие файлы есть в папке фейков, варианты параметров профилей; прокси, история, статистика и адреса ПК не отдаются) и `settings_import {plan}` (долгая, исключительная; `plan` — JSON-строка до 3 МБ `{mode: add|replace, sections: […], data: {…}}` с уже проверенными данными; помощник разбирает её строго, каждую запись проверяет теми же правилами, что и при чтении чужих файлов, **без единой правки** — лишнее поле, запись вне выбранных разделов, домен не в нормальном виде, неразрешённый параметр winws, файл фейка не из папки программы, не публичный адрес в hosts — отказ целиком (`invalid` на входе в канал или `failed` при сверке с состоянием ПК); затем сам строит план по своему состоянию и применяет разделы теми же методами, что и обычные команды; до первой правки пишет в журнал изменений запись `settings_import` «Загружены настройки из файлов: …» с прежним состоянием; ответ `{sections: [{id, ok, added, removed, skipped, message}], journalId}`; сбой раздела не мешает остальным);
  - hosts: `hosts_check`, `hosts_preview`, `hosts_apply`, `hosts_revert`, `hosts_recheck`;
  - hosts, примерка и свои строки ([architecture.md](architecture.md), «Починить адреса», API 1.4): `hosts_try {entries}` (долгая; `entries` — до 500 строк «адрес имя», адрес любой, в том числе заглушка `0.0.0.0`, имя — с точкой, без маски, порта и пути; ответ — вердикт по каждой: поможет / не нужна / сломает / не поможет / опасно / блокирует; hosts не меняется), `hosts_audit` (долгая; те же вердикты для чужих записей hosts вне блоков DpiShell, у каждой — `lineId` «номер:хеш»; мешающие запоминаются), `hosts_user_set {entries}` (долгая; `entries` — до 500 пар «публичный адрес имя» после `HostsRules.TryParsePublic` и `HostsInput.CleanHost`; ставит **ровно** этот набор своих строк в блок `# DpiShell user begin … end`, каждая строка с тегом `# dpishell-user <дата> manual`; новые пары помощник заново проверяет живым подключением (сертификат на это имя) и непрошедшие возвращает в `rejected`; прежние строки не перепроверяются и не снимаются; пустой список убирает все свои строки), `hosts_comment {ids}` (до 500 id «номер:хеш», 12 hex хеша sha256 текста строки; только мешающие строки из последнего `hosts_audit`; строка превращается в `# DpiShell off <дата>: <строка как была>`; хеш не совпал, строка стала нашей или без записи — пропуск с причиной в `skipped`), `hosts_uncomment` (вернуть закомментированные нами, байт в байт), `hosts_restore` (полное «Вернуть как было»: оба блока, все строки с тегом `dpishell-user`, закомментированные нами — обратно; чужие строки не меняются). Путей и произвольного текста эти команды не принимают; перед каждой правкой — копия `.bak`;
  - обслуживание: `stop_foreign`, `core_repair`, `remove_all`, `tcp_timestamps_on` (включить временные метки TCP, если их требует стратегия роутера — [router-api.md](router-api.md) §6), `data_update {confirmed?}` (обновить данные по `data.json`: источники — из своей копии `update-sources.json`, файлы — по sha256 манифеста; окно передаёт только согласие на сильно изменившийся IP-список — [architecture.md](architecture.md), «Обновления данных»);
  - подключения программ (ТЗ 13, [architecture.md](architecture.md) «Подключения программ», протокол 1.4): `rec_start {mode, pid?, driver?}` (`mode` — `new` — процессы, запущенные после начала, или `process` — выбранный `pid` с дочерними, `pid` обязателен только при `process`; `driver:false` — без драйвера, только TCP; запись только читает, срок — 5 минут, потом останавливается сама; ответ — `RecordingStatus`), `rec_status` (только чтение: идёт ли, секунды, число подключений, записан ли UDP, заметки), `rec_stop` (остановить и отдать записанное: `RecordingResult` — процесс, адрес, порт, протокол, число наблюдений, «процесс из новых», состояние TCP `works|noreply`; помощник записанное забывает), `app_profiles` (только чтение: профили, варианты параметров, запись), `app_profile_set {id?, title, tcp?, udp?, addresses, variant}` (`tcp`/`udp` — порты «443,27015-27030», цифры, запятые, дефис, не больше 16 элементов; нужен хотя бы один из двух; `addresses` — до 500 подсетей/адресов, служебные сети и подсети шире /16 отбрасываются; `variant` — номер из `app_profiles.variants` (параметры десинхронизации берутся из готовых стратегий, своих окно не передаёт); `id` — только `p` и 8 hex-цифр, пусто — новый профиль; ответ — профиль), `app_profile_remove {id}` («Вернуть как было»: профиль и файл адресов удаляются, оптимизация перезапускается без него);
  - откат всего (API 1.6; [architecture.md](architecture.md), «Откат всего»): `changes_list` (только чтение: записи журнала `%ProgramData%\DpiShell\changes.jsonl`, которые ещё можно откатить, — `items: [{id, at, kind, title, undoable}]`, `at` — UTC), `changes_undo_all` (долгая; откат по журналу в порядке, обратном записи; ответ — `items: [{id, title, at, status, note}]`, `status` — `restored|alreadyBack|changedByOthers|failed`), `changes_undo {id}` (долгая; одна запись, `id` — 12 hex-знаков; тот же ответ из одного пункта). Значения и пути окно не передаёт; помощник возвращает прежнее значение, только если сейчас стоит то, что ставили мы (`changedByOthers` — не трогаем, пункт закрывается с пометкой, вопрос — в отчёте окна), `failed` оставляет запись для повторной попытки. Журнал пишет помощник **до** действия (`do` → `done|abort`), недописанная строка при чтении пропускается;
  - системный прокси (API 1.7; [architecture.md](architecture.md), «Системный прокси»): `proxy_status` (только чтение: `now` — настройки пользователя канала, настройки машины, политика `ProxySettingsPerUser`, «изменение закреплено политикой», WinHTTP; `previous` — что вернёт «Вернуть прежний» для машины), `proxy_user_set {enabled, server?, bypass?, pac?}` (запись в ветку **пользователя этого канала** — SID берётся из токена клиента, не из запроса; SYSTEM и служебные SID — отказ; ветка должна быть загружена), `proxy_machine_set {enabled, server?, bypass?, pac?, winhttp?}` (HKLM Internet Settings + `ProxySettingsPerUser=0` в политике; `winhttp:true` — ещё и прокси WinHTTP для служб), `proxy_machine_restore` (поставить прокси, бывший до последнего «Очистить»; хранится в `%ProgramData%\DpiShell\proxy-backup.json`). `enabled:true` — нужен `server` или `pac`; `enabled:false` — «Очистить»: прокси и PAC выключаются, остальные поля не передаются. Белый список значений (`ProxyValues`): `server` — `хост:порт` или `схема=хост:порт;…` (схемы `http|https|ftp|socks`, хост — имя, IPv4 или `[IPv6]`, порт 1–65535, до 300 знаков), `bypass` — до 100 имён/масок/адресов через `;` (`<local>`, `<-loopback>`, буквы, цифры и `* . _ - : [ ] /`), `pac` — только `http(s)://` до 500 знаков, без логина, пробелов и кавычек. Путей реестра и имён значений в командах нет; изменения пишутся в журнал помощника (`proxy_machine`, `proxy_user_admin`) до действия и проверяются чтением обратно;
  - продвинутый режим «сайты → стратегия» (API 1.8; [architecture.md](architecture.md), «Продвинутый режим»; [../research/mixed-strategies.md](../research/mixed-strategies.md) §6): `advanced_get` (только чтение: `{enabled, others, rows: [{domains, strategy, resolved}]}`; `resolved` — чем строка идёт сейчас: у `auto` итог подбора, до подбора — текущая стратегия, у `direct` — `null`), `advanced_set {enabled, others, rows}` (`others` — `direct|lists|all`: остальные адреса напрямую / по спискам / для всех; `rows` — до 20 строк `{domains, strategy?}`, в строке 1–50 сайтов и `strategy` — `auto` (по умолчанию), `direct` или id из каталога и найденных; других полей нет, в том числе `resolved` — итог подбора пишет только подбор). Белый список: сайт — строгий шаблон имени (`AdvancedSites.IsDomain`: строчные латиница, цифры, `-`, точки; русские имена окно присылает в punycode; без схемы, пути, пробелов, запятой, `^`, кавычек, обратного слеша), стратегия — id по тому же шаблону, что у остальных команд, и только из каталога. Параметров winws, путей и списков команды не принимают: профиль строки помощник собирает сам — `--filter-tcp=80,443 --hostlist-domains=<сайты>` с десинком роли `general` выбранной стратегии (и `--filter-udp=443`, если у неё есть `quic`) первыми профилями, `direct` — `--hostlist-exclude-domains` во всех ролях каталога, `others: direct` — роли каталога не включаются, `all` — `general`/`quic` без списка имён. Нечего обрабатывать (`others: direct` и ни одной строки со своей стратегией, профилей программ нет) — отказ `failed` с причиной. Настройки живут в `state.json` помощника; изменение — в журнал отката (`advanced`, «Вернуть как было» возвращает прежние строки и режим); работающая оптимизация перезапускается, не поднялась — настройки возвращаются;
  - совместная работа с роутером (API 1.9; [architecture.md](architecture.md), «Совместная работа с роутером»; [../research/mixed-strategies.md](../research/mixed-strategies.md) §7): `joint_get` (только чтение: `{pcId, active, owned, own, rows, decoys, decoysReliable, decoyNotes, strategyId, enabled, work, profiles}` — что этот ПК готов взять на себя: `own` — «Свои сайты», `rows` — сайты строк продвинутого режима (в том числе «напрямую»), `decoys` — имена приманок стратегии ПК, `work` — сайты, которые ПК реально оптимизирует, `profiles` — сколько профилей программ; `pcId` — постоянный GUID ПК, создаётся при первом обращении и лежит в `state.json` помощника; `active` — связка действует сейчас), `joint_set {active, owned?}` (включить или выключить связку и продлить её: `owned` — до 500 сайтов ПК, которые ведёт роутер, строгий шаблон имени как у `advanced_set`; на ПК они исключены, а строки продвинутого режима с ними не применяются). Параметров winws, путей и списков команда не принимает: сборка — `WinwsArgs.Build` по белому списку. Пока связка действует, остаются только роли `quic` и `general`, и ловят они только `user-general.txt` (свои сайты) и строки продвинутого режима; роли YouTube, Discord, IP-списков и игр, `general.txt` и «Остальные адреса» на ПК не включаются — их ведёт роутер. Связка держится `JointRules.Lease` (150 мин) с последнего `joint_set`; окно продлевает её вместе с `pc_link_set` (не реже раза в 30 мин), не продлило — помощник сам возвращает ПК к полной настройке (таймер помощника; и при старте). Включение — в журнал отката (`joint`, «Отменить всё» выключает связку); нечего вести (нет своих сайтов, строк и профилей) — отказ `failed` с причиной, настройка не меняется;
  - DNS этого компьютера: `dns_status` (только чтение: вариант DNS на физических адаптерах, защищён ли, есть ли что вернуть, какие VPN/виртуальные адаптеры не трогаем), `dns_set {preset, ips?, doh?, fallback?}` (`preset` — `auto|google|cloudflare|quad9|yandex|custom`; `ips` — 1–4 настоящих IPv4/IPv6 без повторов и `doh` — только `https://сервер[:порт]/путь` до 200 символов — **только** при `custom`, и тогда `ips` обязательны; адаптеры помощник выбирает сам), `dns_restore` (вернуть DNS адаптеров как было до первой смены).
- Идентификаторы стратегий — из каталога; **командной строки, путей и произвольных файлов помощник не принимает** (тот же принцип, что в договоре с роутером). Обновление IP-списка из файла — окно передаёт содержимое, помощник прогоняет валидатор.
- Окно без помощника — те же экраны, данные «только чтение» (состояние, статистика из своей копии результатов — §4).

## 4. Данные

- Папка `%ProgramData%\DpiShell` закрыта (только SYSTEM и Администраторы). Окну без прав нужны: состояние, каталог+найденные, статистика, результаты (без адресов) — их отдаёт помощник командой `status`/`read_results` (статистика — `StrategyStats.Stat`: общие числа `score`/`runs`/`fullOk`, с 1.2 ещё `groups` — по группам каталога, `userShare`/`userOk`/`userTotal` — свои сайты, `seconds`, `controlBroken`, `last` — адреса последнего прогона; старый помощник присылает только общие); до установки помощника — каталог из поставки, статистики нет («появится после первого подбора»).
- Настройки окна (тема, закрытие, автозапуск, свои варианты DNS, адрес и пароль роутера под DPAPI CurrentUser) — в `%LocalAppData%\DpiShell\window.json` (принадлежат пользователю, права не нужны). Обходные настройки (стратегия, режимы, свои сайты) — у помощника.
- Прежние настройки DNS адаптеров — `%ProgramData%\DpiShell\dns-backup.json` (закрытая папка); пишется один раз, до первой смены.

## 5. Безопасность (покрыто тестами)

- Канал: подключение от процесса другого пользователя — отказ; неизвестная команда, лишние поля, id стратегии не из каталога, путь в аргументах — отказ с кодом `invalid`.
- Исполняемый файл службы — только из закрытой папки; при старте помощник проверяет свои права на папку (`IsHardened`) и хеш ядра.
- `IsHardened`/`Harden` не доверяют папке, созданной до установки помощника кем угодно: корень-ссылка удаляется, корень с чужим владельцем откладывается в `DpiShell.untrusted-…` и создаётся заново, ссылки внутри (junction, symlink, жёсткие) удаляются до смены прав (иначе права легли бы на цель), остальному — владелец «Администраторы» и наследуемые права; корень был открыт пользователям — скачанные данные `data\` удаляются (в работе поставка). Служба winws (`DpiShell`) создаётся и запускается только при ядре, сходящемся с манифестом (`ServiceManager.BeforeStart`); стартовала с Windows с несошедшимся ядром — помощник при подготовке её останавливает.
- Пароль роутера не идёт через помощника вовсе (роутером управляет окно).
- DNS (`dns_set`): адаптер, путь, команда — не аргументы; адреса проходят разбор как IP (не «похожие на IP» строки), шаблон — строгий шаблон https без пробелов, кавычек, обратных слешей и параметров. Адреса IPv4 — через WMI, DoH на адаптере — реестр; `netsh` (IPv6-адреса, регистрация шаблона) запускается без оболочки, каждый аргумент — отдельный элемент списка, собранный из проверенных значений и чисел.
- Запись подключений и профили программ (`rec_*`, `app_profile_*`): запись только читает (таблица TCP и слой FLOW драйвера WinDivert в режиме SNIFF | RECV_ONLY — содержимое пакетов не открывается), живёт не дольше 5 минут, не больше 4000 подключений, гасится при отключении окна и в `remove_all`; `driver:false` отключает драйвер совсем. Профиль — только порты (канонический разбор `AppProfiles.NormalizePorts`), адреса (валидатор подсетей, без служебных сетей) и номер варианта; параметры десинхронизации помощник берёт из своего каталога и проверяет тем же `WinwsArgs.Problem` для ролей `game_*`; в командную строку winws профиль попадает только после повторной проверки `AppProfiles.Problem`. Файл адресов — `lists\app-<id>.txt` в закрытой папке, пишет помощник.
- Системный прокси (`proxy_*`): имена значений и ветки реестра зашиты (`ProxyNames`, `ProxyKey`): `Internet Settings` пользователя и машины (`ProxyEnable`, `ProxyServer`, `ProxyOverride`, `AutoConfigURL`) и `ProxySettingsPerUser` в `HKLM\SOFTWARE\Policies\Microsoft\Windows\CurrentVersion\Internet Settings`; остальное — только чтение. Ветка пользователя — по SID токена клиента канала (`RunAsClient`), а не по аргументу. WinHTTP — API `WinHttpSetDefaultProxyConfiguration` (не двоичное значение `WinHttpSettings`: его формат не документирован). Откат — «если сейчас стоит то, что ставили мы», по частям (настройки / политика / WinHTTP).
- Продвинутый режим (`advanced_*`): сайты строки — только имена по строгому шаблону (запятая, пробел, `^`, схема и путь отклоняются до сборки), стратегия — только из каталога; командная строка собирается из тех же ролей и белого списка параметров, что и для обычной стратегии, поэтому через строку нельзя передать ни параметр, ни путь; `resolved` от окна не принимается. Покрыто тестами `AdvancedSitesTests`.
- **Действия на весь компьютер** (API 1.14; аудит безопасности №2, решение владельца — вариант «в»): `hosts_apply`, `hosts_user_set`, `hosts_comment`, `dns_set`, `proxy_machine_set`, `proxy_machine_restore` и `settings_import` с разделом `hosts` или `dns` (`HelperCommands.IsMachine`) помощник принимает только от окна **той же сборки**: после hello он берёт PID клиента (`GetNamedPipeClientProcessId`), путь его exe (`QueryFullProcessImageName`) и сверяет sha256 exe (и `DpiShell.dll`, `DpiShell.Core.dll` рядом, если сборка не одним файлом) со своей копией в закрытой папке — её туда положило окно, установившее помощника (`HelperClientImage`, `HelperServerOptions.CheckClient`). Доверие — по хешу, не по пути: портативная папка записываема пользователем. Не та сборка — `denied` с фразой, что обновить: окно старее помощника — программу, новее — помощника, та же версия другой сборки или не DpiShell — переустановить помощника из этого окна. Остальные команды такого клиента работают как прежде; возврат как было (`hosts_revert`, `hosts_restore`, `hosts_uncomment`, `dns_restore`, `changes_undo*`) не ограничен. Повышенный администратор и SYSTEM не проверяются (им это доступно и без помощника). Итог проверки — в hello: `machine: true|false`; окно той же версии при `false` считает помощника устаревшим и предлагает обновить его (один UAC). Окно спрашивает перед такими действиями там, где намерение не очевидно: загрузка hosts или DNS из файла настроек, прокси для всей машины (включить, вернуть прежний); hosts по кнопкам вкладки — свои вопросы, как раньше; DNS — явный выбор и «Применить» или кнопка «Включить защищённый DNS», затем всплывающее «Вернуть».
  **Остаточный риск** (честно): процесс того же пользователя может запустить настоящий DpiShell.exe и управлять им — внедрить код (отладка, запись в память, перехват дескриптора канала), нажимать кнопки окна (диалоги подтверждения тоже); между процессами одного пользователя Windows границы прав не держит. Проверка отсекает простой случай — чужую программу, которая пишет в канал сама. `enable` (winws от SYSTEM с параметрами из белого списка) и прочие команды под эту проверку не попадают.
- Коды ошибок помощника: `invalid`, `busy`, `conflict`, `failed`, `denied`, `cancelled`; у каждого — готовая фраза для пользователя.

## 6. Версии и совместимость окна и помощника

- Окно и помощник — один exe, но помощник обновляется отдельно (копия в закрытой папке, `--install-helper`), поэтому версии могут разойтись: окно обновилось само ([architecture.md](architecture.md) «Обновление программы»), а помощник ещё старый.
- **Версия протокола** `api` — «мажор.минор» (`HelperProtocol.Api`). Текущая версия — `1.14` (1.0 — до появления `api`; 1.1 — `api` и `commands`; 1.2 — статистика стратегий по группам и адресам в `read_results`, исход проверки `blocked` — HTTP 451; 1.3 — свои стратегии: `strategy_add`, `strategy_delete`, `strategy_check`; 1.4 — hosts: примерка строк, свои строки, проверка и комментирование чужих: `hosts_try`, `hosts_audit`, `hosts_user_set`, `hosts_comment`, `hosts_uncomment`, `hosts_restore`; в `details.hosts` — `userLines`, `offLines`, `userStale`, в ответе `hosts_recheck` — `staleUser`, `newStaleUser`; 1.5 — подключения программ: `rec_start`, `rec_status`, `rec_stop`, `app_profiles`, `app_profile_set`, `app_profile_remove`; 1.6 — откат всего: `changes_list`, `changes_undo_all`, `changes_undo`; 1.7 — системный прокси: `proxy_status`, `proxy_user_set`, `proxy_machine_set`, `proxy_machine_restore`; 1.8 — продвинутый режим «сайты → стратегия»: `advanced_get`, `advanced_set`; 1.9 — совместная работа с роутером: `joint_get`, `joint_set`; 1.10 — сайты без оптимизации на ПК: `user_exclude_set`, в `status` — `userExclude`; 1.11 — выгрузка и загрузка своих настроек: `settings_export_read`, `settings_import`; 1.13 — хвост журнала помощника: `log_tail` (только чтение, без аргументов → `{lines}`, последние 200 строк `helper.log`; для «Сохранить отчёт» на «Диагностике») и язык ответов: необязательное поле запроса `lang` (код языка окна, `ru` или `en`): на время этого запроса помощник отвечает на нём (`L.Scope`), а не на своём русском; язык берётся на запрос, не на соединение — окон может быть несколько; окно шлёт поле только помощнику 1.13+ (прежний отвергает лишние поля и отвечает по-русски, окно переводит узнанные фразы само); 1.14 — действия на весь компьютер только от окна той же сборки (§5): поле hello `machine`, отказ `denied` на `hosts_apply`, `hosts_user_set`, `hosts_comment`, `dns_set`, `proxy_machine_*` и `settings_import` с hosts/DNS от другой сборки; формат запросов не менялся; 1.12 — адреса сайтов для проверок: необязательный аргумент `dns` (`doh` — защищённый DNS, по умолчанию; `system` — как у системы, DoH не используется) у `select`, `search`, `strategy_check`; в отчёте подбора — поле `addressSource`). Минор растёт при добавлениях без поломок (новые команды, поля ответов, необязательные аргументы), мажор — только при несовместимых изменениях. Помощник без поля `api` — «1.0».
- `api` приходит в `hello` и в ответе `status`; там же `commands` — имена команд белого списка этого помощника (`HelperCommands.Names`, источник — `HelperCommands.Specs`), по алфавиту. Поля заполняет сервер канала, не бэкенд.
- Сравнение в окне — `HelperCompat.Evaluate` (`HelperClient.Compat`: по hello при подключении, уточняется после `status`); правила — как у договора с роутером ([router-api.md](router-api.md) §5.4):
  - **мажор другой** — `Incompatible`: команды запрещены (клиент сам отвечает кодом `incompatible`, кроме `status`), доступна только переустановка помощника;
  - **минор другой** — `MinorDiffers`: предупреждение; кнопки команд, которых нет в `commands`, неактивны (`HelperCompat.Supports`);
  - **программа помощника старее окна** (`version` из hello/status) — `HelperOutdated`: «Обновить помощника».
- Переустановка и обновление — один путь: окно запускает `DpiShell.exe --install-helper` с `runas` (один UAC, §2), новый exe заменяет копию помощника и перезапускает службу. `status` остаётся совместимым при любом мажоре.
- Код `incompatible` — только у окна (помощник его не шлёт): «Помощник несовместим с этой версией программы — переустановите его».
- Совместимость 1.14: старое окно с новым помощником — подключается и работает, на действия на весь компьютер получает `denied` с фразой «обновите программу» (обновление программы через помощника не идёт) или переустанавливает помощника своей кнопкой; новое окно со старым помощником — помощник старее, окно предлагает обновить его (тот же путь `--install-helper`), поле `machine` отсутствует — проверки нет.
