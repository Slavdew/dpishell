# Протокол окно ↔ помощник (Windows)

Окно DpiShell работает без прав администратора. Всё, что требует прав, делает служба-помощник `DpiShellHelper`; права запрашиваются один раз — при её установке. Здесь — что через кого делается, формат канала, белый список команд и правила безопасности. Реализация: `src/DpiShell.Core/Helper/` (`HelperProtocol.cs`, `HelperCommands.cs`, `HelperServer.cs`, `HelperInstaller.cs`), тесты — `tests/DpiShell.Tests/Helper*Tests.cs`.

## 1. Что без прав, что через помощника

| Без прав (окно само) | Через помощника (служба, SYSTEM) |
|---|---|
| Проверка сайтов («Проверить сейчас»), DNS-проверка | Включить/выключить обход на ПК (служба winws или процесс) |
| Статистика подборов, список стратегий, найденные | Подбор, глубокий поиск (запускают winws) |
| Состояние служб (`sc query`, реестр `ImagePath` — читаются без прав) | Починить адреса (запись hosts), временные метки TCP |
| Обнаружение чужих обходов (процессы — без командной строки чужих elevated-процессов; стратегию узнаёт помощник) | IP-списки, игровой режим (меняют аргументы службы) |
| Управление роутером (сеть + пароль роутера) | Установка/восстановление ядра, «Удалить полностью», «Остановить» чужой обход |
| Тема, настройки окна, свои адреса — черновик до сохранения | Запись в `%ProgramData%\DpiShell` (папка только SYSTEM+Администраторы); DNS этого компьютера; обновление данных |

Кнопки второй колонки до установки помощника — со значком щита; нажатие → «Нужен помощник DpiShell: один запрос прав администратора, дальше без вопросов» → установка → действие продолжается.

## 2. Помощник

- Тот же `DpiShell.exe` с ключом `--helper`, работающий как служба Windows `DpiShellHelper` (SYSTEM, автозапуск). Копия исполняемого файла и `data\` — в `%ProgramData%\DpiShell\helper\` (папка закрыта правами: иначе обычный пользователь подменил бы файл, который система запускает от SYSTEM).
- Установка: окно запускает `DpiShell.exe --install-helper` с `runas` (единственный UAC) → копирование, `sc create`, права на канал, запуск. Приложение новее помощника → тот же путь (UAC — только при смене версии). Занятый exe службы заменяется после её остановки (`DeleteWhenReleased`).
- Служба обхода (`DpiShell`, winws) остаётся отдельной: помощник управляет ею, но не заменяет её. «Режим службы» выключен → winws запускает помощник как процесс в своём объекте задания и гасит, когда окно отключилось от канала (и при остановке помощника).

## 3. Канал и команды

- Именованный канал `\\.\pipe\DpiShell.Helper`. Доступ (DACL): SYSTEM, Администраторы, **пользователь, установивший помощника** (SID сохраняется при установке). Помощник дополнительно проверяет клиента (`GetNamedPipeClientProcessId` → SID токена) — другие пользователи компьютера управлять не могут.
- Формат: строки JSON (`{"id":1,"cmd":"enable","args":{"strategy":"alt9"}}` → `{"id":1,"ok":true,…}`), одна строка UTF-8 = один объект, конец — `\n`. События хода подбора — сообщения с тем же `id` и `"progress":{…}` до финального ответа; отмена — `{"cmd":"cancel","target":<id>}`. Одновременно выполняется одна операция, кроме команд только для чтения (`status`, `details`, `dns_status`, `hosts_preview`, `read_results`, `cancel`).
- **Белый список команд** с проверкой аргументов (`HelperCommands.Specs`):
  - состояние и выбор: `status`, `details` (только чтение: состояние hosts, свои подсети, проверка ядра, найденные стратегии), `read_results` (только наши файлы, свои адреса уже скрыты), `clear_history`, `choose {strategy}` (выбрать стратегию, не включая обход);
  - обход: `enable {strategy}`, `disable`, `set_run_mode {service:bool}`, `select {quick, groups}`, `search {base, groups}`, `cancel`;
  - режимы: `ipset_mode`, `all_addresses_start/stop`, `game_mode`, `ipset_update {from: manifest|file-content}`, `user_ipset_set`, `user_targets_set`;
  - hosts: `hosts_check`, `hosts_preview`, `hosts_apply`, `hosts_revert`, `hosts_recheck`;
  - обслуживание: `stop_foreign`, `core_repair`, `remove_all`, `tcp_timestamps_on` (включить временные метки TCP, если их требует стратегия роутера — [router-api.md](router-api.md) §6), `data_update {confirmed?}` (обновить данные по `data.json`: источники — из своей копии `update-sources.json`, файлы — по sha256 манифеста; окно передаёт только согласие на сильно изменившийся IP-список — [architecture.md](architecture.md), «Обновления данных»);
  - DNS этого компьютера: `dns_status` (только чтение: вариант DNS на физических адаптерах, защищён ли, есть ли что вернуть, какие VPN/виртуальные адаптеры не трогаем), `dns_set {preset, ips?, doh?, fallback?}` (`preset` — `auto|google|cloudflare|quad9|yandex|custom`; `ips` — 1–4 настоящих IPv4/IPv6 без повторов и `doh` — только `https://сервер[:порт]/путь` до 200 символов — **только** при `custom`, и тогда `ips` обязательны; адаптеры помощник выбирает сам), `dns_restore` (вернуть DNS адаптеров как было до первой смены).
- Идентификаторы стратегий — из каталога; **командной строки, путей и произвольных файлов помощник не принимает** (тот же принцип, что в договоре с роутером). Обновление IP-списка из файла — окно передаёт содержимое, помощник прогоняет валидатор.
- Окно без помощника — те же экраны, данные «только чтение» (состояние, статистика из своей копии результатов — §4).

## 4. Данные

- Папка `%ProgramData%\DpiShell` закрыта (только SYSTEM и Администраторы). Окну без прав нужны: состояние, каталог+найденные, статистика, результаты (без адресов) — их отдаёт помощник командой `status`/`read_results`; до установки помощника — каталог из поставки, статистики нет («появится после первого подбора»).
- Настройки окна (тема, закрытие, автозапуск, свои варианты DNS, адрес и пароль роутера под DPAPI CurrentUser) — в `%LocalAppData%\DpiShell\window.json` (принадлежат пользователю, права не нужны). Обходные настройки (стратегия, режимы, свои адреса) — у помощника.
- Прежние настройки DNS адаптеров — `%ProgramData%\DpiShell\dns-backup.json` (закрытая папка); пишется один раз, до первой смены.

## 5. Безопасность (покрыто тестами)

- Канал: подключение от процесса другого пользователя — отказ; неизвестная команда, лишние поля, id стратегии не из каталога, путь в аргументах — отказ с кодом `invalid`.
- Исполняемый файл службы — только из закрытой папки; при старте помощник проверяет свои права на папку (`IsHardened`) и хеш ядра.
- Пароль роутера не идёт через помощника вовсе (роутером управляет окно).
- DNS (`dns_set`): адаптер, путь, команда — не аргументы; адреса проходят разбор как IP (не «похожие на IP» строки), шаблон — строгий шаблон https без пробелов, кавычек, обратных слешей и параметров. Адреса IPv4 — через WMI, DoH на адаптере — реестр; `netsh` (IPv6-адреса, регистрация шаблона) запускается без оболочки, каждый аргумент — отдельный элемент списка, собранный из проверенных значений и чисел.
- Коды ошибок помощника: `invalid`, `busy`, `conflict`, `failed`, `denied`, `cancelled`; у каждого — готовая фраза для пользователя.
