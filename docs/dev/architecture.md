# Устройство DpiShell

Два продукта в одном репозитории: приложение для Windows (`src/`, `tests/`, `data/`, `packaging/`) и пакет для роутера с OpenWrt (`router/`). Оба — оболочки над zapret (bol-van, v1): на Windows ядро `winws`, на роутере `nfqws` — один исходник, один каталог стратегий. Друг друга они видят через [договор](router-api.md); каждый работает и сам по себе. Почему именно zapret v1 — [../research/bypass-engines.md](../research/bypass-engines.md); проверка всего взятого — [../vetting.md](../vetting.md).

## Принцип

Пользователь в сетях не разбирается. Программа сама ведёт к результату: «Включить» без стратегии — берёт лучшую по прошлым подборам или подбирает и включает; мешает похожая программа — кнопка «Остановить», а не инструкция; подбор, дошедший до конца, сам включает лучшую. Новые функции проверяются этим принципом: если человеку нужно что-то сделать «сначала», программа делает это сама или предлагает одной кнопкой. Все необязательные функции (IP-списки, игровой режим, hosts, DNS) выключены по умолчанию и имеют «(i)» с текстом из [../info-texts.md](../info-texts.md). Термины «ipset», «hostlist», «any-protocol» в интерфейсе не показываются.

Правила для каждой функции:
- **Ничего, чего человек не ожидает.** Программа не меняет того, о чём он не просил, с его точки зрения, а не с точки зрения сетевика. Каждое действие можно отменить («Вернуть как было»), не задевая чужих правок.
- **Видно, что делает функция и что стоит по умолчанию.** У каждой функции — короткое «что произойдёт» и «(i)»; значение по умолчанию показано. Любая автоматическая проверка, после которой надо выбирать, имеет «Подробнее» с результатом по каждому адресу.
- **Настройки — всем.** Где есть выбор, который может понадобиться человеку (стратегия, DNS, режим, сторож, автозапуск и т. п.), настройка доступна любому пользователю, а не только через файлы или «для опытных». Умолчания разумные, поэтому трогать настройки не обязательно.
- **Не нагружать железо.** Фоновые проверки — только лёгкие и редкие, на ПК их нет вовсе; тяжёлые (подбор, поиск) — по кнопке.

## Подбор стратегии (общее для ПК и роутера)

### Проверка одной цели
1. Имя разрешается самим приложением через DoH (`dns.google`, `cloudflare-dns.com` по IP), соединение — к полученному адресу: оценка не зависит от DNS системы, который провайдер может подменять ([../research/dns.md](../research/dns.md)). Отдельно сравнивается системный DNS с DoH — расхождение даёт предупреждение «DNS подменён».
2. HTTPS GET отдельно с TLS 1.3 и TLS 1.2 (DPI режет их по-разному), таймаут соединения 3 с, чтения 6–8 с. Редиректы внутри того же сайта (`SameSite`) проходятся до конечной страницы тем же клиентом (DoH, версия TLS), не больше 5 переходов (дальше — провал «не дошли до страницы», если нужно тело, `min_bytes > 0`; иначе успех); чужой сайт на любом шаге — заглушка; в подробностях — цепочка («301 → www.youtube.com/ → 200, 512 КБ»).
3. Успех: рукопожатие прошло; конечный статус не 400, не 403/404 и не ≥ 500; 451 («недоступно по требованию закона») — отдельный исход «блокировка»; редирект на чужой сайт — заглушка; конечное тело прочитано полностью (`received >= Content-Length`, и `>= min_bytes` — обычно 20 КБ: часть DPI рвёт соединение после 16–20 КБ). Чтение до 1 МБ. У целей `handshake_only` (CDN, на «/» отвечают 404/400) — успех по факту рукопожатия, статус не важен.
4. `kind: quic` (HTTP/3) — проверяется, если платформа умеет; иначе «не проверялась», на итог не влияет (на роутере curl без HTTP/3).
5. Две попытки с паузой 500 мс; цель «OK», если хотя бы одна успешна. До 8 запросов параллельно.
6. Путь браузера (ПК, только «Проверить сейчас» и проверка после «Включить»; подбор и фон — без этого, `BrowserCheck.cs`): браузер берёт адрес у DNS системы (hosts, затем DNS адаптера), поэтому цель, открывшаяся по DoH, у которой адрес DNS системы не совпадает с DoH (нет общего адреса или подсети /24; имени нет — тоже расхождение), проверяется ещё раз тем же `HttpProbe` по адресу DNS системы — по очереди, только такие цели. Не открылась — в итоге ⚠ «✓ для программы, ✗ для браузера» с причиной («DNS провайдера подменяет адрес» и кнопка «Включить защищённый DNS» или «запись в hosts ведёт на неработающий адрес»), в «Подробнее» — оба результата с адресами.

### Оценка и порядок
- Группа «прошла», если все `required` цели OK. `score` = доля прошедших групп, затем доля всех целей, затем среднее время.
- **Контрольная группа** «Обычные сайты» (`control`) в счёт успеха не входит: стратегия, сломавшая хоть одну её `required`-цель, получает `score = 0` с причиной «ломает обычные сайты». Цели, недоступные и без оптимизации, из контроля выбрасываются. Группа идёт в каждый подбор и обязательна в режиме «Все сайты» на роутере.
- Перед подбором — прогон **без оптимизации**: цели, доступные и так, не учитываются; доступны все — «Без оптимизации всё открывается: оптимизация не нужна или включён VPN».
- **Быстрый** режим останавливается на первой стратегии с `score = 1`, **полный** проверяет все и показывает таблицу.
- **Порядок по статистике** (`StrategyStats`): по каждой стратегии — её последние 10 прогонов (из до 50 файлов `results\`, свежие весят больше), по группам и адресам. Порядок: доля обязательных групп каталога (YouTube, Discord…), затем доля своих сайтов (не «всё или ничего»), затем время; «ломает обычные сайты» — ноль для порядка; новые — между проверенно рабочими и нерабочими. В списке стратегий окна — **только последний прогон**: «YouTube ✓ · Discord ✗ · свои 7 из 9 · проверено 18.10 в 14:30», «ломает обычные сайты» — предупреждением, если в последнем прогоне; раскрытие — его адреса; нет данных — «ещё не проверялась». «Параметры» у каждой строки (и у найденных поиском) — роли как в каталоге (`{fake}/…` как есть) и командная строка winws для этого ПК с текущими режимами IP-списка и игр (пути — от папки программы), кнопка «Скопировать параметры»; у стратегий роутера — роли, только если роутер отдаёт `roles` в `strategies`. История прошлых подборов не видна (стратегия ломается из-за сбоев сети и смены правил у провайдера — прошлое о сегодняшнем дне не говорит): она нужна порядку и подсказке после подбора — стратегия, открывавшая всё в последних N ≥ 3 прогонах (`Streak`, только прогоны с группами), сейчас не прошла: «Стратегия «…», работавшая последние 5 раз, сейчас не открывает Discord — похоже, провайдер изменил правила или сеть сбоит. Можно поискать новые.» Старые файлы (без `GroupId` в `targets`) дают только общие числа. На выбор лучшей не влияет, только ускоряет быстрый подбор.
- **Автоприменение**: подбор, дошедший до конца, сам включает лучшую (полный — лучшую, быстрый — первую, открывшую всё) и запоминает до 3 рабочих как запасные; остановленный «Стопом» ничего не меняет. Подбор при включённом оптимизации — с предупреждением о перебоях.
- Одна неудачная повторная проверка стратегию не меняет; две подряд — предложение «Подобрать заново» (на ПК) или переключение на запасную (на роутере).
- Защита от провайдера: пауза между стратегиями ≥ 300 мс; три подряд полных таймаута всех целей — стоп с сообщением «провайдер, похоже, временно ограничил соединения».
- Подбор идёт последовательно: оптимизация переключается между стратегиями, сайты на время подбора могут прерываться. Параллельный подбор (несколько экземпляров ядра на непересекающихся диапазонах портов) описан в аудитах, но не реализован.

### Глубокий поиск
Когда готовые не помогли. Как blockcheck, но по ролям и с нашим критерием успеха (`StrategySearch.cs`, на роутере `search.uc`/`select.uc` — та же генерация, эталон `router/test/golden-search.json`).
1. Роли `google` (YouTube) и `general` (Discord, свои сайты) подбираются раздельно на обязательных целях своих групп; остальные роли — из базовой стратегии (текущая, иначе лучшая готовая). Раздельно — потому что у одного провайдера YouTube и Discord часто открывают разные приёмы, и собрать стратегию из лучших по ролям лучше, чем искать одну на всё.
2. **Грубый проход** (одна важная цель на группу, одна попытка): семейства `multisplit`, `multidisorder`, `fake`, `fake,multisplit`, `fakedsplit`, `fakeddisorder`, `hostfakesplit`, `multisplit + seqovl` с типовыми значениями — ~18–20 кандидатов на роль.
3. **Уточнение** вокруг 3 лучших семейств по одному параметру (split-pos, fooling, autottl/ttl, repeats, фейк, `fake-tls-mod`) — жадно, «первое улучшение»: нашли соседа лучше — продолжаем от него (оптимизация слоями тратил бюджет на первый слой и не находил улучшений в два шага). Потолок — 30 кандидатов на роль.
4. **Финал**: лучшие кандидаты ролей собираются в стратегии и проходят полную проверку вместе с готовыми; при равном результате предпочтение — меньше пакетов (меньше `repeats`, без `fake`). Найденное сохраняется в свой каталог пользователя (на ПК `user-strategies.json`, на роутере `found-strategies.json`, id `r-…`) и проходит ту же проверку белым списком.

### Свои стратегии: копирование, вставка, правка
Стратегии можно передавать и менять руками (`StrategyExchange.cs`, `FlowsealBat`, `StrategyEditor.cs`, `MainViewModel.Strategies.cs`; на роутере не реализовано — туда уходят готовым списком, см. ниже).
- **Формат обмена**: одна строка `dpishell:1:` + base64url (без `=`) от сжатого deflate JSON `{"title": …, "roles": {роль: параметры}}`. Разбор строгий и один для всех входов: версия (`1`; новее — «обновите DpiShell»), длина строки ≤ 8 КБ, распакованный JSON ≤ 16 КБ (защита от «бомбы»), только поля `title` и `roles`, без повторов ключей, глубина ≤ 4; роли — только из `WinwsArgs.RoleOrder`; каждый параметр — через `WinwsArgs.Problem` (тот же код, что проверяет каталог): токен только `--имя[=значение]` из символов `A-Za-z0-9_.,+=/{}!-` (кавычки, `&`, `|`, `^`, `%`, пробельные и управляющие знаки — отказ), имя в `AllowedOptions` (игровые — только в `game_*`), значения-файлы — только `{fake}/имя.bin`, `0x…` или `!`, файл `имя.bin` обязан лежать в папке фейков программы; `--wf-*`, `--new`, `--hostlist`, `--ipset` и прочее вне белого списка — отказ. Причина — одной фразой («Параметр --xxx не разрешён», «Путь вне папки программы: …», «Строка повреждена»); частично принять нельзя. Название: без управляющих и невидимых знаков, ≤ 60.
- **Вставка из .bat Flowseal**: строка запуска `winws.exe --wf-tcp=… --new …` разбирается так же, как каталог собран из `general*.bat` ([../vetting.md](../vetting.md)): продолжения `^` склеиваются, `^!` → `!`, из профиля снимаются `--wf-*`, `--filter-*`, списки (`--hostlist*`, `--ipset*`: путь только `%LISTS%имя.txt`), остальное — десинк. Роль профиля — по портам и виду списка: UDP 443 + hostlist → `quic`, + ipset → `ipset_udp`; UDP `19294-19344,50000-50100` → `discord_udp`; TCP `2053,…,8443` + `--hostlist-domains` → `discord_media`; TCP 443 + hostlist с «google» в имени → `google`; TCP 80,443 + hostlist → `general`, + ipset → `ipset_tcp`; только `%GameFilterTCP%`/`%GameFilterUDP%` → `game_tcp`/`game_udp`. `%BIN%x.bin` → `{fake}/x.bin` (файл должен быть в папке фейков). Не разбирается однозначно (два профиля на роль, незнакомые порты, неизвестная переменная, остаточные `^ & |`) — отказ с причиной.
- **Хранение**: окну папка программы закрыта, поэтому сохраняет помощник — `strategy_add {title, roles, source}` (source `user` — своя, `pasted` — вставленная; id `own-…` назначает он; роли проверяются ещё раз, файлы fake — по папке программы; не больше 50 своих), `strategy_delete {strategy}` (выбранную сейчас и готовые — нельзя). Лежат в `user-strategies.json` вместе с найденными поиском (`search`) и проходят ту же проверку при каждом чтении.
- **Окно**: у каждой стратегии на «Главной» — «Скопировать стратегию» (строка в буфер, тост «Стратегия скопирована — её можно вставить в DpiShell»), в блоке «Параметры» — «Изменить» (готовым и найденным — «Сделать копию и изменить») и «Удалить» (своим, вставленным, найденным); на «Подборе» те же «Скопировать» и «Изменить» — для выбранной строки, и второстепенная ссылка «Вставить стратегию». Окно правки: название и поле на каждую роль (Consolas), проверка белым списком на лету, «Сохранить» — всегда новая стратегия под новым именем (прежняя не меняется; готовые не правятся вовсе).
- **Проверка перед применением**: вставленная и сохранённая после правки стратегия попадает на «Подбор» строкой «не проверена» с карточкой «Проверить» — `strategy_check {strategy, groups?}` (долгая; тот же `Selector`, один кандидат; итог пишется в статистику, как у подбора; служба на время проверки останавливается и возвращается). «Применить» появляется после успешной проверки; «Применить выбранную» для непроверенной и выбор такой стратегии в списке на «Главной» — только с подтверждением «не проверена». Метки у названия: «вставлена», «своя», «найдена».
- **Роутер**: «Отправить на роутер» (`strategies_user_set`, [router-api.md](router-api.md) §5.2) показывается у каждой стратегии из `user-strategies.json`; набор уходит целиком, роутер проверяет его по своему белому списку и может отклонить роль, которой не знает.

### Временные метки TCP
Приём `--dpi-desync-fooling=ts` (половина каталога) работает, только если метки времени TCP включены у клиента: в Linux/Android/iOS/macOS включены, в Windows — выключены по умолчанию. Поэтому на ПК приложение включает их само перед подбором и при «Включить» (прежнее значение запоминается и возвращается при «Удалить полностью»), а на роутере каждая стратегия с `ts` проверяется дважды — как есть и с `sysctl net.ipv4.tcp_timestamps=0` (как клиент Windows); оценка — по проверке без меток, стратегия, прошедшая только с метками, помечается `needs_tcp_timestamps`, и приложение на ПК включает метки по этому флагу.

## Windows-приложение

### Состав
```
DpiShell.Core (net10.0)      ядро без UI: Strategies (каталог, WinwsArgs), Probe, Selector, StrategySearch,
                             Shell (служба/процесс winws), Helper/ (протокол, сервер, установка), Router/ (клиент договора),
                             IpLists, IpsetValidator, Hosts*, DnsSettings, DataUpdates, SystemChecks, TcpTimestamps

tests/DpiShell.Tests         xUnit; FakeRouter — роутер в памяти по договору
```
Стек: C#/.NET 10, WPF, один self-contained exe (`PublishSingleFile`), без установщика и подписи — portable-zip. Выбран вместо Python+PyInstaller из-за антивирусов (onefile-бутлоадер поверх драйвера WinDivert — двойной риск) и штатных UAC/трея/служб.

### Окно без прав и помощник
Окно работает без прав администратора (`asInvoker`); всё, что требует прав, делает служба-помощник `DpiShellHelper` (тот же exe с `--helper`), права запрашиваются один раз при её установке. Формат канала, белый список команд и правила — [helper-protocol.md](helper-protocol.md). Пароль роутера через помощника не идёт — роутером управляет окно.

### Ядро и служба оптимизации
- Ядро (`winws.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll`) в поставку не входит: скачивается при первом запуске по `core.json` — zip релиза bol-van, затем `mirror_urls` (форк с тем же хешем), локальная копия — `vendor/`. Проверяются sha256 архива и каждого файла; извлекаются только перечисленные. Хеши сверяются перед каждым запуском; не совпали — «Файлы ядра изменены или удалены (антивирус?)», «Восстановить». Лишние файлы в папке ядра (вторая `cygwin1.dll`) — проверка при старте.
- **Режим службы**: служба Windows `DpiShell` — это сам `winws.exe` с собранной командной строкой (`sc create … start= auto`, перед установкой `--dry-run`), работает и без окна, после перезагрузки. «Выключить» оставляет службу с `start= demand`. **Режим без службы**: winws запускает помощник как процесс в объекте задания и гасит, когда окно отключилось.
- Истина — настройки службы в Windows: стратегия и файл читаются из реестра (`ImagePath`), не из памяти программы; чужой файл в службе `DpiShell` — предупреждение. Состояние служб — по кодам `RUNNING`/`STOPPED` (подписи `sc` переводятся на язык Windows).
- **Чужие оптимизации**: Flowseal (по раскладке папок), другой zapret (`winws1`, `winws2`, `zapret`, `discordfix_zapret`), GoodbyeDPI — определяются с их стратегией (командная строка winws сравнивается с каталогом) и подсказкой, как выключить; включение и подбор блокируются, пока они работают; «Остановить» — через помощника.
- При смене сети подбор прерывается; VPN — только предупреждение.

### Папки и права
- `%ProgramData%\DpiShell\{core, data, lists, fake, hosts, helper, state.json, results\, logs\, dns-backup.json}` — **только SYSTEM и Администраторы** (наследование от ProgramData отключено, по SID). По умолчанию там читали и писали все пользователи: свои сайты были видны всем, а `winws.exe` можно было подменить — служба запускает его от системы. Свои сайты в истории и отчётах — «свой адрес №N»; `user-general.txt` остаётся текстом (его читает winws) и защищён правами папки.
- `%LocalAppData%\DpiShell\window.json` — настройки окна (тема, закрытие, автозапуск, свои варианты DNS, адрес и пароль роутера под DPAPI).
- Логи: `logs\app.log` (ротация), winws при подборе — `--debug` в `logs\winws-<стратегия>.log`.

### Окно, трей, автозапуск
- Одна копия (повторный запуск показывает работающую); крестик — «Сворачивать в трей» (по умолчанию) или «Закрывать»; тема как в Windows / светлая / тёмная. Трей: состояние цветом, меню Включить/Выключить/Подобрать/Открыть/Выход.
- **Автозапуск**: значение `DpiShell` в `HKCU\…\CurrentVersion\Run` = `"<путь>\DpiShell.exe" --tray` (окно не показывается, только значок). Не задача планировщика с наивысшими правами — окну права не нужны. Пока пользователь не выбирал: в режиме без службы — **включено** (иначе оптимизация не поднимется после входа), в режиме службы — выключено (служба стартует сама). Портативную папку могут перенести — путь в ключе поправляется при каждом запуске.

### Обновления данных
- Раз в день при запуске окно тихо качает `data.json` с адресов из `data/update-sources.json` (по очереди, 5 с на адрес; без сети — «последняя попытка <дата>»), сравнивает версию с данными помощника и показывает «Доступно обновление списков» (плашка на главной, блок «Версия» на вкладке «Информация и обновления»; там же «Информация» — zapret, репозиторий, лицензии). `app_version` в манифесте — подсказка «вышла новая версия»; `min_app_version` — данные не ставятся старой программой. Саму программу обновляет окно — «Обновление программы».
- Кнопка — команда помощника `data_update`: помощник сам заново берёт манифест со своих источников, качает каждый изменившийся файл и сверяет sha256, собирает новую папку `data` рядом, проверяет её целиком (каталог, цели, `core.json`, hosts-кандидаты, валидатор IP-списка с вопросом при изменении > 40 %) и только потом подменяет. Данные читаются из обновлённой папки, если она новее поставки и цела, иначе — из поставки.
- Доверие: манифест — только с адреса из списка; список источников едет с программой и обновлением **не меняется** (зеркало не может назначить себя или другие адреса). Ключи манифеста — только `имя` в корне `data\` или `lists|fake|hosts|licenses/имя`; `data.json`, `data.json.sig`, `update-sources.json`, `user-*` — никогда. Стратегии из обновления — только из белого списка параметров, IP-список — через валидатор, hosts — белый список доменов и живая проверка сертификата.
- **Подпись манифеста** `data.json.sig` (ed25519 над точными байтами `data.json`, ключ — тот же, что у выпусков, [building.md](building.md) «Подписи»): CI подписывает `data/data.json` при каждом изменении в master и выкладывает `data/` вместе с подписью на GitHub Pages (`https://slavdew.github.io/dpishell/data/`, первый источник) одной сборкой — манифест и подпись не расходятся. Подпись верна — манифест подписан (`FetchedManifest.Signed`, `DataUpdateResult.Signed`); подпись есть, но неверна или не скачалась — источник отброшен, берётся следующий; подписи у источника нет вовсе (404, например raw.githubusercontent.com) — источник тоже отброшен (`DataUpdateClient.RequireSignature`, по умолчанию включён), обновление отклоняется с причиной «манифест без подписи», прежние данные остаются. Проверка — до разбора манифеста и до доверия хешам файлов. Данные из поставки (рядом с exe, seed) подписью не проверяются: их целостность — установка и sha256 манифеста; проверяются только скачанные. Новое `core.json` у подписанного манифеста принимается с любого https-адреса (хеши закреплены подписью); ветка «только релизы bol-van/zapret» для неподписанного осталась как страховка. Ключ в `Shell.DataSigningKey` (в тестах подменяется тестовым).
- Источник один — GitHub Pages; у части провайдеров GitHub блокируется по IP — зеркало вне GitHub (с `data.json.sig`) добавляется одной строкой в `update-sources.json`.

### Обновление программы
- **Лента** `windows-vX.Y.Z`: версия — `<Version>` в `Directory.Build.props` (единый источник для exe, имени архива и `release.json`). CI (`.github/workflows/windows.yml`) по тегу сверяет тег с версией и наличие заметок в `packaging/release-notes.json`, собирает и тестирует на windows-latest, делает portable-архив (`packaging/make-portable.ps1`), `release.json` `{ schema: 1, product: "dpishell-windows", version, tag, min_os, changes, assets: [{ name, sha256 }] }` (`packaging/release-json.py`) и `release.json.sig` (ed25519 над точными байтами, [building.md](building.md) «Подписи»), публикует релиз как «последний» (релизы роутера — `--latest=false`).
- **Проверка** (`AppUpdateClient.CheckAsync`, `AppUpdater.CheckAsync`): источники — `app_sources` в `update-sources.json` (по умолчанию `https://github.com/Slavdew/dpishell/releases/latest/download/`), по очереди, 5 с на ответ. `release.json` принимается **только с верной подписью** (переходного периода, как у данных, нет — это исполняемый файл); тег — `windows-v` + версия, имена файлов без путей. `AppUpdateCheck.Available` — выпуск новее, Windows не старее `min_os`, архив `DpiShell-X.Y.Z-portable.zip` в выпуске есть.
- **Автопроверка раз в день**: `AppUpdateSettings` (`AutoCheck`, `LastCheck`, `LatestVersion`, `SkippedVersion`; `IsDue`, `Checked`, `ShouldOffer`) в хранилище `IAppUpdateSettingsStore`; файловое — `AppUpdateSettingsFile`, `%LocalAppData%\DpiShell\app-update.json` (общий для всех версий).
- **Установка** (`AppUpdater.PrepareAsync`): архив качается потоком в файл с sha256 из подписанного `release.json` (не совпал — следующий источник, затем отказ), распаковывается в `%LocalAppData%\DpiShell\versions\X.Y.Z\` (сначала `X.Y.Z.new`, только записи под `DpiShell/`, без выхода за папку, обязателен `DpiShell.exe`; готовая папка — одним переименованием). Права не нужны; помощник и данные в `%ProgramData%` не трогаются.
- **Перезапуск** (`AppUpdater.RestartInto(версия)` → `RestartPlan.ToStartInfo()`): новая копия запускается с `--wait-pid <pid> --updated-from <версия>`, окно закрывается. Новая копия первым делом вызывает `AppUpdater.WaitForPrevious(args, …)` — до проверки «одна копия окна». Путь автозапуска поправляется при запуске сам (см. «Окно, трей, автозапуск»); новая версия новее помощника — «Обновить помощника» (`HelperCompat`, [helper-protocol.md](helper-protocol.md) §6).
- **Откат**: `versions\state.json` хранит текущую и прежнюю версию с путём её exe (прежняя может быть исходной portable-папкой); `AppUpdater.Rollback()` — команда запуска прежней. `AppVersionStore.Prune(running)` удаляет остальные версии (не текущую, не прежнюю, не запущенную). Новая версия, которая стартовала и не подтвердила запуск (`AppUpdater.ConfirmStarted` — после того как окно создано), на втором старте возвращает прежнюю сама (`CheckStartup`, поля `pending`/`pending_starts`/`failed` в `state.json`); окно скажет об этом один раз (`TakeFailedNotice`).
- **Почему не подмена exe и не помощник**: запущенный exe Windows не даёт перезаписать, а переименование «текущий → .old, новый на место» требует прав на папку программы и оставляет полузамену при сбое посередине. Поэтому программу **не заменяют**: новая версия лежит в своей папке `versions\X.Y.Z` (в `%LocalAppData%`, пишет сам пользователь), старая остаётся там, где была, переключение — запись в `state.json` и запуск другой копии; сбой на любом шаге до записи ничего не меняет. Права администратора и команды помощника не нужны: закрытая папка (`AppPaths.Harden`) — это `%ProgramData%\DpiShell` помощника, а не папка окна. Помощник обновляется отдельно, как раньше (`--install-helper`, окно предлагает само); протокол помощника не менялся (1.3).
- **Окно** (`UpdatesViewModel`, вкладка «Информация и обновления»): проверка `AppUpdater.CheckAsync` раз в день вместе с данными и по «Проверить обновления»; выпуск с верной подписью — «Что нового» из `release.json` показывается до нажатия, кнопка «Обновить до X»: «Скачиваю версию X: N МБ» → проверка sha256 → распаковка → «Перезапускаю программу…» (окно запускает копию и выходит обычным путём, с вопросами «Все адреса»). Не хватает места (`AppUpdater.RequiredFreeBytes`, 600 МБ), подменённый архив, нет связи, неверная подпись описания, не запустилась копия — каждое своей фразой и «программа не изменена»; подробности мелко. Описание выпуска не получено — остаётся прежняя ссылка на страницу релизов. «Вернуть прежнюю версию (X)» — `Rollback()`; после перезапуска — «Программа обновлена до версии X» / «Возвращена версия X».

### IP-списки и игровой режим
- **IP-списки** (`IpLists.cs`): режим «Выкл» (по умолчанию, файл-заглушка `203.0.113.113/32`), «По списку» (`ipset-all.txt` + `user-ipset.txt`), «Все адреса — на 10 минут» (пустой include-лист = оптимизация для любого адреса; таймер, автовозврат, уведомление; варианта «пока не выключу» нет — режим ломает многие сайты). Режимы не переименовывают файлы: `WinwsArgs.Build` подставляет нужный (`ipset-all` / `ipset-none` / пустой `ipset-any`, в последнем случае без `user-ipset.txt`). Список — из Flowseal (дампы префиксов ~100 автономных систем, 10 % IPv4), закреплён хешем в `data.json`, обновляется с ревизией при подготовке версии; winws перечитывает файл сам.
- **Валидатор** (`IpsetValidator`, один код для подготовки версии и для машины): только `IPv4/len` и `IPv6/len`, host-биты обнуляются; запрещены префиксы короче `/8` (IPv4) и `/19` (IPv6), пересечения с приватными/служебными сетями и `ipset-exclude.txt`; 1 000–100 000 строк, 50 КБ–4 МБ, доля IPv4 ≤ 15 %, без дублей; отброшено > 1 % — «список повреждён, оставлен прошлый»; отличие от прошлой версии > 40 % строк — только с подтверждением. Свои подсети — те же правила, лимит 10 000 строк, короче `/16` — с подтверждением.
- **Игровой режим**: один переключатель (= TCP и UDP, порты `1024-65535`; варианты и порты — только в консоли). Роли `game_tcp` (десинк `general` + `--dpi-desync-any-protocol=1 --dpi-desync-cutoff=n3`, при `badseq` — `--dpi-desync-badseq-increment=0x80000000`) и `game_udp` (`fake` + `--dpi-desync-fake-unknown-udp` + `cutoff=n2`) только к адресам из IP-списка; при включении IP-списки сами переводятся в «По списку». В подборе роли `game_*` не участвуют. Запрещён вместе с «Все адреса» (приманки во всё). Цена — нагрузка CPU и пинг (весь UDP верхних портов идёт через winws), поэтому выключен по умолчанию и с предупреждением «стало хуже — выключите».

### Подключения программ (ТЗ 13, вкладка «Игры и программы», ПК)
Запись «куда ходит игра» и профиль под неё (ТЗ 13 в приватном репозитории, решения владельца 6–8). Две ступени: простой режим «Настроить под игру» (Начать → играть → Готово, всё само) и для опытных «Отладка подключений» (список с галочками, ручной выбор; показ — «Настройки» → «Показывать инструменты для опытных», `WindowSettings.ShowAdvanced`; «Подробнее» в простом режиме открывает раздел и без галочки до перезапуска). Роутерная часть (запись по conntrack, `profile_set`) — отдельной работой; переключателя «ПК / роутер» пока нет.
- **Как записывается** (`Recording.cs`, `RecordingNative.cs`; команды `rec_start/rec_status/rec_stop`, протокол 1.4). Помощник (SYSTEM) собирает «процесс → удалённый адрес:порт/протокол» не дольше 5 минут (`ConnectionRecorder.MaxDuration`), не больше 4000 подключений, и отдаёт итог по «Готово». Два источника, оба без сторонних драйверов:
  1. **WinDivert, слой FLOW, только чтение** (`WinDivertFlowSource`, флаги `SNIFF | RECV_ONLY`): событие «поток установлен» для TCP и UDP с PID и удалённым адресом. Пакеты не читаются и не меняются — нагрузка пренебрежимо мала. Единственный способ получить удалённый адрес **UDP** без ETW. DLL — из папки ядра по полному пути, после проверки хешей ядра (`Installer.Check`); тот же драйвер, что у winws, — предупреждение про античиты (Vanguard, FACEIT, EAC) стоит рядом с кнопкой.
  2. **Таблица TCP Windows раз в секунду** (`TcpTableSource`, `GetExtendedTcpTable`): PID, адрес, порт и состояние (`SYN_SENT` дольше 4 с без перехода в `ESTABLISHED` — «нет ответа»). Работает без драйвера: при «Без драйвера» (опытным) или если драйвер не открылся записывается только TCP, и в итоге об этом сказано (`UdpRecorded = false`, заметка). `GetExtendedUdpTable` **удалённых адресов не содержит** — для UDP годится только драйвер.
  - **Почему не ETW** (`Microsoft-Windows-Kernel-Network` отдаёт и UDP): сессия ETW — это ещё один набор P/Invoke и разбор событий по версиям манифеста, без сторонней библиотеки и без проверки на живой машине надёжно не написать; WinDivert уже в поставке и открывается тем же `WinDivert.dll`. ETW остаётся запасным путём для случая «драйвер перехвата не пускают» (не сделано).
  - Режимы: `new` — процессы, запущенные после «Начать» (снимок процессов при старте = «фон»; потоки старых процессов пишутся с `Fresh = false` и их адреса вычитаются), `process` — выбранный PID с дочерними (дерево по Toolhelp32). Источник и каталог процессов — интерфейсы (`IFlowSource`, `IProcessCatalog`): в тестах подмена.
  - Запись гасится при отключении окна и в `remove_all`; одна запись за раз.
- **Профиль из записи** (`AppProfileBuilder`, чистая функция): отсев шума (`FlowNoise`: локальная и служебные сети, порты DNS/DHCP/NTP/NetBIOS/mDNS/SSDP, процессы — службы Windows, браузеры, OneDrive/Teams, Defender, веб-часть лаунчеров; адреса, к которым ходили старые процессы); порты → компактная строка (`CompressPorts`: соседние сливаются, разбросанные верхние — одним диапазоном, не больше 16 элементов); адреса → `/32` или `/24`, если в одной /24 увидели ≥ 4 (не больше 500). Тот же отсев даёт стартовые галочки в «Отладке подключений» (`AppProfileBuilder.Sort`: причина по каждой строке); ручной выбор не пропускает локальную сеть.
- **Профиль в winws** (`AppProfile` в `state.json` помощника; `WinwsArgs.Build`, `BuildOptions.Profiles`): отдельный профиль `--new` **перед** общими ролями (winws берёт первый подходящий) — `--filter-tcp|udp=<порты>`, `--ipset=lists\app-<id>.txt`, исключения пользователя, параметры игровой роли; порты добавляются в `--wf-tcp/--wf-udp`. Файл адресов пишет `Shell.SyncAppProfileFiles` перед каждым запуском и при изменении профиля. Новых параметров winws в белый список **не добавлено**: фильтры и ipset строит `Build` сам из проверенных значений, а параметры десинхронизации — только роли `game_tcp/game_udp` из готовых стратегий (`AppProfiles.Variants`), через тот же `WinwsArgs.Problem`. `AppProfiles.Problem` проверяет профиль целиком (номер, название, канонические порты, адреса без служебных сетей и шире /16, параметры) перед записью и ещё раз перед командной строкой: подделка `state.json` до winws не доходит (тесты на злоупотребление в `AppProfileTests`, `AppProfileHelperTests`).
- **Подбор параметров** (простой режим, `AppsViewModel`): после «Готово» профиль применяется с вариантом 0 (как у текущей стратегии), человеку — «Запустите игру ещё раз. Заработало?» — «Да» / «Нет» / «Стало хуже». «Нет» и «Хуже» заменяют параметры у того же профиля следующим вариантом из `Variants` (до 5 попыток); кончились попытки или варианты — профиль снимается («Настройки возвращены как были»), «Подробнее» открывает запись списком. **Автоматической проверки без человека нет**: UDP-игру без самой игры не проверить (ТЗ «Подводные камни»); командную строку профиля охраняют только белый список и `AppProfiles.Problem`; `winws --dry-run` не вызывается. Первый кандидат из ТЗ «исключить из оптимизации» на ПК не сделан: исключения адресов действуют не во всех профилях общей командной строки (`quic`, `discord_udp` без `--ipset-exclude`).
- **Откат**: «Вернуть как было» — `app_profile_remove` (профиль, файл, перезапуск без него); «Удалить службу оптимизации» тоже чистит профили. Общий журнал `changes.jsonl` — позже (решение 4).

### Починить адреса (hosts)
Для блокировок **по IP** (DoH их не чинит): GitHub, Telegram Web, запуск Discord. Выключено по умолчанию. «Проверить адреса» → таблица «домен | адрес | владелец (RDAP) | проверка | как через DNS» → «Записать N» → «Вернуть как было». Правила (`HostsCheck.cs`, `HostsManager.cs`): домен из **белого списка** манифеста (`github.com`, `*.githubusercontent.com`, Telegram, `discord.com`, `updates.discord.com`), адрес публичный; **живая проверка** — TCP 443 к адресу, TLS с SNI домена, сертификат проходит обычную проверку цепочки и имени (доказывает, что узел законно обслуживает домен), RDAP — вторичный признак; запись ставится, только если чинит то, что через DNS не работает; свой блок `# DpiShell begin … # DpiShell end`, чужие строки не трогаются; копия `hosts.<дата>.bak` (10 последних), атомарная замена, `ipconfig /flushdns`; перепроверка раз в день, устаревшие снимаются с уведомлением; предупреждение про `HostsFileHijack` Защитника до записи; «Удалить полностью» убирает блок. Пустой блок на части провайдеров — нормальный исход («нечего чинить»).

**Примерка строк, свои строки, проверка hosts (ТЗ 12; `HostsTryout.cs`, `HostsFile.User.cs`, `HostsViewModel.Tools.cs`, команды помощника `hosts_try`/`hosts_audit`/`hosts_user_set`/`hosts_comment`/`hosts_uncomment`/`hosts_restore`, API 1.4).** Вкладка — свёрнутые разделы с якорями сверху. Вставка из гайда (`HostsPaste.Parse`: только «адрес имя», маски, порты, `localhost`, URL отбрасываются, до 500 строк) → для каждой пары вердикт `HostsTryVerdict`: *поможет* (по адресу из строки открывается с верным сертификатом, а через DNS мимо hosts — нет), *не нужна* (DNS и так открывает), *сломает* (DNS открывает, а строка — заглушка или мёртвый адрес), *опасно* (сертификат не этого сайта), *не поможет* (не открывается ничего), *блокирует* (заглушка там, где и так не открывалось). Используются `TlsEndpointProbe`, DoH-DNS мимо hosts (`IHostsDns`) и RDAP (владелец — вторичный признак); заглушки наружу не проверяются. Записать можно только «поможет», ограничения белым списком нет, но **помощник заново проверяет каждую новую строку живым подключением** и пишет только прошедшее; ранее записанные не перепроверяются и не снимаются.
- **Свои строки** — отдельный блок `# DpiShell user begin <дата>` … `# DpiShell user end`, на каждой строке тег `# dpishell-user <дата> manual` (источник — ASCII-слово: файл без BOM читается как Latin-1, кириллица превратилась бы в «?»). Строка узнаётся по тегу где бы она ни лежала, поэтому сломанная рамка не мешает откату; строки, которые пользователь вписал внутрь рамки сам, остаются. Блок белого списка (`# DpiShell begin`) и блок своих строк друг друга не трогают. Раз в сутки (`hosts_recheck`) помощник проверяет свои строки: перестала открываться — строка **не снимается**, отметка пишется в `hosts\user-stale.json`, окно показывает предупреждение «Адрес для X больше не работает — уберите строку или подберите новый адрес» и один раз уведомляет.
- **Аудит чужих строк** (`hosts_audit`): записи вне наших блоков и не закомментированные нами, до 500 за раз (сначала с настоящим адресом, потом заглушки; сверх — «проверено N из M»). Строка называется «номер:хеш» (первые 12 hex sha256 её текста). Мешающие («сломает», «опасно») можно отметить и **закомментировать** (`hosts_comment`): строка превращается в `# DpiShell off <дата>: <строка как была>`. По умолчанию ничего не отмечено; помощник трогает только мешающие строки **из своего последнего аудита**, хеш должен совпасть с текущим текстом (файл поменяли — строка пропускается с причиной), наши строки и записи без адреса не принимаются.
- **Откат.** Каждая правка — копия `.bak`, проверка «файл не менялся между чтением и записью», атомарная замена. «Вернуть закомментированные» (`hosts_uncomment`) возвращает исходный текст; «Убрать только мои строки» — `hosts_user_set` с пустым списком; «Вернуть как было» (`hosts_restore`) убирает оба блока и все строки с тегом и раскомментирует `# DpiShell off`, остальное — строки пользователя и других программ до и после нас — остаётся теми же байтами (тесты на копиях в Latin-1, UTF-8 с BOM, UTF-16 LE/BE, LF/CRLF/смешанных переводах). Ограничение: если файл заканчивался без перевода строки, после нашей записи и отката перевод остаётся.

### Вкладки окна
Главная · Подбор · **Сайты** (`Pages.Sites`: свои сайты ПК или роутера, переключатель «На этом ПК / На роутере»; для роутера ещё исключения, «Сайт не открывается», «Для каких сайтов оптимизация») · **Игры и программы** (`Pages.Apps`: «Настроить под игру», профили программ, «Отладка подключений» для опытных, игровой режим; IP-списки и свои подсети — в свёрнутом «Дополнительно») · Починить адреса · DNS · **Диагностика** (только этот ПК) · **Роутер** (устройство: состояние, «Роутер: что мешает» с отчётом, пакет, DNS всей сети, «Проверять сам», подключение) · Настройки (в том числе «Обновления» — и списков, и программы). Номера вкладок — константы `Pages` (порядок не менялся, смысл — по имени). Вход на «Роутер» обновляет DNS сети и «Роутер: что мешает»; вход на «Диагностику» — только проверки этого ПК. Ссылка «Обновить программу» с «Роутера» ведёт в «Настройки».

### Диагностика
Только показывает, что мешает, и что сделать; ничего не меняет без кнопки (`SystemChecks.cs`): служба BFE; системный прокси; временные метки TCP; процесс AdGuard; службы Killer, Intel Connectivity, Check Point, SmartByte; кириллица/OneDrive в пути; строки `youtube.com` в hosts вне нашего блока; `WinDivert` без `winws` («Остановить WinDivert»); чужие оптимизации («Остановить»); VPN; обновления; помощник (состояние, переустановка, удаление). **Очистка кэша Discord** — кнопка с подтверждением (закрывает Discord, удаляет `Cache`, `Code Cache`, `GPUCache`: после смены стратегии Discord держит в кэше неудачные ответы). «Сохранить отчёт» — журнал без паролей и личных данных.

### DNS этого компьютера
Живёт на отдельной вкладке «DNS» (между «Починить адреса» и «Диагностикой»): проверка подмены, таблица «Подробнее: ответы DNS» и выбор DNS; при подключённом роутере внизу — ссылка на вкладку «Роутер», где DNS для всей сети. Один клик вместо ручных настроек (`DnsSettings.cs`, команды помощника `dns_set`/`dns_restore`). Варианты: «Как у провайдера» (DHCP), Google (рекомендуемый — кнопка на плашке «DNS провайдера подменяет…»), Cloudflare, Quad9, Яндекс (с пометкой «российский: применяет реестр блокировок»), свои (имя, 1–2 IPv4, необязательный шаблон https) — одни и те же для ПК и роутера. Меняются только включённые Ethernet/Wi-Fi с основным шлюзом; VPN и виртуальные адаптеры не трогаются и перечисляются. Windows 11: адреса IPv4 — WMI, IPv6 — `netsh`, включение DoH на адаптере — ключи `Dnscache\InterfaceSpecificParameters\{GUID}\DohInterfaceSettings` (то же, что пишут «Параметры» при «Вкл., возврат к обычному тексту: выкл.»), шаблоны своих сайтов — `netsh dnsclient add encryption … autoupgrade=no`; Windows 10 — только обычный DNS с подписью «без шифрования». Откат по умолчанию — только защищённый; безопасность — **проверка после переключения** (сброс кэша, до 4 попыток; нет ответа — помощник сам возвращает прежние настройки); галочка «если защищённый не отвечает — обычный DNS». «Вернуть как было» — к состоянию до первой смены (`dns-backup.json`, повторные смены его не перезаписывают). После смены окно само запускает «Проверить сейчас». Подробности и последствия — [../research/dns.md](../research/dns.md).

### Откат всего (журнал изменений)
Каждое действие программы в системе откатывается, не задевая правки пользователя и чужих программ (решение владельца, `decisions-pending.md` п. 4; команды помощника `changes_list`/`changes_undo_all`/`changes_undo`, API 1.6; код — `src/DpiShell.Core/Changes/`).
- **Журнал** — `%ProgramData%\DpiShell\changes.jsonl` (пишет помощник, закрытая папка) и `%LocalAppData%\DpiShell\changes-window.jsonl` (пишет окно: то, что делается от имени пользователя, — автозапуск `HKCU\Run` и действия на роутере). Одна строка JSON — одно событие, файл только дописывается: `do` (id, время UTC, вид `kind`, понятный заголовок `title`, снимок «было» `before` и «поставили» `after`) пишется и сбрасывается на диск **до** действия, затем `done` (с уточнением `after`) или `abort` (не состоялось, откатилось внутри функции); дальше `update` (то же изменение правится повторно: путь автозапуска, правка профиля), `closed` (функция сама вернула прежнее своим «Вернуть как было»), `undone` (итог отката: `restored|already|skipped`). Недописанная последняя строка при чтении пропускается, при следующей записи файл сначала получает перевод строки; запись без `done` — действие могло не закончиться, откат смотрит, что стоит сейчас. Не удалось записать журнал — действие всё равно выполняется (журнал — страховка), ошибка видна в `ChangeJournal.Failed`. Законченные записи вычищаются при росте файла (после 2000 строк).
- **Виды изменений и откат** (`IChangeUndoer`; откат возвращает значение, только если сейчас стоит то, что ставили мы, иначе — пропуск «изменено кем-то после нас» и вопрос в отчёте): `service` — служба оптимизации (создание — запись до `sc create`; откат удаляет её, только если в ImagePath наш winws; чужая служба под этим именем не трогается); `tcp_timestamps` — метки TCP (включили мы, были выключены; откат выключает, если включены); `dns` — снимок DNS каждого адаптера «было → поставили» (адреса IPv4/IPv6 и признак «автоматически»; откат пишет прежнее только адаптеру, у которого сейчас стоит поставленное нами, остальным — пропуск; зарегистрированные нами шаблоны DoH убираются, `dns-backup.json` забывается, когда все записи откатаны); `hosts_block`, `hosts_user`, `hosts_comment` — каждая наша строка узнаётся по пометке (блок `# DpiShell begin`, тег `dpishell-user`, `# DpiShell off`), поэтому откат вызывает готовые «Вернуть как было» (`HostsManager.Revert`/`SetUserAsync([])`/`Uncomment`) и не задевает чужие строки, в том числе дописанные позже; `core` — ядро (записывается первая установка, когда ядра не было; откат удаляет файлы по манифесту, если их хеши целы — изменённые не трогает); `app_profile` — профиль программы («Подключения программ», откат — `RemoveAppProfile`, если профиль такой, как записан); окно: `autostart` (откат — снять ключ Run, если там наша команда, и запомнить явный выбор «не запускать»), `router_dns` и `router_enable` (откат вызывает готовые «DNS как было» и «Выключить оптимизацию» роутера, нужен подключённый роутер; иначе — «не смог: роутер не подключён»). Если у функции уже есть своё «Вернуть как было» (`dns_restore`, `hosts_revert`/`hosts_restore`/`hosts_uncomment`, `app_profile_remove`, «Удалить службу оптимизации», снятие галочки автозапуска), оно закрывает записи своего вида — журнал не дублирует откат.
- **Не покрыто.** Файлы в закрытой папке самой программы (стратегии, свои сайты, результаты, `state.json`) — это данные программы, не системная настройка: их убирает «Очистка и удаление» и удаление папки. Драйвер WinDivert убирается вместе со службой (`ServiceManager.Remove`) и отдельной записи не имеет. Правил Защитника и брандмауэра программа не создаёт. Служба с нашим именем, но чужим файлом, которую пришлось бы перенастроить, не записывается: перезапись чужой службы программа не делает.
- **Отчёт.** `UndoReport`: по каждому пункту — «вернул» (`restored`), «уже было как раньше» (`alreadyBack`), «не тронул: изменено после DpiShell» (`changedByOthers`, запись закрывается, в окне — вопрос «если это тоже нужно вернуть, сделайте вручную»), «не смог» + причина (`failed`, запись остаётся, можно повторить). «Отменить всё» идёт по записям в порядке, обратном записи; окно сливает отчёты помощника и своего журнала по времени.
- **Окно.** «Настройки» → карточка «Что сделала DpiShell» над «Очисткой и удалением»: список записей с датами, «Отменить всё» (подтверждение: «Вернутся значения, которые были до DpiShell; ваши более поздние правки не трогаем.»), отчёт. «Удалить помощника» сначала предлагает «Отменить всё» — после удаления помощника его журнал уже недоступен. Без помощника видны и откатываются только записи окна. Модель — `ChangesViewModel`.
- **Точка расширения.** Новый вид изменения: константа в `ChangeKinds`; у места изменения — `IChangeRecorder` (`Begin` до действия → `Done`/`Abort`; в Core он у `Shell.Journal`, у `ServiceManager`, `DnsManager`, `HostsManager` — свойство `Recorder`); обработчик `IChangeUndoer` регистрируется в `ShellHelperBackend.Changes.Register(…)` (помощник) или в движке окна (`MainViewModel`).

### Ядро на роутере
Тот же `zapret-v72.13.zip` и тот же `core.json`, что у Windows: при «Загрузить ядро» роутер качает архив (основной адрес, затем зеркала), проверяет sha256 архива и `binaries/linux-<arch>/nfqws`, извлекает только пути из `extract` в `/opt/zapret`. Не `install_easy.sh` (он интерактивный и добавляет в cron загрузку списков со сторонних адресов) — его шаги повторяются: `common/`, `init.d/openwrt/`, `files/`, `ipset/`, `config.default`, `nfqws` → `/opt/zapret/nfq/nfqws`, наш `config`, ссылки `/etc/init.d/zapret` и `/etc/hotplug.d/iface/90-zapret`. Служба `/etc/init.d/zapret` и таблица nft `inet zapret` — штатные zapret; мы пишем только `/opt/zapret/config`. Перед каждым стартом — sha256 `nfqws`. Если GitHub с роутера недоступен — офлайн-набор ([building.md](building.md)).

### Сборка config zapret из стратегии
`NFQWS_PORTS_TCP=80,443,2053,2083,2087,2096,8443`, `NFQWS_PORTS_UDP=443,19294-19344,50000-50100` (те же, что `--wf-*` на Windows); `NFQWS_OPT` — профили ролей через `--new` без изменений (фильтры ролей — из `roles.json`, общих с Windows); `MODE_FILTER=none`; `FLOWOFFLOAD` по диагностике; `DISABLE_IPV6` по настройке. `{lists}` → `/etc/dpishell/lists` и `/usr/share/dpishell/lists`, `{fake}` → `/usr/share/dpishell/fake`. Каждый токен — по белому списку, пути — только внутри наших каталогов. Перед записью — `nfqws --dry-run`. Что реально работает, читается из `/opt/zapret/config`; чужое содержимое — «config zapret изменён не нами».

### Режимы роутера
Основной режим — **«Все сайты»** (по умолчанию): профили `general`/`google` без `--hostlist`, только `--hostlist-exclude` (стандартный + свой) и `--ipset-exclude` (приватные сети) — так открывается и то, чего ещё нет в списках. «По спискам» — запасной. Смена режима — перезапуск zapret и автоматически полная проверка с контрольной группой (стратегия, подобранная в одном режиме, в другом может ломать сайты). «Сайт не открывается с оптимизацией»: адрес проверяется с оптимизацией и без (на время проверки — в `nozapret`); открывается только без — предложение добавить в исключения.

### Страница роутера
Состояние (Выключено / Работает — стратегия, проверено / Подбор k из N / Ошибка), выбор стратегии отдельно от выключателя, кнопки Включить/Выключить, Подобрать, Проверить сейчас; «Включить» без стратегии и статистики = подобрать. Предупреждения строками с кнопкой действия (flow offloading, IPv6, чужой оптимизация, подмена DNS, запасная стратегия, «компьютерам на Windows нужна настройка» при `needs_tcp_timestamps`). Вёрстка — одна колонка карточек, читается на телефоне. Вкладки: Оптимизация, Подбор, Исключения и списки, DNS, Диагностика.

### Подбор на роутере
- Подбор идёт **с самого роутера**: правило nfqws (`postrouting`, `ct original packets 1-9 queue num 200`) видит и транзитный трафик клиентов, и трафик роутера, поэтому `curl` с роутера проходит ту же стратегию, что устройства в сети. На время подбора оптимизация для всей сети переключается между стратегиями — страница предупреждает.
- Проверка цели — `curl` с `--resolve` на адрес из DoH, `--tlsv1.3 --tls-max 1.3` и `1.2`, `-o /dev/null -w '%{http_code} %{size_download} %{redirect_url}'`; коды выхода 18/56/35/28 — провал с причиной. Критерий тот же, что на ПК.
- Отдельный процесс procd `dpishell-select`, ход — `/tmp/dpishell/select.json`, файл-замок с PID (мёртвый замок не блокирует); страницу можно закрыть. После `zapret restart` nfqws поднимается асинхронно — подбор ждёт новый процесс. Перезагрузка во время подбора — при старте восстанавливается прежняя стратегия.
- Глубокий поиск — тот же генератор, что на ПК; базовая стратегия — текущая, иначе `alt9`; на роутере — около 10 минут (оценка: в эмуляторе без сети 1,5 мин на ~80 проверок; уточнить замером на роутере).
- Проверка в эмуляторе — имитатор DPI в `probe.uc`: файл `/tmp/dpishell/fake-dpi.json` (только root) с правилами «сайт открывается, если в профиле nfqws есть такие приёмы»; без файла не действует.

### Проверка по таймеру и запасные
Кнопка и таймер независимы; таймер отключаемый (30 мин — 24 ч, по умолчанию 1 ч). Проверка по таймеру лёгкая (обязательные цели, одна версия TLS), по кнопке — полная; не стартует во время подбора и при выключенном оптимизации. Две неудачи подряд — переключение на следующую из рейтинга запасных (предупреждение `switched_backup`); запасные кончились — «Стратегия перестала работать». **«Подбирать автоматически»** (выключено по умолчанию): роутер сам запускает быстрый подбор, не чаще раза в 6 ч; выключено, потому что подбор на 2–3 мин даёт перебои на всех устройствах в непредсказуемый момент. На ПК фоновых проверок нет вовсе: редкая проверка — пользователь заметит раньше, частая — лишний трафик.

### Аварийный выключатель
Выключить оптимизацию, когда со страницей роутера не связаться, а SSH и ИИ у человека нет. Включить снова может только человек.
- **Кнопка на корпусе** (`/etc/hotplug.d/button/50-dpishell` → `/usr/libexec/dpishell/off button`). Штатный `/etc/rc.button/reset` не заменяется: procd зовёт оба. Как кнопки работают на конкретной прошивке, не проверяем — тексты для человека с оговоркой «на большинстве роутеров с OpenWrt» (решение владельца 2026-10-19). WPS — выключить без перезагрузки. Reset короче 1 с — штатная перезагрузка, оптимизацию выключается до неё (сначала `enabled=0` в uci); 1–4 с — штатно ничего, выключаем без перезагрузки; от 5 с — штатный сброс к заводским, не трогаем. Аварийный режим при загрузке (preinit) сюда не попадает.
- **Подтверждение** (`confirm_s` у `enable`/`strategy_set`/`apply`): роутер пишет `/etc/dpishell/pending-confirm.json` и ждёт `confirm` (фоновое `run revert`), иначе возвращает прежнее; перезагрузка до подтверждения — тоже откат (`run revert now` при старте). Окно ПК после «Включить» само проверяет сайты и подтверждает, человека спрашивает, только если не открылись. Подбор, автоподбор и расписание идут без подтверждения — их страхует сторож.
- **Сторож** (`run guard`, по умолчанию вкл., `schedule.watchdog`): 3 обязательные цели группы `control` не из исключений (стандартных и своих; сайты из исключений оптимизацию не трогает, их поломку сторож не увидел бы), только рукопожатие TLS, по одной и до первой открывшейся. Две неудачи подряд — проверка без оптимизации: открылось — оптимизацию выключается (`last_off.targets` — что не открылось); нет — обрыв у провайдера, оптимизацию возвращается, интервал 5 → 10 → 20 мин, после успеха снова 5. Не идёт во время подбора, проверки, обновления, DNS-заданий и пока включение ждёт подтверждения (откат по сроку сделает своё — без качелей «откат → сторож»).
- **Подбор после сторожа**: выключив оптимизацию, сторож один раз запускает быстрый подбор (`started_by: watchdog`, внутри того же `run tick` под nice). Нашёл — включает, как автоподбор (`auto_selected`); найденная прошла и группу `control`, на которой сторож сработал. Не нашёл — оптимизация выключена, `watchdog_select_failed`. Повтор — только после «Включить» или подбора человеком (`/etc/dpishell/watchdog-select.json` снимают `enable`/`select_start`): сломается и найденная — сторож выключит её снова, но подбирать уже не будет.
- **Нагрузка**: одна строка cron `*/5 * * * * nice -n 19 … run tick` — сторож каждый раз, проверка по таймеру, DNS и обновления раз в 30 мин. Журнал — только logread; состояние — маленькие перезаписываемые файлы (`/tmp/dpishell/guard.json`, `/etc/dpishell/last-off.json`).

### Диагностика роутера
- Чужие оптимизации: службы `zapret2`, `youtubeUnblock`, `b4`, процессы `nfqws`/`nfqws2` не нашего запуска — включение и подбор заблокированы, «Остановить». Чужой zapret **пакетом** (`zapret`, `luci-app-zapret`, `zapret-manager-beam`, `zapret2` — менеджеры zapret в сторонних прошивках ставят пакет в тот же `/opt/zapret`) — остановить нельзя, только удалить; установка ядра отказывает.
- **Flow offloading**: системная разгрузка fw4 несовместима с nfqws (соединение в flowtable nfqws не видит). «Исправить»: разгрузка в firewall выключается, в config zapret — `FLOWOFFLOAD=software|hardware`, zapret ведёт свою flowtable с исключением для пакетов nfqws — скорость не теряется. Прежнее значение хранится и возвращается при удалении пакета.
- **IPv6**: по умолчанию оптимизация только по IPv4; глобальный адрес на WAN6 → предупреждение и «Исправить» (`ipv6_set`, `DISABLE_IPV6=0`), иначе YouTube пойдёт мимо оптимизации.
- «Сохранить отчёт»: версии, хеши, config zapret, `nft list table inet zapret`, DNS, хвост `logread`; свои сайты скрыты.

### DNS для всей сети
Роутер раздаёт DNS всем устройствам, поэтому при подмене у провайдера телефоны, ТВ и ПК получают неверные адреса и оптимизация им не помогает. «Диагностика → DNS» и перед подбором — анализ: ответ DNS провайдера против консенсуса двух DoH (сравнение по /16 и владельцу), доступность и скорость DoH. Варианты (`dns-presets.json`): от провайдера, Google + Cloudflare (по умолчанию), Google, Cloudflare, Quad9, Яндекс (с пометкой), свой. Включение — установка штатного `https-dns-proxy` в этот момент (он сам настраивает dnsmasq: экземпляры на `127.0.0.1:5053/5054`, `noresolv`, WAN `peerdns 0`), затем проверка, что DNS отвечает; не заработал — возвращается предыдущий. Прежние настройки — `/etc/dpishell/dns-backup.json`; «Вернуть как было» — `apk del https-dns-proxy`, восстановление, **явный перезапуск dnsmasq** (сам он не перезапускается — DNS пропадает) и проверка `nslookup`. Оба DoH пропали — временный возврат к DNS провайдера по таймеру проверки (`dns_fallback`). Имена домашней сети (`*.lan`) не страдают — их отвечает dnsmasq. Операции фоновые (установка пакета 10–20 с).

### status.json
`/www/dpishell/status.json` — для приложения на ПК, без входа, из LAN: `{ "product": "dpishell-router", "api": "1.0", "min_app": "0.9.0", "version": …, "engine": "zapret1", "core": …, "enabled": …, "strategy": …, "catalog_version": …, "checked_at": …, "last_check_ok": … }`. Без адресов, списков и логов.

### Установка, обновление, удаление
- **Установка из окна ПК по SSH** — сценарии передаются через stdin ([router-api.md](router-api.md) §5.5): `dpishell-preflight.sh` (пригодность: OpenWrt и apk, fw4/nftables, `kmod-nft-queue` под ядро, сеть, место, чужой оптимизация) → `dpishell-install.sh` (ключ витрины, строка витрины, пакеты, ядро). Роутеру без GitHub интернет даёт ПК: `ssh -R` к HTTP-прокси окна и `https_proxy` в команде; архив ядра окно кладёт по SFTP. Выбор выпуска — `data/router-releases.json`.
  - Сторона окна — `src/DpiShell.Core/Router`: `RouterInstallFlow` (установка и удаление целиком), `RouterSsh` (сценарии из ресурсов сборки — те же файлы `router/`), `RouterSuitability` (годится ли роутер, причины по-русски), `RouterReleases.Choose`, `PcTunnelProxy`/`RouterTunnel`, `RouterCoreArchive`, `RouterCompatibility` (§5.4). SSH — SSH.NET (`SshNetConnector`).
  - Ключ роутера запоминается при первом входе; другой — отказ «Ключ роутера изменился (переустановили прошивку?)», пока пользователь не подтвердит.
  - Окно (`RouterViewModel.Setup.cs`, `RouterInstallDialog.cs`): «Установить на роутер» (проверка → установка по шагам → вход тем же паролем), «Удалить DpiShell с роутера» (через API или по SSH, затем «что осталось»), «Доступно обновление» (витрина, иначе пакеты через ПК по подписанному `release.json` — `RouterUpdatePackages`), плашка совместимости §5.4, «Доверять новому» ключу. Отпечатки ключей — `%LocalAppData%\DpiShell\router-hostkeys.json`.
  - Прокси туннеля живёт только на время сценария и пускает лишь витрину, фиды из `distfeeds`/`customfeeds` роутера, `downloads.openwrt.org` и GitHub, порты 443/80. Без `sftp-server` на роутере (по умолчанию его нет) файлы идут потоком в `cat`; всё загруженное сверяется `sha256sum` на роутере.
- **Обновление**: раз в сутки (таймер `run watch`) — `apk update` и сравнение версий, итог — `status.update` и плашка «Доступно обновление» с заметками из `router/release-notes.json`; `update_install` — из витрины или из `/tmp/dpishell-update` (окно ПК, только наши пакеты по `SHA256SUMS`). Номер сборки (`PKG_RELEASE`) поднимается при каждой правке пакета — иначе роутеры её не получат.
- **Удаление**: `uninstall { keep_settings }`, кнопка в свёрнутом разделе «Удаление DpiShell» внизу «Диагностики» (подтверждение словом «удалить»), без API — `uninstall.sh` по SSH, при ручном `apk del` — prerm. Возвращается всё изменённое вне своих файлов: разгрузка межсетевому экрану, DNS (с удалением https-dns-proxy, если ставили мы), метки TCP, cron; удаляются ядро `/opt/zapret` и папки пакетов; модули ядра и зависимости остаются. Проверка после — `dpishell-preflight.sh --after-uninstall`.
- **Выпуски**: тег `router-vX.Y.Z` → релиз GitHub: пакеты, `release.json` (версия, api, min_app, что нового, sha256 файлов) и подпись ed25519; сборка сверяет тег, `PKG_VERSION` и `VERSION`.

## Безопасность (сводно)

- Всё заимствованное — закреплённые хеши и белые списки ([../vetting.md](../vetting.md)); ядро только из релизов bol-van; скрипты zapret исполняются как есть из проверенного архива.
- ПК: окно без прав; помощник принимает только команды из белого списка с проверкой аргументов, без командной строки и путей; канал — DACL + проверка SID клиента; папка данных и папка помощника закрыты правами; ядро проверяется по хешам перед каждым запуском.
- Роутер: ACL rpcd — только `dpishell.*`, без `file.exec`/`file.write`; методы проверяют входные данные сами, командной строки и путей от клиента не принимают; `/etc/dpishell` — только root; `status.json` без секретов; API только из LAN.
- Пароль роутера — DPAPI на ПК, в логи и отчёты не попадает; сохраняется после любого удачного входа — и в окне, и по SSH (проверка, установка, удаление), переиспользуется везде, стирается, только когда перестал подходить, или по «Забыть» (вкладка «Роутер» → «Подключение» и «Настройки» → «Роутер»: «Пароль сохранён на этом компьютере»). Поле window.json не того вида (писала другая сборка) не стирает остальные настройки; в отчётах свои сайты пользователя скрыты.
- Обновления: источники только из поставки, файлы только по sha256; манифест данных — только с подписью ed25519 (`data.json.sig`); обновление программы — только по подписанному `release.json` и sha256 архива.

## Вне рамок и планируется

Не делается: VPN; zapret2/nfqws2 (другой синтаксис стратегий — только адаптер `engine`); автоматическая проверка голоса Discord/игр по UDP; Windows 7/8, 32-бит, ARM64; разные стратегии для разных устройств роутера; установка самой OpenWrt (под ответственность пользователя); приложение для Android (без root zapret не работает; дома телефон покрывает роутер, управлять им можно со страницы `/dpi`).

Планируется:
- **Окно ПК**: плашка обновления программы на главной, флаг «данные не подписаны», «Обновить помощника» (ядро готово — «Обновление программы», `HelperCompat`).
- Пакеты под `opkg` (OpenWrt 24.10); параллельный подбор; перехват DNS устройств с жёстко прописанным DNS; игровой режим и IP-списки на роутере.
