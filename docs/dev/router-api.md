# Договор: управление оптимизацией соединения (обходом DPI) на роутере из Windows-приложения

Версия API 1. Сторона роутера — пакет `dpishell` (`router/dpishell`, ubus-объект `router/dpishell/files/usr/share/rpcd/ucode/dpishell`), сторона ПК — `src/DpiShell.Core/Router/RouterClient.cs`, тесты — `tests/DpiShell.Tests/FakeRouter.cs` и `Router*Tests.cs`. Документ — единственный источник формата: меняется только с увеличением `api` (до первого выпуска роутерного пакета — правки без увеличения, см. §9).

## 1. Как это устроено

- На роутере работает `rpcd` (штатная часть OpenWrt). Через него страница DpiShell в меню роутера вызывает методы объекта `dpishell`. Windows-приложение вызывает **те же методы тем же путём** — отдельного сервера для приложения нет.
- Транспорт: JSON-RPC 2.0, `POST http://<адрес роутера>/ubus`, `Content-Type: application/json`.
- Роутер принимает запросы только из домашней сети (uhttpd слушает LAN, fw4 закрывает WAN).

## 2. Поиск роутера

1. Адрес по умолчанию — основной шлюз IPv4 активного адаптера (у OpenWrt по умолчанию `192.168.1.1`). В настройках можно указать свой адрес (IP или имя, без схемы и пути).
2. `GET http://<адрес>/dpishell/status.json`, таймаут 1 с, без входа. Роутер с DpiShell — если `product == "dpishell-router"`. Формат — [architecture.md](architecture.md), «status.json», плюс поле `"api": 1`.
3. Нет ответа / 404 / другой `product` — «На роутере DpiShell не найден». Приложение работает как раньше, только с ПК.
   - Роутер может стоять не первым: «роутер провайдера → наш роутер → ещё один роутер/Mesh → ПК». Если по шлюзу DpiShell не найден, приложение пробует ещё до 3 частных адресов на пути наружу (первые узлы `tracert -d -h 4`, только `10/8`, `172.16/12`, `192.168/16`), тем же запросом с таймаутом 1 с. Найден не на шлюзе — управление так же, вход по паролю того роутера.
4. `api` у роутера больше, чем знает приложение — «Обновите приложение», разрешено только чтение статуса. Меньше **или поля `api` нет** (пакет старше договора) — «Обновите пакет на роутере», только чтение статуса.

## 3. Вход

```json
→ {"jsonrpc":"2.0","id":1,"method":"call","params":["00000000000000000000000000000000","session","login",{"username":"root","password":"<пароль>","timeout":600}]}
← {"jsonrpc":"2.0","id":1,"result":[0,{"ubus_rpc_session":"c1ed6c7b…","timeout":600,"expires":600,…}]}
```
- Пароль — пароль администратора роутера (тот же, что для меню). Хранится на ПК через DPAPI (`ProtectedData`, `CurrentUser`), в логи и отчёты не попадает.
- Сессия живёт `timeout` секунд с последнего вызова. Неверная или истёкшая сессия: штатный `uhttpd-mod-ubus` отвечает ошибкой JSON-RPC `{"error":{"code":-32002,"message":"Access denied"}}` без `result`; вызов, на который у сессии нет прав, возвращает `result[0] == 6`. Оба случая — «нет доступа»: войти заново один раз; снова — «Неверный пароль или сессия», запросить пароль.
- `result[0] == 6` на `login` — неверный пароль.

## 4. Вызов метода

```json
→ {"jsonrpc":"2.0","id":2,"method":"call","params":["<ubus_rpc_session>","dpishell","<метод>",{…аргументы…}]}
← {"jsonrpc":"2.0","id":2,"result":[0,{…ответ…}]}
```
- `result[0]` — код ubus: `0` успех, `2` неверные аргументы, `4` метода/объекта нет (пакет не установлен или старый), `6` нет доступа, `7` таймаут, `5` ответа нет.
- Ошибка уровня DpiShell при коде `0`: `{"error":{"code":"busy","text":"Идёт подбор"}}`. Коды: `busy`, `not_installed` (ядро не загружено), `invalid` (с полем `field`), `conflict` (работает чужой оптимизация), `core_mismatch` (хеш ядра), `failed` (с `text`). У всех кодов `text` — готовая фраза для пользователя.
- Необязательное `parts` (роутер 0.2.0-r9) у собранных из частей («Смешанная»): в `strategies_user_set` и `strategies.items[]`, у роутерной смешанной — и в `select_progress.rows[]`: `{ "youtube": "<id>", "discord": "<id>", "user": "<id>" }` — из какой стратегии взята часть группы. Роли части: YouTube — `google`; Discord — `discord_tcp`, `discord_udp`, `discord_media`; свои — `general`, `quic`, `ipset_*`, `game_*`. Роутер хранит `parts` как прислали. Его подбор (не глубокий), если ни одна стратегия не открыла всё, собирает смешанную из лучших по группам (`r-mix-<хеш частей>`; название — как у ПК, MixBuilder: «Смешанная · YouTube — ALT · Discord — ALT2 · свои сайты — ALT10», части из одной стратегии сливаются — «остальное», до 60 знаков — иначе «свои»; роли частей без лучшей стратегии — из основы «свои» → Discord → YouTube) и делает один проверочный прогон; строка остаётся и включается, только если у неё выше доля групп, а при равной — доля адресов, чем у лучшей одиночной. Глубокий поиск подбирает три роли раздельно (`google` → YouTube, `discord_tcp` → Discord, `general` → свои) и собирает их как ПК (StrategySearch.Assemble): лучший приём каждой роли + по одной запасной на роль.
- Необязательное `roles` (как в `strategies_user_set`) в элементах `strategies` и строках `select_progress.rows`: окно по нему даёт найденным стратегиям короткое имя из параметров («Новая: fake+multisplit · ts · ×6»); нет — показывает `title` как есть.
- `field` при `invalid` — путь к значению в аргументах: `items[3].url`, `items[0].roles.google`, `hours`, `groups`. Индексы с нуля.
- Таймаут HTTP — 10 с. Долгие операции (подбор, проверка, загрузка ядра, DNS) только запускаются и возвращаются сразу (rpcd-вызов не ждёт); ход — опросом `status`/`select_progress` раз в 1 с.

## 5. Методы

Время — ISO 8601 UTC. Идентификаторы стратегий — как в `strategies.json` / `user-strategies.json`.

### 5.1 Чтение

**`status`** `{}` →
```json
{ "api": "1.0", "version": "0.2.1", "min_app": "0.9.0", "methods": ["apply", "check_now", "…", "uninstall", "update_install"], "engine": "zapret1",
  "core": { "version": "v72.13", "installed": true, "hash_ok": true, "installed_version": "v72.13" },
  "packages": { "dpishell": "0.2.0-r8", "luci-app-dpishell": "0.2.0-r5" },
  "enabled": true, "mode": "all", "strategy": "alt10", "backups": ["alt9", "alt13"], "needs_tcp_timestamps": true,
  "last_check": { "at": "2026-10-16T21:00:00Z", "source": "timer", "ok": true,
                  "groups": [ { "id": "youtube", "ok": true }, { "id": "discord", "ok": true } ] },
  "fail_streak": 0,
  "schedule": { "enabled": true, "hours": 1, "auto_select": false, "watchdog": true },
  "pending_confirm": { "until": "2026-10-19T12:03:00Z", "left_s": 165, "revert_to": "off" }, "last_off": null,
  "watchdog": { "enabled": true, "checked_at": "2026-10-19T12:00:01Z", "ok": true, "interval_min": 5, "select": null },
  "advanced": { "enabled": false, "rows": 0 },
  "pc_links": 0,
  "rollback": { "version": "0.2.0-r15", "saved": true, "reason": null },
  "jobs": { "select": false, "check": false, "core_install": false, "dns": false, "dns_analyze": false, "site_check": false, "update": false, "changes": false },
  "warnings": [ { "code": "flow_offload", "text": "Включено ускорение сети (flow offloading) — с ним оптимизация не работает" } ],
  "update": { "available": true, "version": "0.2.1-r1", "notes": ["Глубокий поиск стратегий на самом роутере"], "checked_at": "2026-10-17T14:00:00Z",
              "job": { "action": "update", "from": "feed", "running": false, "step": "done", "started_at": "…", "from_version": "0.2.0-r6",
                       "target": "0.2.0-r7", "log": ["(2/2) Upgrading luci-app-dpishell (0.2.0-r4 -> 0.2.0-r5)", "OK: 22.3 MiB in 193 packages"], "ok": true, "message": "Обновлено до 0.2.0-r7", "at": "…" } } }
```
`source`: `manual` | `timer` | `app`. `jobs.dns` — идёт любое DNS-задание (`dns_analyze` — прежнее имя, то же значение). Коды `warnings`: `flow_offload`, `ipv6`, `dns_spoofed`, `conflict`, `core_missing`, `switched_backup` (сработала запасная стратегия, в `text` — какая), `auto_selected` (автоподбор нашёл и включил стратегию, в `text` — какую), `auto_select_failed` (автоподбор ничего не нашёл, оставлена прежняя), `watchdog_select_failed` (с 0.2.0-r8: сторож выключил оптимизацию, подбор после него не включил стратегию — оптимизация выключена; снимается «Включить» или подбором), `dns_fallback` (защищённый DNS недоступен, временно DNS провайдера), `watchdog_off` / `button_off` / `confirm_reverted` (оптимизация выключена сторожем, кнопкой на корпусе, откатом неподтверждённого включения — пока его не включат снова). **Аварийный выключатель** ([architecture.md](architecture.md) «Аварийный выключатель»): `pending_confirm` — включение ждёт `confirm` до `until` (`left_s` — сколько осталось на момент ответа: часы роутера и ПК могут расходиться), иначе роутер сам вернёт `revert_to` (`off` или id стратегии), `null` — не ждёт; есть и в `status.json` (без входа). `last_off` — последнее выключение без человека `{ by: "watchdog"|"button"|"revert", at, text, targets: [ { url, detail } ] }` (`targets` — что не открылось у сторожа), `null` при включённой оптимизации. `watchdog` — жив ли сторож: последняя проверка и через сколько минут следующая (5, при обрыве у провайдера 10, 20). Сторож не проверяет, пока есть `pending_confirm`. **Подбор после сторожа** (с 0.2.0-r8): выключив оптимизацию, роутер один раз сам запускает быстрый подбор (`started_by: watchdog`); нашёл — включает (`auto_selected`, в `text` — какую), нет — оптимизация выключена, `watchdog_select_failed`. Больше сам не пробует, пока человек не сделает `enable` или `select_start`. `watchdog.select` — этот подбор уже был `{ at, ok, best }` (`best` — включённая, `null` при неудаче; пока идёт — `ok: false`, `jobs.select: true`), `null` — не было с последнего действия человека; старые роутеры поля не отдают. `needs_tcp_timestamps` — включённая стратегия работает только у устройств с временными метками TCP (нужно только компьютерам на Windows: у Android, iOS, macOS и Linux они включены по умолчанию).

`api` — «мажор.минор» (§5.4); роутеры до 0.2.0 отдают число `1` (= «1.0»). `core.version` — версия ядра, закреплённая в пакете; `core.installed_version` — установленная в `/opt/zapret` (`null` — не установлено), `packages` — установленные версии пакетов DpiShell (`null` — пакета нет); оба поля с 0.2.0-r8, старые не отдают. `methods` — методы, которые этот роутер реально обрабатывает (заглушки «не реализовано» не входят); `min_app` — минимальная версия окна ПК, которую он понимает. `update` — есть ли в витрине версия новее установленной (проверка раз в сутки и по `update_check`), `notes` — что нового (до 15 строк, `router/release-notes.json`), `job` — последнее задание обновления (`null` — не было): `step` — `download` → `install` → `restart` (ждёт, пока после перезапуска rpcd объект снова отвечает) → `done`; `at` — время последнего шага, `target` — ставящаяся версия, `log` — до 6 последних строк apk/opkg. Задание, чей процесс умер (убит со старым rpcd, перезагрузка), закрывается по факту при чтении `status`: установленная версия против `target` (у записей до r7 — против версии витрины). Окно: шаги «Скачиваю → Устанавливаю → Перезапуск службы → Готово» и «Подробнее» с `log` (принимает и массив строк, и одну строку); без `step` (до r7) — «Обновляю…» с прошедшим временем. `running` дольше 4 мин при отвечающем роутере окно решает по `version`: уже новая — «обновлено, роутер не дописал итог», прежняя — «Обновление не завершилось» и «Повторить».

**`strategies`** `{}` → `{ "catalog_version": 3, "items": [ { "id": "alt10", "title": "general (ALT10)", "source": "catalog|user", "runs": 7, "passed": 6 } ] }` — порядок как в списке выбора (по статистике). Необязательные поля (роутер с 0.2.0-r7; старые не отдают): `last: { "at": "…", "ok": false, "failed": ["Discord"] }` — последняя проверка этой стратегии, подбором или проверкой текущей (`failed` — названия групп: YouTube, Discord, Свои сайты, Обычные сайты; `null` — не проверялась; окно показывает только её, историю `runs`/`passed` — нет), `roles: { "google": "…", "general": "…" }` — параметры по ролям, как в `strategies.json`, для «Подробнее». `source: user` — присланные с ПК (`u-…`) и найденные глубоким поиском на роутере (`r-…`, последние 20).

**`select_progress`** `{}` →
```json
{ "running": true, "started_by": "app", "depth": "main", "index": 4, "total": 20, "eta_s": 95,
  "message": "alt3: YouTube",
  "rows": [ { "id": "alt", "title": "general (ALT)", "group_share": 1.0, "target_share": 0.88, "avg_s": 0.74, "error": null,
              "verdicts": [ { "group": "youtube", "url": "https://www.youtube.com/", "ok": false, "detail": "TLS 1.2: поток оборвался на 16384 байтах", "seconds": 6.1 } ] } ],
  "finished_at": null, "cancelled": false, "best": null, "applied": false, "backups": [] }
```
`index` — номер проверяемой стратегии с 1. `title` в строках `rows` — всегда: название из каталога или короткое описание кандидата глубокого поиска («fake + multisplit, ts — YouTube»); у кандидатов ещё `candidate: true`, `ok`/`total` (сколько обязательных целей роли открылось); кандидаты в `strategies` не попадают — только найденные в финале. `started_by`: `page` | `app` | `auto` («Включить» без стратегии) | `timer` (автоподбор после неудачной проверки) | `watchdog` (подбор после сторожа, §5.1 `status`). Подбор, запущенный с другого устройства, виден так же и его можно отменить. `eta_s` — оценка оставшегося времени, `null`, пока не известна (глубокий поиск сужает перебор по ходу). После завершения — `best`, `applied: true` (подбор сам включил лучшую) и `backups` (до 3 запасных). Остановленный подбор — `cancelled: true`, `applied: false`, прежнее состояние восстановлено. Доли `group_share`/`target_share` — дробные. `groups_ok`/`groups_total` (целые, роутер с 0.2.0-r8; старые не отдают — окно считает по `group_share`, если может) — сколько групп открылось из проверявшихся, для «N из M»: у полных проверок — все группы подбора, кроме контрольной (группа открылась — все её обязательные цели и хотя бы одна цель); у кандидатов — группы роли, по обязательным целям; ошибка запуска — `groups_ok: 0`. `verdicts` (у полных проверок, не у кандидатов) — исход по каждой цели для «Подробнее»: `detail` — одна строка (код, байты, редиректы; у провала — что сломалось, с версией TLS, если проверялись обе), `seconds` — самая долгая из проверок цели. Исходы проверки — как на ПК: свои редиректы проходятся до конечной страницы (до 5) и судятся по ней, чужой редирект — заглушка, HTTP 451 — блокировка, 403/404 у целей с телом — провал.

Необязательные аргументы (роутер с 0.2.1-r2): `{ "since": N, "run": R }` → в `rows` только строки с номера `N` (с 0), остальное как обычно. В ответе такого роутера всегда, и без аргументов, — `run` (метка подбора, `started_at` в unix-секундах; 0 — подборов не было), `rows_from` (с какого номера строки в `rows`) и `rows_total` (сколько строк всего). `run` в аргументах не совпал с текущим (уже другой подбор) или `since` не число ≥ 0 — строки с 0 (`rows_from: 0`); `since` больше числа строк — `rows: []`, `rows_from = rows_total`. Строки подбора после записи не меняются, только добавляются — клиент дописывает новые к полученным. **Слать `since`/`run` только роутеру, чей прошлый ответ был с `rows_total`**: старый rpcd отвергает необъявленный аргумент (`ubus` код 2, Invalid argument; проверено в эмуляторе). Окно ПК и страница так и делают: первый опрос без аргументов, дальше — `since` = число полученных строк и `run` из ответа. Без аргументов ответ прежний (плюс три поля) — старые окна работают как раньше.

*Предложение окна (формат обсуждается, в договор не внесено):* у строки `rows` — необязательное `verdicts: [ { "group": "youtube", "url": "https://www.youtube.com/", "ok": true, "detail": "TLS 1.3 и TLS 1.2: 200, 512 КБ", "seconds": 0.52 } ]` — итог по каждому проверенному адресу для «Подробнее» в таблице подбора (`RouterUrlVerdict`). Нет поля — окно показывает «Подробности по адресам появятся после обновления роутера».

**`targets_get`** `{}` → `{ "items": [ { "url": "https://example.com/", "important": true } ] }` — только «Свои сайты» роутера.

**`lists_get`** `{ "name": "user-general" | "user-exclude" | "exclude" | "google" | "discord" | "general" }` → `{ "lines": ["example.com"], "editable": true }` — `exclude` (стандартные исключения) и встроенные списки ролей `google`, `discord`, `general` (с 0.2.0-r9, для совместной работы: ПК исключает адреса роутера у себя) — только для чтения.

**`diag`** `{}` → `{ "conflicts": [ { "kind": "service", "name": "zapret2", "running": true } ], "flow_offload": false, "flowoffload": "software", "ipv6_wan": false, "dns": { "spoofed": true, "checked_at": "…" }, "overlay_free_kb": 18000 }`. `flow_offload` — разгрузка включена в межсетевом экране (мешает оптимизации, предупреждение `flow_offload`); `flowoffload` — разгрузку ведёт zapret после `flow_offload_fix` (`none` | `software` | `hardware`, оптимизации не мешает). `conflicts[].kind`: `service` (чужой демон — его останавливает `conflict_stop`), `package` (чужой zapret пакетом — `zapret`, `luci-app-zapret`, `zapret-manager-beam`, `zapret2`: занимает `/opt/zapret`, остановить нельзя, только удалить; `core_install` при нём отказывает).

**`site_check_result`** `{}` → `{ "running": false, "url": "https://example.com/", "with_bypass": { "ok": false, "detail": "сброс после 16 КБ" }, "without_bypass": { "ok": true, "detail": "" }, "suggest_exclude": true }` — `suggest_exclude`: открывается только без оптимизации, предложить добавить в исключения (`lists_set user-exclude`).

**`dns_compare_result`** `{}` → `{ "running": false, "items": [ { "id": "google", "ms": 38 }, { "id": "custom", "ms": null } ], "at": "…" }` (с 0.2.1-r2) — итог последнего `dns_compare_start`: `items` как у `dns_compare` (`null` — замера не было, он идёт или прервался), `at` — когда закончился. Задание умерло — `running: false, items: null`. Итог живёт в ОЗУ не дольше ~10 мин.

**`report`** `{}` → `{ "text": "…" }` — то же, что «Сохранить отчёт» на странице. Свои сайты пользователя в отчёте заменены на «свой адрес №N».

**`security_check`** `{}` → `{ "checks": [ { "id": "http_login", "state": "warn", "detail": "https_optional" }, { "id": "port_forwards", "state": "warn", "params": { "n": 2 } } ], "checked_at": "…" }` (с 0.2.0-r13; с 0.2.0-r17 — группа записи: учётке «только чтение» сведения о защите не отдаются) — «Безопасность роутера», справочно: только чтение настроек (`uci`, наличие файлов, адреса прослушивания), ничего не меняет; секретов в ответе нет (пароль и ключи Wi-Fi — только «задан/не задан»). `state`: `ok` | `warn` | `unknown` («не удалось проверить» — не `ok`). `id`: `root_password`, `http_login` (`detail`: `https_optional`, `redirect`), `panel_listen`, `ssh_listen`, `ssh_password` (`warn_keys` — ключ уже есть), `wan_firewall`, `wan_admin` (`params.ports` или `detail: warn_all`), `port_forwards` (`params.n`), `upnp` (`none` — не установлен, `warn_insecure`), `wifi_encryption` (`open`/`weak`, `params.n`; без Wi-Fi пункта нет), `dns_rebind`, `dns_wan` (`local`). Ускорение сети здесь не повторяется — оно в `diag`. Звать, только если метод есть в `status.methods`: старый роутер — блока нет; старое окно метод не зовёт. Итог (id и состояния, без `params`) — и в `report`.

Пункты выводятся из текущего состояния, а не из ленты событий (журнал не растёт и не расходится с роутером): `enable` — оптимизация включена (nfqws, правила nft, автозапуск), `pc:<id>` (`kind: pc_link`) — связка с ПК, `advanced` — свои настройки для сайтов, `list:<имя>` (`kind: list`) — непустой свой список (`params.name` — вложенная фраза, `params.n` — строк), `ipv6`, `flow_offload` — ускорение сети выключено пакетом (`params.mode`: software | hardware), `dns` — DNS для всей сети изменён, `core` — ядро в `/opt/zapret`. «Как было до DpiShell»: у своих настроек — пусто (их создаёт пакет), у системных — копии, которые пакет и так ведёт (`fw_offload_prev`, `dns-backup.json`). `at` — когда пункт появился (время включения, IPv6, ускорения сети — в `/etc/dpishell/changes.json`, не больше 4 ключей, пишется только при появлении пункта; остальное — по файлам). `undo`: `yes` — можно отменить отдельно, `no` — нельзя (`note_key`/`note` — почему; сейчас только ядро: убирается удалением). `risk: link` — отмена перезапускает DNS или межсетевой экран: связь может прерваться на несколько секунд (окно и страница предупреждают в вопросе). `job` — итог последней отмены (`changes_undo`/`changes_undo_all`), по пунктам `status`: `restored` | `same` (уже как было) | `skipped` | `failed` (`note`, `note_key`); задание умерло — `running: false, ok: false`. Названия — по ключам `router.changes.*` (текст — для старых окон). Звать, только если метод есть в `status.methods`: старый роутер — карточки нет.

**`dns_status`** `{}` → `{ "mode": "provider" | "doh" | "plain", "preset": "default", "custom": null, "spoofed": true, "checked_at": "…", "servers": [ { "id": "google", "name": "Google", "doh_ok": true, "ms": 38 }, { "id": "quad9", "name": "Quad9", "doh_ok": true, "ms": 41 } ], "fallback_active": false, "job": { "action": "dns_enable", "running": false, "ok": true, "message": "Готово", "at": "2026-10-17T00:30:00Z" } }` — `job` — последнее DNS-задание (`null`, если их не было); `at` — когда закончилось (пока `running: true` — нет). Установка пакета DoH занимает 10–20 с, поэтому `dns_enable`/`dns_restore`/`dns_set` фоновые, как подбор. `fallback_active`: оба DoH пропали, временно работает DNS провайдера. `preset` — включённый вариант (`dns_presets`), `custom` — последний свой вариант (как в `dns_set`, `null` — не задавался); `servers` — доступность и скорость DoH всех вариантов с одним сервером (по `dns_analyze`).

Приложение, не нашедшее метода (`4`), показывает прежнюю одну кнопку «Включить защищённый DNS».

### 5.3 Запись стратегии
- Набор ролей **не фиксирован**: он растёт (игровые профили, обновляемый ipset). Роутер принимает роли, которые знает его каталог (`strategies.json` той версии, что в пакете; `catalog_version` в `strategies`). Сейчас это `quic`, `discord_udp`, `discord_media`, `discord_tcp` (с `catalog_version` 3, роутер 0.2.0-r9: TCP 80/443 по списку `discord.txt`, стоит перед `google` и `general`, исключения как у `general`), `google`, `general`, `ipset_udp`, `ipset_tcp`. Окно не шлёт роутеру с `catalog_version` < 3 стратегию с `discord_tcp`: вариант без неё и предложение обновить пакет; `invalid` — страховка. Роль, неизвестная роутеру, — `invalid` с `field` на неё; приложение не отбрасывает роли само, а при таком ответе предлагает обновить пакет на роутере.
- Значения — как в `strategies.json`: `{fake}/<файл>.bin` (набор файлов `fake/` у роутера тот же), `0x…`, `!`. Подстановку `{fake}` роутер разворачивает сам. Файл, которого нет в его `fake/`, — `invalid`.

### 5.4 Ядро договора и совместимость
- `status.api` — «мажор.минор». Минор растёт при добавлениях без поломок (новые методы и поля), мажор — только при несовместимых изменениях.
- Приложение сравнивает с поддерживаемым: мажор другой — команды запрещены, доступны только состояние, «Обновить» и «Удалить»; минор другой — предупреждение, кнопки методов, которых нет в `status.methods`, неактивны; `min_app` новее приложения — «обновите приложение».
- **Ядро договора** — `status` (поля `product`, `api`, `version`, `methods`, `min_app`, `update`), `update_install`, `uninstall`: остаются совместимыми при любом мажоре — по ним пользователь выбирается из несовместимости. Аргументы и ответы ядра только расширяются.
- Выпуски: тег `router-vX.Y.Z`, в релизе — пакеты, `release.json` `{ schema, version, tag, api, min_app, pkg, changes, assets: [{ name, sha256 }] }` и `release.json.sig` — base64 подписи ed25519 над точными байтами `release.json` (проверочный ключ — в приложении). Тот же `release.json` без подписи — в витрине (`feed/release.json`) для заметок к обновлению. Какой выпуск под какую OpenWrt — `data/router-releases.json` (`schema 1`: `feed { url, key_url, key_sha256 }`, `releases [{ version, tag, api, min_app, pkg, openwrt { min, snapshot }, packages, release_json }]`).

### 5.5 Сценарии по SSH (когда API нет или пакета ещё нет)
Окно передаёт сценарий через stdin, на роутер его не кладёт: `ssh root@<роутер> 'sh -s -- <аргументы>' < файл`. Последняя строка ответа — JSON.
- `router/tools/dpishell-preflight.sh` — пригодность роутера: `{ schema: 1, mode: "check", openwrt { release, revision, arch, target }, pkg, fw4, nft, kernel, kmod_nft_queue { installed, available, version, matches_kernel }, net { feed, fw_feed, github }, space { overlay_free_kb, tmp_free_kb }, foreign [{ kind, name }], dpishell { version, api } | null, luci }`; `--update` — сначала обновить индексы; `--after-uninstall` — что осталось: `{ schema: 1, mode: "after-uninstall", left: [{ what, detail }], kept { settings, https_dns_proxy } }`.
- `router/tools/dpishell-install.sh` — установка: ключ витрины (встроен, sha256) → строка витрины → `apk add dpishell luci-app-dpishell` → ядро → проверка. Ход — строки `# …`, итог `{ schema: 1, ok, step, message, version, api, core }`. Архив ядра окно кладёт заранее по SFTP в `/tmp/dpishell/core/zapret.zip` — тогда сеть для ядра не нужна.
- **Без SSH — через веб-вход** (логин и пароль, как в браузере; эталон — `router/tools/web-install.py`). Только штатные права LuCI для `root`: `session.login` → `file.write /etc/apk/keys/dpishell.pem` (группа `luci-mod-system-repokeys`) → `file.read`/`file.write /etc/apk/repositories.d/customfeeds.list` и `file.exec /usr/libexec/package-manager-call update | install dpishell luci-app-dpishell` (`luci-app-package-manager`) → вход заново и ожидание объекта `dpishell` → архив ядра — `cgi-upload` в `/tmp/dpishell-core.zip` (право записи — в ACL пакета; `core_install` берёт его, если sha256 совпал) → `dpishell.core_install`. Ограничения: rpcd прерывает `file.exec` через 30 с (код ubus 7), а команда идёт дальше — `install` при занятой базе apk повторять, обрыв ответа на `install` (postinst перезапускает rpcd) значит «ставится»; роутеру нужен свой доступ к GitHub для пакетов (туннель через ПК — только SSH). Через веб же можно включить SSH (`uci dropbear`, группа `luci-mod-system-ssh`), если его выключили.
- `router/dpishell/files/usr/libexec/dpishell/uninstall.sh` — удаление без API: `--keep` | `--full`, итог — `/tmp/dpishell-uninstall.json`.
- **Роутер без доступа к GitHub** — через ПК: `ssh -R <порт>:127.0.0.1:<порт>` к локальному HTTP-прокси окна и `https_proxy=http://127.0.0.1:<порт>` в команде. apk шлёт запросы в абсолютной форме (`GET https://…`, TLS к серверу делает прокси), curl — `CONNECT`; прокси должен уметь оба. Подлинность не страдает: apk проверяет подпись индекса и хеши, участок роутер—ПК идёт внутри SSH. Проверено в эмуляторе с закрытым GitHub.

## 6. Что приложение делает с этим (для Windows-стороны)

- **Настройки → «Роутер»**: адрес (по умолчанию «Автоматически — основной шлюз»), пароль, кнопка «Подключиться», строка состояния («Подключено, DpiShell 0.1.0» / «DpiShell на роутере не найден» / «Неверный пароль»).
- **Главный экран**, если роутер найден и оптимизация на нём включён: блок «Оптимизацию делает роутер — стратегия N, проверено в 14:00». Кнопки: Включить/Выключить на роутере, Проверить, Подобрать на роутере, выбор стратегии. **Оптимизация на ПК и оптимизация на роутере одновременно не работают**: пакеты, изменённые оптимизацией ПК, роутер изменяет второй раз — стратегии ломаются непредсказуемо, а подбор на ПК находит стратегии, работающие только «в паре» с роутером.
  - Пока `status.enabled == true`, «Включить» на ПК не включает оптимизацию на ПК, а предлагает: «Оптимизация уже работает на роутере» и кнопки «Подобрать на роутере» / «Выключить на роутере и включить на этом ПК».
  - Подбор на ПК при `enabled == true` не стартует: «Выключить оптимизацию на роутере на время подбора» (`disable`, после подбора — вопрос «Включить на роутере обратно?» и `enable`) или «Подобрать на роутере».
  - Это решение по факту «включён», а не по тому, открываются ли сайты: сломанная стратегия на роутере всё равно обрабатывает пакеты.
  - Оптимизация на ПК уже включена, а роутер сообщает `enabled == true` (включили со страницы роутера или с другого ПК) — приложение выключает оптимизацию на ПК и сообщает «Оптимизация перешёл на роутер: на этом ПК выключен» (и когда состояние ПК пришло позже ответа роутера — служба ПК поднялась с Windows). Окно помнит, что оптимизация «живёт» на роутере (последний ответ — «включён»; адрес и MAC роутера по ARP — `WindowSettings.RouterBypass`, «выключен» — забывает). При старте окна роутер не отвечает (обновление, перезагрузка), а это тот же роутер (адрес и MAC совпали) — оптимизация ПК выключается («…роутер сейчас не отвечает»), в режиме без службы не включается сам; MAC другой или не узнать (чужая сеть) — всё как было. «Включить» на ПК при неотвечающем роутере — выбор человека: память о роутере стирается.
- **Аварийный выключатель**: «Включить», «Применить стратегию», «Применить на роутере» и «Включить снова» шлют `confirm_s: 180` (только если в `methods` есть `confirm`; старый роутер — как раньше). Затем окно само делает «Проверить сейчас» с ПК (обязательные цели): открылись — `confirm`; нет или проверить нельзя — плашка «Всё работает? [Да, оставить] [Вернуть как было] — вернётся само через 2:45» (отсчёт по `left_s`; «Вернуть» — `disable` или `strategy_set` на `revert_to`, затем `confirm`). Срок вышел — один `status`, без опроса. `last_off`/`watchdog_off`/`button_off`/`confirm_reverted` — фраза на главной и на вкладке, «Подробнее» с `last_off.targets`, «Включить снова». Сторож — галочка в «Проверять сам» (`schedule_set { watchdog }`) и строка из `status.watchdog`.
- **Подбор на роутере**: тот же диалог, что для ПК (группы, режим, глубина), таблица из `select_progress`, «Применить на роутере».
- **Стратегия с ПК → на роутер**: найденную глубоким поиском на ПК стратегию можно отправить на роутер (`strategies_user_set` + `strategy_set`). Путь ПК → провайдер идёт через роутер, поэтому стратегия, найденная на ПК при выключенном оптимизации на роутере, обычно подходит и роутеру; после отправки — `check_now`.
- **Свои сайты и списки роутера** — отдельная вкладка «На роутере» в тех же экранах, с ПК не синхронизируются автоматически (кнопка «Скопировать с ПК»).
- **DNS роутера**: на вкладке «Роутер» — варианты из `dns_presets` плюс свои варианты пользователя (те же, что для ПК; уходят как `custom`: с шаблоном — адреса как `bootstrap`, без — как `plain`), «Вернуть как было» — `dns_restore`. Старый пакет без `dns_presets` — прежняя одна кнопка.
- **Диагностика**: раздел «Роутер» — `diag`, кнопки «Остановить» у конфликтов `kind: service`, «Исправить» для `flow_offload` (`flow_offload_fix`) и `ipv6` (`ipv6_set`), «Сохранить отчёт роутера». Под «Что мешает» — карточка «Безопасность роутера» (`security_check`, если он есть в `status.methods`): ✓/⚠/•, вывод и варианты решения текстом, без кнопок.
- **Изменения DpiShell на роутере** (`changes_list`, если он есть в `status.methods`): карточка на вкладке «Роутер» под «Безопасностью роутера» — тот же список, что на странице («Диагностика»): «Отменить» у пункта или подпись, почему нельзя; «Отменить всё»; итог по пунктам, как в «Настройках» → «Изменения DpiShell». Пока идёт отмена (DNS, межсетевой экран), роутер может не отвечать — окно ждёт итог `changes_list.job`.
- **Вернуть версию** (`status.rollback`, `update_rollback`): ссылка «Вернуть версию X» в карточке «Подключение»; вопрос перед откатом. `saved: true` — роутер ставит пакеты из флеша; `false` — окно скачивает выпуск прежней версии (подпись и sha256, как при обновлении через ПК), кладёт по SSH и зовёт `from: local`; в выпуске нет версии старше установленной — «вернуть нельзя».
- **Временные метки TCP** (`needs_tcp_timestamps: true`): приложение включает метки на этом ПК само (команда помощника `tcp_timestamps_on`), как перед своим подбором, и пишет одной строкой «Включены временные метки TCP — нужны стратегии роутера». Выключать обратно при уходе из сети не нужно — метки ничему не мешают.
- **Совместная работа с ПК** (карточка «Совместная работа с роутером» на вкладке «Роутер», выключена по умолчанию): `pc_link_set { id, macs, domains }` — `id` постоянный GUID ПК (у помощника), `macs` — MAC адаптера, через который ПК ходит к роутеру (берётся каждый раз: Windows может менять MAC Wi-Fi по сетям), `domains` — **имена приманок ПК первыми** (SNI из файлов фейков его стратегии, `sni=`/`host=` из параметров, встроенные фейки; стенд 2026-10-20) и его сайты (свои сайты, строки продвинутого режима ПК), без адресов роутера: их окно берёт из `lists_get google|discord` и из `ignored`. Продление — не реже раза в 30 мин (договор: не реже раза в час), сразу при смене сайтов и MAC; `pc_link_get` раз в минуту — `active`. Не продлилось, `active: false`, `status.enabled` стал `false`, роутер пропал — ПК сразу по полной своей настройке (`pc_link_del`, если роутер отвечает). Выключение, «Удалить службу оптимизации» и «Отменить всё» — `pc_link_del`. Старый пакет без `pc_link_*` в `status.methods` — «Роутер не умеет совместной работы», переключатель не включается.
- Сеть сменилась (ноутбук ушёл из дома) — роутер не найден, блок пропадает, приложение работает как обычно.

## 9. История договора

API 1 (до первого выпуска роутерного пакета правки шли без увеличения номера):
- Подбор сам включает лучшую (`applied`, `backups`, `cancelled` вместо `restore_at`), `started_by`, `depth`, `eta_s`, `title` у строк; `apply` — выбор другой стратегии из итога; `schedule.hours` с `0.5`, по умолчанию `1`; `schedule.auto_select`, `started_by: timer`, предупреждения `auto_selected`/`auto_select_failed`.
- Истёкшая сессия — JSON-RPC `-32002`; `error.field` — путь; §5.3 — запись стратегии, набор ролей из каталога роутера; присланные стратегии роутер перепроверяет сам.
- Поиск DpiShell не только на шлюзе, но и на частных узлах пути наружу; запрет одновременной работы оптимизации на ПК и роутере; `needs_tcp_timestamps` и включение меток на ПК.
- Режим `mode` (`all`/`lists`), `mode_set`, `site_check`, `lists_get exclude`; группа `control` в подборе (поле `"control": true` в `targets.json`; стратегию бракуют только её `required`-цели, в счёт успеха не входит).
- DNS-задания фоновые (`dns_status.job`, `status.jobs.dns`); варианты DNS — `dns_presets`, `dns_set`, в `dns_status` — `preset`, `custom`, `mode: plain`, `servers[].id`.
- Глубокий поиск на роутере (`depth: deep`, `candidate`, `ok`/`total`, стратегии `r-…`); дробные доли в `rows`.
- `flow_offload_fix`, `ipv6_set`; предупреждения `flow_offload`/`ipv6`/`conflict` в `status.warnings`; `enable`/`select_start` при похожей программе — `conflict`; `kind: package` в `diag.conflicts`; поле `flowoffload` в `diag`.
- `select_start` только с группой `user` при пустых своих адресах — `invalid`/`groups`; свои сайты в `report` скрыты.

API 1.0 (первый выпуск пакета, 0.2.0): `api` строкой «мажор.минор», `methods`, `min_app`, `update`, `jobs.update`; `uninstall`, `update_install`, `update_check`; ядро договора (§5.4); сценарии по SSH (§5.5); `mode_set` — «Все сайты» / «Только из списков». `rows[].verdicts` в `select_progress`. Аварийный выключатель: `confirm`, `confirm_s` у `enable`/`strategy_set`/`apply`, `status.pending_confirm`/`last_off`/`watchdog`, `schedule.watchdog`, предупреждения `watchdog_off`/`button_off`/`confirm_reverted`. `update.job`: `step`, `started_at`, `from_version`, `target`, `log`; прерванное задание закрывается по факту.

Необязательные поля без смены `api` (старые роутеры не отдают, окно обходится без них): `strategies.items[].last`/`roles` (0.2.0-r7); `select_progress.rows[].groups_ok`/`groups_total` (0.2.0-r8); подбор после сторожа — `started_by: watchdog`, `status.watchdog.select`, предупреждение `watchdog_select_failed`, сторож молчит при `pending_confirm` (0.2.0-r8); `status.packages`, `status.core.installed_version` (0.2.0-r8); роль `discord_tcp` и `catalog_version` 3, `parts`, смешанная в подборе роутера (0.2.0-r9); продвинутый режим — `advanced_get`, `advanced_set`, `status.advanced`, группы `adv-<номер>` в подборе (0.2.0-r9); совместная работа — `pc_link_set`, `pc_link_del`, `pc_link_get`, `status.pc_links`, в `lists_get` — встроенные `google`, `discord`, `general` только для чтения (0.2.0-r9).

2026-10-20 (0.2.0-r10, согласовано с окном ПК; `api` остаётся 1.0):
- **Тексты от роутера — ключом словаря.** Рядом с готовым русским `text` (остаётся всегда — для старых окон) приходят `key` и `params`: `key` — ключ общего словаря окна ПК и страницы (`router.*`, `select.*`, …; своё страницы — `web.*`), `params` — сырые значения: время (`time`, `*_at`) — unix-секунды, числа — числами, имена — как есть, вложенная фраза — `{ key, params, text }`. Окно и страница берут `t(key, params)`, если ключ знают, иначе `text`. Где: `status.warnings[]`, `error` (частые тексты; технические — только `text`), `select_progress.message_msg` (рядом с `message`).
- `select_start.ids` — проверить только эти стратегии (до 5, «Проверить только её» на ПК): без автоприменения, после проверки — прежняя стратегия и прежнее вкл/выкл, запасные не трогаются; `total` = число `ids`, `best` — проверенная, если открыла всё. В `select_progress` — `ids` и `groups` (группы прогона).
- Быстрый подбор начинает с включённой стратегии, затем — открывших всё при последней проверке, затем по статистике (как на ПК: «до первой рабочей, начиная с прежних»).
- Глубокий поиск ограничен: перебор приёмов — до 13 мин, всего — до 15 (предупреждение-итог `web.msg.time_limit`). На странице глубина больше не выбирается до запуска: кнопка «Искать глубже (до 15 мин)» после результата, как на ПК (`depth: deep` в `select_start` — как было).
- `advanced_revert` — своим настройкам для сайтов состояние до последнего `advanced_set` (одна ступень; нечего — `{ nothing: true }`).
- `dns_compare` — время ответа защищённого DNS каждого варианта (`items[]: { id, ms|null }`), «Сравнить скорость».
- `diag.ipv6` — оптимизация для IPv6 включена (`ipv6_set`): «IPv6 у провайдера» не мешает.
