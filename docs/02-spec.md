# ТЗ: оболочка обхода DPI для Windows (рабочее имя — DpiShell)

Версия 0.1, 2026-10-16. Основание — `01-audit.md`. Имена опций winws сверить с `winws --help` закреплённой версии перед реализацией: часть взята из чужих скриптов.

## 1. Цель и пользователь

**Главный принцип интерфейса** (пользователь, 2026-10-16): максимально просто, без необходимости знать правильный порядок действий. Программа сама ведёт к результату: «Включить» без стратегии — берёт лучшую по прошлым подборам или подбирает и включает; мешает другой обход — кнопка «Остановить», а не инструкция; подбор, дошедший до конца, сам включает лучшую. Новые функции проверять этим принципом: если человеку нужно что-то сделать «сначала», программа делает это сама или предлагает одной кнопкой.

- Пользователь: обычный человек на Windows 10/11 x64, без консоли. Хочет: нажать «Включить» — YouTube, Discord и свои сайты работают; при смене провайдера/сети — нажать «Подобрать».
- Что делает приложение: ставит ядро обхода (winws + WinDivert), подбирает рабочую стратегию по проверяемым адресам, применяет её на всю систему (служба Windows с автозапуском), следит за состоянием в трее.
- Что не делает: VPN, не меняет DNS/hosts, не собирает телеметрию.

## 2. Основа и зависимости

### 2.1 Ядро
- `winws.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll` из релиза `bol-van/zapret` (каталог `windows-x86_64/` в `zapret-vX.Y.zip`).
- Закрепление: в приложении зашит манифест `core.json`: `{ "version": "v72.13", "zip_url": "...", "zip_sha256": "...", "files": { "winws.exe": "<sha256>", ... } }`. Хеши четырёх файлов берутся из `sha256sum.txt` релиза при подготовке манифеста (вручную, с проверкой подписи GitHub-релиза глазами), а не на машине пользователя.
- Поставка: бинарники ядра **включены в релиз приложения** (MIT, см. открытый вопрос 2). Отдельная команда «Обновить ядро» качает zip по манифесту из нашего репозитория, проверяет SHA-256 zip и каждого файла, кладёт во временную папку, меняет атомарно, при ошибке откатывает. Никаких «последний релиз с GitHub» без манифеста.
- Размещение: `%ProgramData%\DpiShell\core\` (служба должна читать без профиля пользователя), права на запись — только администраторам.

### 2.2 Данные
- `strategies.json` — каталог стратегий (см. 4.2). Свой формат, в нашем репозитории.
- `lists/` — `general.txt`, `google.txt`, `exclude.txt`, `ipset-all.txt`, `ipset-exclude.txt` (посев из Flowseal `lists/`, MIT) + пользовательские `user-general.txt`, `user-exclude.txt`.
- `fake/` — `tls_clienthello_*.bin`, `quic_initial_*.bin`, `discord_udp.bin`, `game_udp.bin`, `stun.bin` (посев из Flowseal `bin/`, MIT).
- `targets.json` — цели проверки по группам (см. 4.1).
- Обновление данных: манифест `data.json` (версия, URL каждого файла, sha256) в нашем репозитории; пользовательские файлы не перезаписываются.

### 2.3 Лицензии в составе
В «О программе» и в папке `licenses/`: zapret (MIT), Flowseal (MIT), WinDivert (LGPLv3), cygwin (LGPLv3) с ссылками на исходники.

## 3. Функции

### 3.1 Главный экран
- Состояние: «Выключено / Работает (стратегия N, служба) / Подбор… / Ошибка (текст)».
- Выбор стратегии — отдельно от выключателя: выпадающий список (готовые и найденные, порядок и доля удачных подборов — по статистике); смена при включённом обходе перезапускает службу, при выключенном — только запоминается.
- Кнопки: Включить/Выключить (одна), Подобрать стратегию, Проверить сейчас.
- Текущая сеть (имя SSID/NLM-профиль) и какая стратегия к ней привязана.

### 3.2 Запуск/остановка
- «Включить» = установить службу с выбранной стратегией и запустить:
  `sc create DpiShell binPath= "\"C:\ProgramData\DpiShell\core\winws.exe\" <args>" DisplayName= "DpiShell DPI bypass" start= auto`, затем `sc start DpiShell`. Перед установкой — `winws.exe <args> --dry-run` (код 0 = аргументы корректны).
- «Выключить» = `sc stop DpiShell`; служба остаётся с `start= demand`, чтобы повторное включение было быстрым. «Удалить полностью» (в настройках) = `sc delete DpiShell`, `sc stop WinDivert`, `sc delete WinDivert`.
- Режим «процесс» (только для подбора и «Проверить сейчас»): `Process.Start(winws.exe, args)`, остановка — `kill` дерева процесса. Перед запуском процесса служба останавливается, после — восстанавливается.
- Перед любым стартом: проверка хешей файлов ядра; если не совпали — «Файлы ядра изменены или удалены (антивирус?)», предложение восстановить из пакета приложения.

### 3.3 Автоподбор
- Кнопка «Подобрать». Диалог: что проверять (группы: YouTube, Discord, Свои адреса; чекбоксы), режим (Быстрый: первая рабочая / Полный: все стратегии с рейтингом), глубина (Основные ~20 / Глубокий ~60).
- Ход: прогресс по стратегиям, таблица «стратегия — % целей — время», можно остановить. По завершении — рекомендация и кнопка «Применить» (устанавливает службу). Результат сохраняется в `results/<дата>.json` и привязывается к текущей сети.
- При запуске из трея по расписанию не выполняется (только вручную; open question 7).

### 3.4 Свои адреса для проверки
- Поле «Свои адреса» (один на строку): домен или URL. Домен → `https://домен/`. Для каждого адреса можно отметить «важный» (обязателен для успеха).
- Добавленные домены автоматически попадают в `user-general.txt` (hostlist), с возможностью снять галочку.
- Группы по умолчанию редактируемы; «Сбросить к стандартным».

### 3.5 Списки доменов и ipset
- Экран «Списки»: просмотр/правка `user-general.txt`, `user-exclude.txt`; стандартные — только просмотр и «обновить».
- Режим применения: «По спискам» (по умолчанию) / «Все сайты» (без hostlist — как Flowseal `ipset any`; предупреждение о возможных поломках).
- Game filter: переключатель «Игры (порты 1024–65535 TCP/UDP)», требует перезапуска службы.

### 3.6 Обновления
- Проверка раз в день при запуске: `data.json` и `core.json` из нашего репозитория (raw GitHub, с таймаутом 5 с). Показ «Доступно обновление списков/ядра/приложения», установка по кнопке. Приложение само себя не обновляет в v1 — ссылка на релиз.
- **Как сделано (2026-10-17, решение 23):** окно раз в день тихо качает `data.json` с источников из `data/update-sources.json` (по очереди, 5 с на адрес; без сети — «последняя попытка <дата>»), сравнивает версию с данными помощника и показывает «Доступно обновление списков» (плашка на главной, карточка «Обновления» в «Диагностике»). Кнопка — команда помощника `data_update {confirmed}`: помощник сам заново берёт манифест со своих источников, качает каждый изменившийся файл и сверяет sha256, собирает новую папку `%ProgramData%\DpiShell\data` рядом, проверяет её целиком (каталог, цели, `core.json`, hosts-кандидаты, валидатор IP-списка с вопросом при изменении > 40 %) и только потом подменяет. Ядро — файлом `core.json` в том же манифесте: изменился — ставится по нему до замены данных. Данные читаются из обновлённой папки, если она новее поставки и цела, иначе — из поставки. `app_version` в манифесте — ссылка «Скачать новую версию», `min_app_version` — данные не ставятся старой программой.

### 3.7 Диагностика
- Экран «Диагностика»: состояние служб `DpiShell`, `WinDivert`; найденные конфликтующие службы (`zapret`, `winws1`, `winws2`, `GoodbyeDPI`, `discordfix_zapret`, `WinDivert14`) и чужие процессы `winws.exe`/`goodbyedpi.exe`; предложение остановить и удалить их с подтверждением; детект VPN-адаптера; проверка DNS (системный vs DoH); кнопка «Сохранить отчёт» (логи winws с `--debug`, версии, хеши).

### 3.8 Трей и автозапуск
- Иконка в трее: состояние цветом, меню Включить/Выключить/Подобрать/Открыть/Выход. Закрытие окна — сворачивание в трей.
- Автозапуск GUI при входе: ~~задача планировщика с наивысшими правами (`schtasks /create /rl highest /sc onlogon`)~~ ключ `HKCU\…\Run` без прав, окно — свёрнутым в трей (`DpiShell.exe --tray`), см. решение 22. Служба стартует сама независимо от GUI.

## 4. Алгоритм подбора

### 4.1 Цели проверки (`targets.json`)
```json
{ "groups": [
  { "id": "youtube", "title": "YouTube", "targets": [
      { "url": "https://www.youtube.com/", "min_bytes": 20480, "tls": ["1.3","1.2"], "required": true },
      { "url": "https://i.ytimg.com/vi/<id>/maxresdefault.jpg", "min_bytes": 20480, "required": true },
      { "url": "https://rr1---sn-<...>.googlevideo.com/...", "kind": "googlevideo_redirect", "required": true },
      { "url": "https://www.youtube.com/", "kind": "quic", "required": false } ] },
  { "id": "discord", "title": "Discord", "targets": [
      { "url": "https://discord.com/", "min_bytes": 20480, "required": true },
      { "url": "https://gateway.discord.gg/", "required": true },
      { "url": "https://cdn.discordapp.com/...", "min_bytes": 20480, "required": true } ] },
  { "id": "user", "title": "Свои адреса", "targets": [] } ] }
```
Цель googlevideo: как у Flowseal `targets.txt` — запрос к redirector, который отвечает редиректом на реальный `*.googlevideo.com`, затем запрос туда (точные URL — при реализации).

### 4.2 Каталог стратегий (`strategies.json`)
```json
{ "engine": "winws", "version": 3,
  "common": { "wf_tcp": "80,443,2053,2083,2087,2096,8443", "wf_udp": "443,19294-19344,50000-50100" },
  "profiles_fixed": [
    "--filter-udp=443 --hostlist=@{lists}/general.txt --dpi-desync=fake --dpi-desync-repeats=6 --dpi-desync-fake-quic=@{fake}/quic_initial_www_google_com.bin",
    "--filter-udp=19294-19344,50000-50100 --filter-l7=discord,stun --dpi-desync=fake --dpi-desync-fake-discord=@{fake}/discord_udp.bin --dpi-desync-fake-stun=@{fake}/discord_udp.bin --dpi-desync-repeats=6" ],
  "strategies": [
    { "id": "ms-seqovl-568", "tier": 1, "title": "multisplit + seqovl (общая)",
      "tcp": "--dpi-desync=multisplit --dpi-desync-split-seqovl=568 --dpi-desync-split-pos=1 --dpi-desync-split-seqovl-pattern=@{fake}/tls_clienthello_4pda_to.bin" },
    { "id": "fake-autottl-badseq", "tier": 1, "title": "fake, autottl, badseq",
      "tcp": "--dpi-desync=fake,multisplit --dpi-desync-split-pos=1 --dpi-desync-autottl=2 --dpi-desync-fooling=badseq --dpi-desync-fake-tls=@{fake}/tls_clienthello_www_google_com.bin" },
    { "id": "fakedsplit-md5", "tier": 2, "generated_from": "blockcheck",
      "tcp": "--dpi-desync=fakedsplit --dpi-desync-split-pos=1 --dpi-desync-fooling=md5sig" } ] }
```
- Полная командная строка собирается: `--wf-tcp=... --wf-udp=... <profiles_fixed через --new> --new --filter-tcp=80,443 --hostlist=@{lists}/general.txt --hostlist=@{lists}/user-general.txt --hostlist-exclude=@{lists}/exclude.txt --hostlist-exclude=@{lists}/user-exclude.txt --ipset-exclude=@{lists}/ipset-exclude.txt <strategy.tcp> --new --filter-tcp=443 --hostlist=@{lists}/google.txt <strategy.tcp> --new --filter-tcp=80,443,8443 --ipset=@{lists}/ipset-all.txt <strategy.tcp>` + при game filter профили на `--filter-tcp=1024-65535`/`--filter-udp=1024-65535` с `--dpi-desync-any-protocol=1 --dpi-desync-cutoff=n3`.
- Tier 1 (~20) — посев из Flowseal `general*.bat` (десинк-части TCP-профилей). Tier 2 (~40) — генерация по порядку blockcheck: `{multisplit, multidisorder} × split-pos {1, 2, midsld, sniext+1}`, `fake × fooling {badseq, badsum, md5sig, datanoack} × {autottl=2, ttl=3..6}`, `fakedsplit/fakeddisorder × fooling`, `seqovl {568, 681}`. Tier 2 только в «Глубоком» режиме.
- Поле `engine` в каталоге и адаптер `IEngine { BuildArgs(strategy, lists, mode) }` — задел под `winws2` (другой синтаксис `--lua-desync`), не реализуется в v1.

### 4.3 Проверка одной цели
1. Разрешить имя системным DNS; параллельно DoH (`https://cloudflare-dns.com/dns-query`); если множества IP не пересекаются — пометка «DNS подменён» (цель всё равно проверяется по системному DNS; предупреждение в отчёте).
2. HTTPS GET с заданной версией TLS (по умолчанию проверяем TLS 1.3 и 1.2 отдельно), таймаут подключения 3 с, чтения 6 с, без автоследования редиректов.
3. Успех, если: соединение и рукопожатие прошли; статус не 400; если редирект — `Location` на тот же базовый домен; тело прочитано полностью: `received >= Content-Length` (при известной длине) и `received >= min_bytes` (при заданном). Чтение до 1 МБ, дальше считаем успехом.
4. `kind: quic` — HTTP/3-запрос (`HttpVersion.Version30`, `RequestVersionExact`); если платформа не поддерживает HTTP/3 — цель помечается «не проверялась», не влияет на итог.
5. Две попытки с паузой 500 мс; цель «OK», если хотя бы одна успешна; время — лучшее.

### 4.4 Оценка стратегии
- Группа «прошла», если все `required` цели OK. Стратегия: `score = (прошедшие группы / выбранные группы)`, затем доля всех целей, затем среднее время.
- Быстрый режим: остановка на первой стратегии с score = 1. Полный: все стратегии tier 1 (и tier 2 при «Глубоком»), таблица по score.
- Перед подбором: прогон целей **без обхода** — цели, доступные и так, не учитываются (как blockcheck); если доступны все — сообщение «Блокировки не обнаружено или включён VPN», подбор не нужен.
- Повторные проверки («Проверить сейчас»): одна неудача не меняет стратегию (noirlie); две подряд с интервалом — предложение «Подобрать заново».

### 4.5 Выполнение: последовательно (обязательно) и параллельно (эксперимент)
- Последовательно: остановить службу → для каждой стратегии: запустить процесс winws с полной командной строкой, подождать готовности (процесс жив 1 с и `--debug` не выдал ошибку) → проверить цели (параллельно, до 8 запросов) → убить процесс → пауза 300 мс. Ожидание: 5–7 с на стратегию.
- Параллельно (слоты, до 4): для слота k — `--wf-raw=@slot_k.txt`, где фильтр = базовый фильтр (однократно получить через `winws <базовые --wf-*> --wf-save=base.txt --dry-run`) с добавкой `and ((outbound and tcp.SrcPort >= P_k and tcp.SrcPort <= P_k+99) or (inbound and tcp.DstPort >= P_k and tcp.DstPort <= P_k+99))` и аналогично для udp; HTTP-клиент слота привязывает сокет к порту из своего диапазона (`SocketsHttpHandler.ConnectCallback` с `Bind`). Критерий успеха spike: два слота с разными стратегиями дают разные результаты на заведомо «ломающей» и «рабочей» стратегиях, в `--debug`-логах нет чужих пакетов. При провале spike — только последовательный режим.

### 4.6 Память по сетям
- Ключ сети: GUID NLM-профиля (+ SSID для Wi-Fi). Хранится `{network: strategy_id, checked_at, score}`. При смене сети: если есть запись — применить её и запустить «Проверить сейчас»; нет — предложить подбор. Опция вместо своей логики — `--ssid-filter`/`--nlm-filter` winws; в v1 не используем, управляем из приложения.

### 4.7 Глубокий поиск (генерация стратегий)

Когда готовые не помогли или пользователь хочет лучше. Как blockcheck, но по ролям и с нашим критерием успеха.

1. **Раздельно по ролям**: `google` (цели YouTube) и `general` (Discord и свои адреса); у остальных ролей (QUIC, UDP Discord) — профиль из лучшей готовой стратегии. Пока ищем одну роль, вторая берёт профиль из лучшей готовой (или не задаётся).
2. **Грубый проход** (по одной «важной» цели на группу, одна версия TLS, одна попытка): семейства `multisplit`, `multidisorder`, `fake`, `fake,multisplit`, `fakedsplit`, `fakeddisorder`, `hostfakesplit`, `multisplit + seqovl` с типовыми значениями (split-pos=1 / 2 / midsld / sniext+1, fooling=ts / md5sig / badseq, repeats=6, fake-tls = google / `!`). ~20 кандидатов на роль.
3. **Уточнение** вокруг сработавших (до 3 лучших семейств): варианты split-pos, fooling, autottl/ttl, repeats 2/6/11, фейк (все `fake/*.bin` + `!`), `fake-tls-mod`. Поиск жадный, «первое улучшение»: меняем по одному параметру; нашли соседа лучше — сразу продолжаем от него (обход слоями тратил бюджет на первый слой и не находил улучшений в два шага; 2026-10-17, так же на роутере — 06 §4.5). Потолок — 30 кандидатов уточнения на роль, общий на все семейства.
4. **Финал**: 3 лучших кандидата на роль собираются в стратегии и проходят полную проверку (§4.3–4.4) вместе с готовыми; итоговая таблица общая. Найденное сохраняется в `user-strategies.json` (свой каталог пользователя, та же проверка `Validate`).
5. Предпочтение при равном результате — меньше пакетов (меньше repeats, без fake), затем время.
6. Скорость ограничиваем: пауза между кандидатами ≥ 300 мс, стоп при 3 подряд полных таймаутах всех целей (признак, что провайдер начал резать по IP) с сообщением «провайдер, похоже, временно ограничил соединения — продолжить позже».
7. Генератор не выходит за белый список параметров `WinwsArgs`.

## 5. Архитектура

```
DpiShell.Core (net8.0, без UI)
  Engine/      IEngine, WinwsEngine (сборка аргументов, dry-run, запуск процесса, --wf-save)
  Service/     ServiceManager (sc create/start/stop/delete, запрос состояния, чужие службы)
  Catalog/     StrategyCatalog, Lists, Targets (чтение JSON, подстановка {lists}/{fake})
  Probe/       HttpProbe (TLS1.2/1.3, тело, редирект), QuicProbe, DnsCheck, VpnDetect
  Selector/    SequentialRunner, ParallelRunner (слоты), Scorer, ResultStore
  Update/      Manifest, Downloader (SHA-256, атомарная замена, откат), Integrity (хеши ядра)
  Network/     NetworkIdentity (NLM/SSID), NetworkChangeWatcher
  Diagnostics/ ConflictFinder, ReportBuilder, Log
DpiShell.App  (net8.0-windows, WPF): главный экран, подбор, списки, диагностика, трей
DpiShell.Cli  (консоль): `dpishell test --strategy id`, `dpishell select --quick` — для отладки и автотестов
```
- Все действия с правами — в одном процессе с `requireAdministrator`; отдельной службы-обёртки нет: служба — сам winws.
- Файлы: `%ProgramData%\DpiShell\{core,lists,fake,strategies.json,targets.json,state.json,results\,logs\}`.
- Логи: приложение — `logs\app.log` (ротация 5×1 МБ); winws при подборе — `--debug` в `logs\winws-<strategy>.log`.

## 7. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Хеши ядра не совпали / файл удалён | Блокировать запуск, сообщение про антивирус, кнопка «Восстановить», ссылка на инструкцию по исключению папки |
| `sc query WinDivert` = STOP_PENDING | Диагностика: найти чужие службы/процессы, предложить остановить; совет про античиты; после — `sc stop WinDivert`, повтор |
| Чужой `winws.exe` или GoodbyeDPI запущен | Подбор не стартует; предложение остановить с подтверждением |
| `--dry-run` ≠ 0 | Стратегия помечается «ошибка аргументов», лог в отчёт, подбор продолжается |
| winws упал во время работы службы | Служба `start= auto` + `sc failure DpiShell reset= 60 actions= restart/5000`; трей показывает «перезапущено» |
| VPN активен | Предупреждение «VPN активен, обход не нужен»; подбор не запускается без подтверждения |
| Нет интернета вовсе (ping 1.1.1.1 и DoH не отвечают) | «Нет сети», подбор не запускается |
| DNS подменён | Пометка в результатах; совет включить DoH в браузере (в v1 DNS не меняем) |
| Secure Boot/подпись драйвера: WinDivertOpen не удаётся | Текст из документации zapret (secure boot / testsigning), ссылка |
| Рядом вторая `cygwin1.dll` (пользователь скопировал) | Проверка папки ядра на лишние файлы при старте |
| Смена сети во время подбора | Подбор прерывается, результат помечается недействительным |
| Нет прав администратора (запуск из-под ограниченной учётки без UAC-повышения) | Сообщение и выход |
| Антивирус блокирует сетевые запросы проверки | Таймауты трактуются как «нет ответа», не как блокировка DPI, если без обхода тоже таймаут везде |

## 9. Решения (2026-10-16)

Пользователь доверил сетевые решения разработке; условие — проверять всё взятое из открытых источников (раздел 11).

1. Стек — C#/.NET (берём .NET 10 LTS: он установлен и поддерживается дольше 8-го).
2. Ядро не кладём в свой релиз: качаем с GitHub bol-van на первом запуске по манифесту с закреплёнными хешами.
3. Только последовательный подбор; параллельный — позже, отдельным экспериментом.
4. Группы по умолчанию — YouTube и Discord; остальное — «Свои адреса».
5. UDP Discord — фиксированным профилем без автопроверки; game filter и режим «Все сайты» — во вторую версию.
6. Перепроверка — ~~по кнопке и при смене сети, без таймера~~ заменено п. 15.
7. VPN — только предупреждение.
8. Без подписи exe, без установщика: portable-zip.
9. Данные — `%ProgramData%\DpiShell`. Имя — DpiShell (рабочее).
10. Резерв ядра: форк `Slavdew/zapret` с копией релиза v72.13 (хеш тот же) — запасной адрес в `core.json` (`mirror_urls`), используется только если основной не ответил или отдал не тот файл; локальная копия — `vendor/`. Ориентир — основной репозиторий bol-van.

11. DNS (по живой проверке 2026-10-16): провайдер подменяет ответы обычного DNS даже к 8.8.8.8 (`www.youtube.com` → «имени нет»), DoH отдаёт настоящие адреса. Браузеры ходят в DoH сами, поэтому сайт в браузере работает, а проверки по системному DNS (и Flowseal, и наши) врут. Отсюда:
    - проба резолвит цели сама через DoH (dns.google / cloudflare-dns.com, по IP) и подключается к полученному адресу — оценка стратегий не зависит от DNS системы;
    - отдельно сравнивается системный DNS с DoH; расхождение — предупреждение «DNS провайдера подменяет адреса: приложения вне браузера (Discord и др.) не будут работать» и кнопка «Включить защищённый DNS» (Windows 11: DoH для текущих серверов или 8.8.8.8/8.8.4.4, без возврата к обычному тексту; запоминаем прежние настройки и умеем вернуть). Это отменяет «DNS не трогаем» из раздела 1 — с согласия пользователя по кнопке.
12. **Анализ DNS** — отдельная функция на экране «Диагностика» (кнопка «Подобрать DNS»), см. §10.

13. **Параллельный подбор** (§4.5) — только опцией «Быстрый подбор» с предупреждением о риске временной блокировки провайдером, по умолчанию выключен, до 4 слотов.
14. **Глубокий поиск** — генерация новых стратегий (§4.7). Живая проверка 2026-10-16 (DNS исправлен): без обхода закрыто всё; YouTube+Discord — alt9, alt13; только YouTube — alt, alt11, alt12, simple-fake; только Discord — alt4. Вывод: роли нужно подбирать раздельно и собирать из лучших.
15. ~~**Запасные стратегии с автопереключением**~~ **Отменено пользователем 2026-10-16** для ПК: редкая проверка — пользователь заметит раньше, частая — лишний трафик. На ПК фоновых проверок нет; запасные остаются порядком для быстрого подбора. Автопроверка с переключением и (по вопросу 7 в 07-router-api §8) автоподбором — только на роутере, по желанию. Было: (вместо «динамической» подмены на каждый запрос: смена стратегии = перезапуск winws = обрыв всех соединений, а против обновления правил провайдера случайная смена не помогает). После подбора хранится рейтинг рабочих стратегий (до 3). Приложение в трее раз в 30 мин и при смене сети проверяет обязательные цели (лёгкая проверка, одна версия TLS); две неудачи подряд — переключение на следующую из рейтинга с уведомлением; кончились — предложение подобрать заново. Без открытого окна, только иконка в трее.
16. **Порядок проверки по статистике**: стратегии идут в порядке средней доли пройденных групп за последние 10 подборов (свежие весят больше), новые — между проверенно рабочими и нерабочими. На выбор лучшей не влияет, только ускоряет быстрый подбор. Под перебои провайдера отдельно не подстраиваемся.
17. **Автоприменение**: подбор/поиск, дошедший до конца, сам ставит лучшую стратегию в службу (полный — лучшая, быстрый — первая, открывшая всё); остановленный «Стопом» — нет. Подбор при включённом обходе — с предупреждением о перебоях (служба приостанавливается, стратегии меняются).
18. **Служба по её настройкам в Windows**: стратегия и файл службы читаются из реестра (ImagePath), не из памяти программы; чужой файл в службе DpiShell — предупреждение. Состояние служб — по кодам RUNNING/STOPPED (подписи `sc` переводятся на язык Windows).
19. **Чужие обходы**: Flowseal (по раскладке папок), другой zapret, GoodbyeDPI — с их стратегией (сравнение командной строки winws с каталогом) и подсказкой, как выключить; включение и подбор блокируются, пока они работают.
20. **Окно**: одна копия (повторный запуск показывает работающую); крестик — по настройке «Сворачивать в трей» (по умолчанию) / «Закрывать программу»; тема как в Windows / светлая / тёмная.
21. **Права на папку данных**: `%ProgramData%\DpiShell` — только SYSTEM и Администраторы (наследование от ProgramData отключено, по SID). По умолчанию там читали и писали все пользователи: свои адреса были видны всем, а `winws.exe` можно было подменить — служба запускает его от имени системы после перезагрузки без нашей проверки хешей. Свои адреса в истории — «свой адрес №N»; `user-general.txt` остаётся текстом (его читает winws), защищён правами папки. Шифровать state.json смысла нет: тот же список лежит в user-general.txt.
22. **Автозапуск окна** (2026-10-17): окно без прав (11-helper-spec), поэтому не задача планировщика с наивысшими правами, а значение `DpiShell` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` = `"<путь>\DpiShell.exe" --tray` (окно не показывается, только значок в трее). Галочка «Запускать вместе с Windows (в трее)» в настройках, выбор — в `%LocalAppData%\DpiShell\window.json` (`autostart`). Пока не выбирали: **в режиме без службы — включено** (обход живёт, пока открыта программа, без автозапуска после входа он не поднимется), **в режиме службы — выключено** (служба стартует сама, окно по желанию); ключ трогаем, только когда режим известен (помощник ответил). Портативную папку могут перенести — путь в ключе поправляется при каждом запуске.
23. **Источники обновлений данных** (2026-10-17): список адресов папки `data/` нашего репозитория в `data/update-sources.json`, по очереди: сейчас только `raw.githubusercontent.com/Slavdew/dpishell/master/data/` (его блокируют по IP — зеркало Codeberg/GitLab/Cloudflare добавится одной строкой, owner-questions №2). На адрес — 5 с до ответа. Манифест доверенный, только если пришёл с адреса из списка; каждый файл — только при совпадении sha256 с манифестом, иначе отбрасывается и берётся следующий источник. Список источников едет с программой и обновлением данных **не меняется**: зеркало не может назначить себя или другие адреса. Ключи манифеста — только `имя` в корне `data\` или `lists|fake|hosts|licenses/имя`; `data.json`, `update-sources.json`, `user-*` — никогда (свои файлы пользователя обновлением не перезаписываются). **Подписи у манифеста пока нет:** кто подменит наш репозиторий или зеркало, сможет выдать свои данные (стратегии — только из белого списка параметров winws, IP-список — через валидатор, hosts — белый список доменов и живая проверка сертификата). Поэтому новый `core.json` из обновления принимается, только если архив — из релизов `github.com/bol-van/zapret` и без `mirror_urls`: подменивший наш репозиторий может выбрать лишь настоящий релиз zapret, а не свой exe (форк-зеркало ядра — только в `core.json` поставки). Подпись манифеста (ключ в программе) — следующий шаг.

## 10. Анализ и выбор DNS

### Что проверяем
Кандидаты: текущий DNS системы, DNS роутера/провайдера (из DHCP), Google (8.8.8.8), Cloudflare (1.1.1.1), Quad9 (9.9.9.9), AdGuard (94.140.14.14, с фильтром рекламы — отдельно помечен). Яндекс DNS в список рекомендуемых не входит: российские резолверы обязаны применять реестр блокировок.

Для каждого — по контрольным доменам (YouTube, Discord, свои адреса пользователя + нейтральные `example.com`, `wikipedia.org` как эталон «всё работает»):
1. **Обычный DNS (UDP 53)**: ответ совпадает с эталоном (консенсус двух DoH-серверов по пересечению адресов/подсетей, CDN отдают разные IP — сравниваем по /16 и владельцу), подмена (NXDOMAIN, адрес-заглушка, `0.0.0.0`/`127.0.0.1`), таймаут.
2. **DoH (443)**: доступен ли вообще (сам `dns.google` бывает под DPI — тогда с обходом и без), время ответа (медиана из 5).
3. **Внутренние имена**: резолвит ли текущий DNS что-то, чего нет в публичном DNS — суффиксы поиска DNS из настроек адаптера, домен Active Directory (`USERDNSDOMAIN`), имена из локальной сети (`*.local`, `*.lan`, `*.home.arpa`, имя роутера). Такие имена — признак, что смена DNS их сломает.

### Итог для пользователя
Таблица «DNS — подменяет ли — работает ли шифрование — скорость» и одна рекомендация («Включить шифрование для 8.8.8.8 и 8.8.4.4») с кнопкой «Применить» и «Вернуть как было». Пользователь видит последствия **до** применения, коротким списком:

| Последствие | Когда | Что делаем |
|---|---|---|
| Перестанут открываться внутренние адреса (корпоративная сеть, домен AD, ресурсы офиса) | Найдены внутренние имена или ПК в домене | Предупреждение крупно; правила NRPT (`Add-DnsClientNrptRule`): внутренние суффиксы остаются на прежнем DNS |
| Перестанут находиться устройства домашней сети по имени (роутер, принтер, NAS) | Роутер отвечает на локальные имена | Те же правила NRPT для `.lan`/`.local`/`.home.arpa` и имени роутера |
| Корпоративный VPN | VPN-адаптер со своим DNS | DoH включаем только на физическом адаптере; адаптеры VPN не трогаем |
| Пропадёт фильтрация провайдера/роутера (родительский контроль, блок рекламы на роутере) | DNS роутера отличается от провайдера | Сообщение «фильтрация роутера перестанет действовать» |
| Сайты могут грузиться чуть медленнее (CDN выбирает сервер по местоположению DNS, кэши провайдера не используются) | Всегда | Строка в пояснении; показываем замер скорости |
| Нет интернета через гостиничный/общественный Wi-Fi до входа на страницу авторизации | Ноутбук | Совет «Вернуть как было» на время входа; при обрыве DoH Windows без возврата к обычному тексту DNS не ответит вовсе |
| Если DoH-сервер станет недоступен — DNS перестанет работать целиком | Возврат к обычному тексту выключен | Два сервера разных компаний (Google + Cloudflare); проверка доступности перед применением; «Вернуть как было» доступно из трея |

### Реализация
- Windows 11: `Set-DnsClientServerAddress` + `Add-DnsClientDohServerAddress` (известные шаблоны уже есть в системе для 8.8.8.8/1.1.1.1/9.9.9.9) + флаг DoH на адаптере; Windows 10 без встроенного DoH — только рекомендация, без кнопки.
- Прежние настройки (серверы, DoH, NRPT) сохраняются в `state.json` до изменения; «Вернуть как было» восстанавливает дословно.
- Проверки подбора стратегий (§4.3) резолвят цели сами через DoH и не зависят от того, применён ли этот пункт.

## 11. Проверка заимствованного

- Ядро: только релиз `bol-van/zapret`, хеш zip и каждого файла сверяются с `sha256sum.txt` релиза и зашиваются в манифест; файлы не из списка (`winws.exe`, `WinDivert.dll`, `WinDivert64.sys`, `cygwin1.dll`) не извлекаются.
- Стратегии Flowseal: `.bat` не исполняем и в репозиторий не кладём — из них вручную выписываются только аргументы winws, каждый аргумент сверяется с `winws --help`; аргументы, запускающие внешние программы или указывающие на файлы вне наших `lists/`/`fake/`, отбрасываются.
- Списки: только строки-домены/подсети, проверка регулярным выражением при загрузке; всё прочее отбрасывается.
- Фейки `.bin`: проверяем, что это то, чем назван файл (TLS ClientHello / QUIC Initial / STUN), и размер в разумных пределах.
- Код чужих проектов не копируем; NuGet-пакеты — только широко известные, с закреплённой версией.
