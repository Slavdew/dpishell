# Передача Windows-сессии DpiShell (2026-10-17)

Для новой сессии: прочитать этот файл, затем `docs/STATUS.md` (точка остановки) — и продолжать. Отвечать пользователю по-русски, коротко, без технических подробностей там, где можно.

## Что за проект
DpiShell — простая оболочка над zapret (winws от bol-van) для обхода DPI: Windows-приложение (C# .NET 10, WPF) + пакет для роутера OpenWRT. Репозиторий `C:\Dev\zapret-automation`, опубликован: github.com/Slavdew/dpishell (remote origin, почта в коммитах — noreply).

Пользователь в сетях не разбирается и **доверил сетевые и архитектурные решения нам**: решаем сами и записываем в ТЗ (02-spec §9, 09 «Решения»). Главный принцип интерфейса — **просто, без правильного порядка действий, программа сама ведёт** (02-spec §1). Всё заимствованное — только после проверки (03-vetting). Fable — бережно, только для больших аудитов.

## Что готово (закоммичено, 449+ тестов зелёные до последней переделки)
- Ядро: установка ядра по хешам (+ зеркало-форк `Slavdew/zapret`, копия в `vendor/`), каталог 20 стратегий Flowseal (проверены, белый список параметров), проверка сайтов (TLS 1.2/1.3, тело целиком, DoH-резолв), подбор (быстрый/полный, порядок по статистике, автоприменение лучшей), глубокий поиск (генерация по ролям), служба/процесс (Job Object), обнаружение Flowseal и др. со стратегией, временные метки TCP, папка данных только SYSTEM+админы, свои адреса скрыты в истории.
- v2: IP-списки (список Flowseal по хешу + валидатор, режимы, «все адреса» 10 мин), игровой режим, «Починить адреса» (hosts: свой блок, TLS-проверка, откат), кэш Discord, диагностика.
- Окно WPF: тёмная/светлая тема как в Windows, список стратегий, режим службы галочкой, роутер (подключение, подбор на роутере, отправка стратегий, адреса, диагностика), кнопки «(i)», одна копия, трей.
- Помощник (служба `DpiShellHelper`): протокол с белым списком команд, канал с проверкой клиента по токену, клиент `HelperClient`, установка `HelperEntry`.
- Роутерный клиент `Core/Router/*` по договору + `FakeRouter` в тестах.
- Консоль `dpishell-cli` для отладки (`live\`), публикация окна — `publish\DpiShell-N\`.

## Дальше
1. Доделать окно без прав → `dotnet build` 0/0, `dotnet test` зелёный → закоммитить **своими путями** (`git add <пути>`, не `-A`).
2. Живая проверка: пользователь перезапустит VS Code от администратора (иначе UAC мне запрещён классификатором). План: установить помощника, включить `alt9`, проверить сайты, подбор, режим без службы и закрытие окна, «Починить адреса» — только предпросмотр. Потом вернуть как было (удалить помощника и службу, Flowseal запустить обратно). Flowseal у пользователя стоит службой `zapret` — на время проверки останавливать (кнопка «Остановить» в окне).
3. Затем: автозапуск окна при входе, portable-архив с лицензиями, обновления данных (`raw.githubusercontent.com` блокируют по IP — нужно зеркало вне GitHub; вопрос пользователю открыт: Codeberg/GitLab/Cloudflare).
4. Вывести в окно новое из договора роутера: режим «Все сайты / По спискам», «Сайт не открывается» (site_check), DNS роутера, автоподбор по расписанию, метки TCP по `needs_tcp_timestamps`, запрет одновременного обхода ПК и роутера (07 §6).

## Как работать
- Сессия роутера — `ai-1c` (SendMessage), договор согласуем напрямую. Её файлы: `router/`, `docs/04–07`; наши: `src/`, `tests/`, `data/`, `docs/02, 03, 08–11`, `live/`, `publish/`.
- Агенты: окно и крупные куски — агентам (обычная модель), снимки окна (`DPISHELL_SNAPSHOTS`) смотреть самим; агенты не коммитят, не запускают приложение/winws/sc/UAC.
- **Код с обратным слешем — только Edit/Write**, не python/bash-heredoc (ломалось 6 раз).
- Подписи `sc`/`netsh` переводятся на язык Windows — искать по непереводимому (RUNNING, RFC 1323, enabled).
- Без прав `%ProgramData%\DpiShell` не прочитать — результаты подборов через пользователя или помощника.
- Каталог стратегий: `^!` из .bat = `!` в winws (ловили дважды).
