# Локализация окна — памятка

Строки интерфейса — в JSON «ключ → текст». Русский — источник правды, английский — второй встроенный язык. Загрузчик и `L` — `src/DpiShell.Core/Localization/` (строки ядра тоже идут через `L`), в окне — `{l:T}`, выбор языка, флаги — `src/DpiShell.App/Localization/`.

## Где лежит
- `src/DpiShell.Core/Lang/ru/<область>.json` и `Lang/en/<область>.json` — ресурсы сборки DpiShell.Core, при загрузке файлы языка сливаются.
- Области: `common` (общие кнопки, меню слева, выбор языка), `home`, `select`, `sites`, `apps`, `hosts`, `dns`, `proxy`, `diag`, `router`, `settings`, `about`, `shell` (трей, диалоги, тосты, запросы помощника, строка состояния), `core` (тексты из DpiShell.Core: ошибки, итоги, причины; ключи `core.<файл>.<что>`), `export` (выгрузка и загрузка настроек: разделы, причины пропуска записей, журнал), `info` (тексты «(i)»), `web` (временная: ключи страницы роутера из `router/luci-app-dpishell/lang-src/web.json` — предупреждения роутера, автоимена стратегий, названия DNS-вариантов; после слияния ветки router-work заменяется встроенным ресурсом того файла).
- В Core: `using DpiShell.Core.Localization;` и `L.T(...)`. Помощник (служба) собран из того же Core, но языка окна не знает — его тексты пока русские (L по умолчанию ru).
- Каждая вкладка — в своём файле: параллельная работа без конфликтов. Набор файлов в ru и en одинаковый.

## Ключи
- `<область>.<что>[.<уточнение>]`: латиница, нижний регистр, слова через `_`, уровни через точку — `home.strategy`, `router.watchdog.off_reason`.
- Ключ начинается с имени своей области (`sites.*` — только в `sites.json`). Повтор ключа в двух файлах — ошибка (тест).
- Ключи с `_` в начале не читаются (`_meta`, комментарии).

## Как вызывать
- XAML: `xmlns:l="clr-namespace:DpiShell.App"` в корне файла, затем `Text="{l:T home.title}"`. Работает в `Text`, `Content`, `Header`, `ToolTip`, `AutomationProperties.Name`, `Run.Text`, в `Setter Value` стилей и в шаблонах. Это привязка — при смене языка текст меняется сам.
- Код: `L.T("home.title")`, с подстановками `L.T("home.strategy", new { name })` (анонимный объект или словарь).
- Вычисляемые свойства моделей (`StatusTitle => L.T(...)`) обновляются сами: при смене языка все модели (`Observable`) поднимают `PropertyChanged("")`.
- **Состояние показываем из данных, а не из готовой строки.** Модель хранит данные (состояние, числа, имена, ответ помощника или роутера) или правило сборки строки (`LiveText`: `XxxIs(() => L.T(...))`) и собирает текст при показе. Если готовую строку всё же держат в поле, модель переопределяет `OnLanguageChanged()` и пересобирает её из своих данных (статус главной, итог и строки «Проверить сейчас», DNS, диагностика, роутер, hosts, прокси, игры, откат всего). Примеры: `MainViewModel.OnLanguageChanged`, `RouterViewModel.OnLanguageChanged`.
- **Сообщения последних действий** (`Message`, тосты, `ResultText`, ошибка последней операции) можно оставить как есть: при смене языка модель прогоняет их через `L.Relocalize(text, own: true)` (`Retranslate(ref поле)` / `LiveText.Retranslate()`) — знакомая фраза переводится по шаблону ключа, чужой текст остаётся.
- **Готовые фразы ядра и помощника.** Помощник (служба) и ядро в нём собирают тексты по-русски, журнал и история проверок хранят текст как записан. Окно показывает их через `L.Relocalize(text)`: фраза узнаётся по шаблонам ключей всех встроенных языков (длинный шаблон точнее короткого) и собирается заново на языке окна; ответы помощника проходят через неё сразу при получении (`HelperClient`). Поэтому русский текст ключа ядра должен совпадать с тем, что ядро показывает (тест `RelocalizeTests`). Названия, которые хранятся в файлах (автоимена стратегий, смешанные), остаются русскими, а на языке окна их показывает `StrategyNaming.DisplayTitle` по тем же шаблонам, что у страницы роутера (`web.strat.*`).
- Даты и время — `L.Date(d)`, `L.Time(d)`, `L.DayMonth(d)`, `L.LongDate(d)`; культура выбранного языка — `L.Culture`.
- (i): `InfoButton Topic="{x:Static local:InfoTexts.Home}"` → `info.home` (текст) и `info.home.title` (заголовок).

## Подстановки и формы числа
- Подстановки именованные: `"home.strategy": "Стратегия: {name}"`. Имена по-английски, по смыслу. В ru и en набор одинаковый (тест).
- Фразу целиком, без склеек из кусочков: порядок слов в другом языке другой.
- Числа: значение — объект форм, число — `{n}`:
  - ru: `{ "one": "{n} сайт", "few": "{n} сайта", "many": "{n} сайтов", "other": "{n} сайта" }`
  - en: `{ "one": "{n} site", "other": "{n} sites" }`
  - Код: `L.Plural("sites.count", count)` или `L.Plural("sites.count", count, new { name })`.

## Что не выносить
Логи, тексты исключений для разработчика (разбор release.json, JSON-RPC и т. п.), имена стратегий каталога, сайтов и программ, названия и описание службы Windows (то, что видно в services.msc), консольный `DpiShell.Cli`, технические коды и адреса. Сообщения, присланные роутером, переводятся: по `key` (если новый роутер прислал и ключ известен), иначе по `warnings[].code` (`RouterTexts.WarningText`); неизвестный код — текст роутера как есть.

## Тон
Программа — инструмент: без первого лица («Проверяю…» → «Проверка…»), без рода («нашла» → «найдено»), без фамильярности; «обычно», где не у всех так. Английский — так же коротко, американское написание, sentence case, названия элементов в “…”.

## Тексты (i)
Источник правды — `src/DpiShell.Core/Lang/ru/info.json`; `docs/info-texts.md` — копия для чтения, тест окна сверяет её дословно. Правка текста (i) — в обоих местах и в `en/info.json`.

## Пользовательский перевод
Один файл `<код>.json` в папке `lang` рядом с программой или в `%AppData%\DpiShell\lang`:
```json
{ "_meta": { "language": "Deutsch", "code": "de", "author": "", "version": "0.9.6", "flag": "de" },
  "common.ready": "Fertig." }
```
- Цепочка: выбранный язык → en → ru → сам ключ (пустой строки в окне не бывает).
- Строка не берётся, если подстановки не как в ru, вид другой (строка/формы), нет нужных форм числа или длиннее 2000 знаков. Битый файл или код встроенного языка — файл пропускается; причина — в «Диагностике» и в логе.
- `flag` — код страны ISO 3166; без своего рисунка (FlagIcon) — плашка с кодом.
- Шаблон: «Настройки» → «Для опытных» → «Выгрузить шаблон перевода» (значения — английский текст, рядом `_ru.<ключ>` — русский).

## Проверки
`dotnet test --filter "FullyQualifiedName~Localization|FullyQualifiedName~LangWindow"`:
каждый ключ из кода (литералы `"<область>.…"` внутри вызова `L.T(`/`L.Plural(`, включая тернарные `L.T(ok ? "a.x" : "a.y")`) и разметки (`{l:T …}`) есть в ru и en; нет ключей ru, которые нигде не упомянуты литералом (ключ, вынесенный в константу или словарь, всё равно пишется литералом где-то в Core/App — тогда он считается упомянутым; собранный из частей — только `info.<тема>.title`); ключи ru и en совпадают; подстановки и формы числа совпадают; ключ начинается с области своего файла. Снимки окна на английском — `DPISHELL_SNAPSHOTS=<папка> dotnet test --filter FullyQualifiedName~WindowSmokeTests` при `L.Set("en")` (см. LangWindowTests).

**Кириллица в английском окне** (`CyrillicScan` в языковых тестах `Lang*`): в видимом тексте (TextBlock, TextBox, кнопки, заголовки, подсказки, карточки «(i)») на английском нет русских букв, кроме белого списка — имена из данных (названия, которые ввёл человек, названия языков, текст роутера с неизвестным кодом). В русском окне тот же осмотр идёт после переключения на английский на лету: всё, что собрано на прежнем языке и не пересобралось, видно сразу. Данные для проверки — заполненные состояния (`LangPopulatedTests`: история проверок, автоимена, чужие программы, VPN, DNS; `LangRouterWindowTests`: предупреждения роутера по старому и новому формату). `DPISHELL_CYR_LOG=<файл>` — не падать, а дописывать находки в файл.
Тесты, которые меняют язык, — в коллекции `lang` (не параллельно с остальными) и возвращают русский в `Dispose` (`L.ResetForTests()`).
