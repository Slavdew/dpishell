# ТЗ v2: IP-списки, игровой режим, hosts, диагностика (2026-10-17)

Основание — `08-features-audit.md`. Принцип §1 `02-spec.md`: пользователь ничего не должен делать «сначала» — программа делает сама или предлагает одной кнопкой. Проверка заимствованного — по §11 `02-spec.md`. Термины «ipset», «hostlist», «any-protocol» в интерфейсе не показываются.

## 0. Общее

- Все новые функции **выключены по умолчанию**; включение — переключателем на своём экране, с «(i)» (тексты — `10-info-texts.md`).
- Любое изменение, затрагивающее службу, применяется само: приложение перезапускает службу и показывает «Применяю… / Готово». Не просить «перезапустите стратегию».
- Состояние каждой функции — в `state.json`; командная строка winws собирается `Strategies.Build(strategy, options)` из тех же данных, что показаны на экране (§9.18: истина — ImagePath службы).
- Данные новых функций — файлы в `%ProgramData%\DpiShell\lists\` и `hosts\`, обновление через `data.json` (§2.2) с sha256 каждого файла.

## 1. Игровой режим

**Функция.** Переключатель «Игры» с вариантами: Выкл (по умолчанию) / TCP и UDP / только TCP / только UDP. Порты — `1024-65535` для обоих протоколов, поле «Порты» — в «Дополнительно» (по умолчанию скрыто), синтаксис как у Flowseal `1024-1934,1936-65535`, проверка: числа 1–65535, начало ≤ конец, не пересекать базовые порты (`WfTcp`, `WfUdp`).

**Интерфейс.** Экран «Игровой режим»: переключатель, строка состояния «Работает по N адресам из IP-списка (обновлён <дата>)» или «Выключен», подсказка «Если игра или программа после включения стала работать хуже — выключите». При включении, если IP-список не загружен (режим «Выкл» в §2), приложение само переводит IP-списки в «По списку» и говорит об этом одной строкой; если списка нет на диске — скачивает по манифесту, показывает прогресс.

**Данные/сборка.** В каталоге — роли `game_tcp`, `game_udp` (`RoleOrder` после `ipset_tcp`):
- `--wf-tcp=<WfTcp>,<game_tcp_ports>`, `--wf-udp=<WfUdp>,<game_udp_ports>` — только для включённых протоколов;
- `game_tcp`: `--filter-tcp=<ports> --ipset=@lists/ipset-all.txt --ipset=@lists/user-ipset.txt --ipset-exclude=@lists/ipset-exclude.txt --ipset-exclude=@lists/user-ipset-exclude.txt <десинк роли general выбранной стратегии> --dpi-desync-any-protocol=1 --dpi-desync-cutoff=n3`;
- `game_udp`: тот же фильтр по UDP + `--dpi-desync=fake --dpi-desync-repeats=12 --dpi-desync-any-protocol=1 --dpi-desync-fake-unknown-udp=@fake/game_udp.bin --dpi-desync-cutoff=n2` (посев `general.bat:25`; вариант `repeats=10` из ALT4 — второй кандидат).
- Если в десинке `general` есть `--dpi-desync-fooling=badseq` — для `game_tcp` добавить `--dpi-desync-badseq-increment=0x80000000` (`readme.md:349`); имя опции сверить с `winws --help` закреплённой версии.
- `Validate` каталога: роли `game_*` допускают только `--dpi-desync-any-protocol`, `--dpi-desync-cutoff`, `--dpi-desync-fake-unknown-udp` сверх белого списка.

**Проверка.** Автоматически проверить нельзя (нет универсальной цели). Делаем: `--dry-run` перед установкой; после включения — «Проверить сейчас» по обычным целям, чтобы убедиться, что сайты не сломались; если доля пройденных целей упала относительно последней проверки без игрового режима — предупреждение «С игровым режимом сайты стали работать хуже — выключить?» с кнопкой.

**Ошибки/крайние случаи.** Подбор стратегий идёт **без** игрового режима (роли `game_*` не участвуют в оценке), применяется к найденной стратегии после. Игровой режим при режиме IP-списков «Все адреса» запрещён (это `any` на всех портах — приманки во всё): переключатель серый с пояснением. Высокая нагрузка CPU winws (> 50 % ядра 30 с) — уведомление «Игровой режим нагружает процессор (торренты?) — выключить?». Диапазон портов пользователя, захватывающий 53/123/500/4500 — предупреждение.

## 2. IP-списки

**Функция.** Экран «IP-списки». Режим: «Выкл» (по умолчанию, файл-заглушка `203.0.113.113/32`), «По списку» (загруженный `ipset-all.txt` + `user-ipset.txt`), «Все адреса — на 10 минут» (пустой include-лист; таймер; по истечении — возврат к прежнему режиму и уведомление; кнопка «Оставить» нет — только повторный запуск). Переключение режимов не меняет каталог: `Build` подставляет нужный файл (`ipset-all.txt` / `ipset-none.txt` / `ipset-any.txt` пустой) — без переименований, как у Flowseal.

**Интерфейс.** Строка состояния «N подсетей, обновлён <дата>, покрывает X % адресов интернета», кнопка «Обновить», «Свои подсети» (поле, одна на строку, тот же валидатор), «Исключить подсети». В «Дополнительно» — «Показать список» (только просмотр).

**Данные.** `ipset-all.txt` — из нашего `data.json` (источник при подготовке версии: `Flowseal/.service/ipset-service.txt` = `V3nilla/IPSets-For-Bypass-in-Russia`, ревизия PR глазами: какие AS добавлены, нет ли `/0–/7`). В манифесте: `url`, `sha256`, `lines`, `ipv4_share`, `updated`. Хранится `ipset-all.txt`, `ipset-all.prev.txt`, `ipset-all.meta.json` (дата, версия, счётчики). winws перечитывает файл сам (`readme.md:284`) — перезапуск службы при обновлении не нужен; при смене режима — нужен (меняется путь).

**Проверка безопасности (по §11).** Один валидатор `IpsetValidator`, применяется и при подготовке версии (CI), и на машине при загрузке/ручной правке:
1. Строка: `#…` и пустые — пропуск; иначе строго `IPv4/len` (len 0–32) или `IPv6/len` (0–128), разбор `IPAddress.TryParse`, host-биты обнуляются с пометкой «исправлено».
2. Запрещено: len < 8 (IPv4) / < 19 (IPv6); пересечение с `ipset-exclude.txt` (приватные, loopback, link-local, multicast, CGNAT, `0.0.0.0/8`, `::1`, `fc00::/7`, `fe80::/10`) и с `240.0.0.0/4`, `ff00::/8`; нарушение — строка отбрасывается, счётчик.
3. Список целиком: 1 000 ≤ строк ≤ 100 000; размер 50 КБ ≤ файл ≤ 4 МБ; доля IPv4 ≤ 15 % (порог — вопрос 2); дубликаты убираются; отброшено > 1 % строк — «список повреждён, оставлен прошлый».
4. Отличие от прошлой версии > 40 % строк (симметрическая разность / старый размер) — на машине список принимается только после подтверждения «Список сильно изменился (+N/−M). Применить?»; при подготовке версии — ручная проверка обязательна.
5. Пользовательские файлы — те же правила 1–2, лимит 10 000 строк, запрет len < 16 (IPv4) без подтверждения («подсеть из 65 536 адресов — точно?»).
6. Загрузка только по HTTPS, в temp, атомарная замена после проверки хеша из манифеста; хеш не совпал — не применять, сообщение.

**Ошибки/крайние случаи.** Нет сети при обновлении — тихо, «последняя попытка <дата>». Файл удалён/изменён антивирусом (хеш не совпал с `meta`) — восстановить из `prev`/пакета, уведомление. Режим «Все адреса» при закрытии приложения — служба продолжит с `any`: при выходе спросить «Вернуть обычный режим?»; при старте приложения с истёкшим таймером — вернуть. Список содержит `1.1.1.0/24`, `8.8.8.0/24` (Cloudflare/Google AS): наши DoH-пробы идут к этим адресам на 443 и попадают под профиль `ipset_tcp` — поэтому DoH-разрешение в подборе всегда проверять и с заглушкой; при обнаружении, что DoH не работает с обходом, пробовать второй DoH и отметить в отчёте.

## 3. hosts («Починить адреса»)

**Функция.** Экран «hosts». Выключено по умолчанию. Кнопка «Проверить адреса» → таблица кандидатов → кнопка «Записать N адресов» → «Вернуть как было». Назначение — только два случая: загрузки с GitHub и Telegram Web (плюс Discord-запуск, пока запись актуальна).

**Интерфейс.**
- Таблица: Домен | Адрес | Владелец (RDAP) | Проверка (✓ сертификат действителен / ✗ не отвечает / ✗ чужой сертификат) | Сейчас (как отвечает через DNS: ✓/✗). Записываются **только** строки «✓ сертификат» и «DNS ✗ или медленнее» — т. е. когда наша запись реально что-то чинит; остальные показаны серым «не нужно».
- Перед первой записью — окно: «Будет изменён системный файл hosts: добавлен блок DpiShell из N строк, другие строки не трогаем. Копия сохранена. Защитник Windows может показать предупреждение `HostsFileHijack` — это реакция на любую правку hosts; выберите в нём «Разрешить». Продолжить?».
- После записи: «Записано N, проверка раз в день; устаревшие убираются сами».
- «Вернуть как было» — всегда доступна (и из трея), удаляет только наш блок; если есть `.bak` и пользователь просит — восстановление файла целиком с предпросмотром различий.

**Данные.** `hosts/hosts-candidates.json` из нашего `data.json` (sha256): `[{ "host": "raw.githubusercontent.com", "ips": ["146.75.22.132", "2606:50c0:8000::154"], "owner_any_of": ["FASTLY", "GITHU"], "reason": "github-ip-block", "since": "2026-08-30", "source": "flowseal#17088" }]`. Источник при подготовке версии — `.service/hosts` Flowseal и их PR; в манифест попадают только домены из **белого списка**: `github.com`, `*.githubusercontent.com`, `telegram.org`, `*.telegram.org`, `t.me`, `telegram.me`, `telegram.dog`, `telegram.space`, `tg.dev`, `*.tg.dev`, `telesco.pe`, `*.telesco.pe`, `discord.com`, `updates.discord.com`. Домен вне списка — манифест не проходит `Validate`. Никогда: `youtube.com`, `googlevideo.com`, банки, `*.microsoft.com`, `*.windowsupdate.com`, антивирусы.

**Проверка безопасности (по §11), на машине при каждой записи и раз в день:**
1. Домен из белого списка; IP разбирается; IP не приватный/не loopback/не `0.0.0.0`.
2. RDAP (`https://rdap.org/ip/<ip>`, таймаут 5 с): `name`/`handle` объекта сети содержит одно из `owner_any_of`. RDAP недоступен — проверка «не выполнена», запись допускается только если п. 3 прошёл (RDAP — вторичный признак).
3. **Живая проверка**: TCP 443 к IP, TLS с SNI = домен, сертификат проходит обычную проверку цепочки и имени (`SslStream`, без отключения валидации), HTTP `HEAD /` отвечает любым кодом < 500 за 5 с. Это доказывает, что узел по этому IP законно обслуживает домен. Не прошла — запись не ставится; стояла — снимается с уведомлением «Адрес для X устарел, убран».
4. Сравнение с DNS: тот же тест к адресам из DoH. Если DNS-адрес работает не хуже — запись «не нужна», не ставим (hosts должен чинить, а не дублировать).
5. Запись: читать файл, найти блок `# DpiShell begin v<N> <дата>` … `# DpiShell end`, заменить/добавить только его, остальное побайтно сохранить (кодировка/переводы строк файла как были); перед записью `hosts` → `%ProgramData%\DpiShell\hosts\hosts.<yyyyMMdd-HHmmss>.bak` (хранить 10 последних); запись во временный файл рядом и `File.Replace`; атрибут «только чтение» снять и вернуть; `ipconfig /flushdns` после.
6. Чужие записи для наших доменов (например, строка `youtube.com` или `discord.com` вне нашего блока) — не трогать, показать «в hosts уже есть запись для X от другой программы — она имеет приоритет» (Windows берёт первую подходящую строку).

**Ошибки/крайние случаи.** Нет прав — запрос повышения (приложение и так с наивысшими). Файл заблокирован антивирусом/политикой — «не удалось записать, изменения не внесены» и путь к копии. Defender удалил/очистил файл — при следующей проверке блок не найден → статус «снято защитником», предложить повторить. Пользователь редактировал внутри нашего блока — при обновлении блок перезаписывается (предупредить в «(i)»). Блок DpiShell найден, а функция в `state.json` выключена (старая установка) — предложить убрать. Удаление приложения («Удалить полностью») — убирает блок.

**Почему не DoH.** DoH чинит подмену DNS; hosts здесь чинит блокировку по IP — это разные поломки (аудит §4). Обе функции независимы; на экране DNS и hosts — взаимные ссылки «если сайт всё равно не открывается…».

## 4. Диагностика — дополнения (§3.7)

Проверки из `service.bat:411-730`, как список «✓/⚠/✗ — что делать», без автоматических действий кроме помеченных кнопкой:

## Вопросы к пользователю

1. Игровой режим: варианты TCP+UDP / TCP / UDP — оставить все три или только «Вкл/Выкл» (= TCP+UDP)? Поле портов — прятать в «Дополнительно» или не давать вовсе?
2. IP-список: порог «покрывает ≤ 15 % IPv4» — согласен? (Список Flowseal — 10,3 %, с ростом будет упираться.) Альтернатива — только наш отбор AS (Cloudflare, Google, Discord/i3D, Riot, Akamai) без хостеров (Hetzner, OVH, Amazon, Azure) — заметно меньше ложных попаданий, но хуже для игр на этих хостерах.
3. «Все адреса» — 10 минут с автовозвратом достаточно? Нужен ли вариант «пока не выключу» с красной полосой в окне?
4. hosts: делать вообще? Если да — согласен с правилом «ставим только записи, которые прошли TLS-проверку и чинят то, что через DNS не работает»? Это значит, что на части провайдеров блок будет пустым.
5. Очистка кэша Discord в диагностике (закрывает Discord, удаляет `Cache`, `Code Cache`, `GPUCache`) — брать?
6. Зеркало для `data.json`/`core.json` вне GitHub (блокировка `185.199.x` по IP): где разместить — свой домен, Cloudflare Pages, GitLab? Или ограничиться встроенными данными + ручной загрузкой файла? *Механизм готов (список источников в данных, зеркало — одна строка); где — ждёт владельца (owner-questions №2).*
7. Автосписок (`--hostlist-auto`) — обсуждать для v3 или закрыть вопрос?
8. TCP timestamps: Flowseal включает их при каждом запуске (`netsh … timestamps=enabled`) — нам включать по кнопке в диагностике или тоже автоматически при «Включить»?

## Решения (2026-10-17, координатор; сетевые решения пользователь доверил разработке — 02-spec §9)

1. Игровой режим — один переключатель «Вкл/Выкл» (= TCP+UDP), порты не показываем (принцип §1 02-spec). Варианты TCP/UDP и порты — только в отладочной консоли.
2. IP-список — список Flowseal, закреплённый хешем в нашем `data.json` на каждую нашу версию, плюс валидатор из §2 (порог ≤ 15 % IPv4, запрет приватных и `/0–/7`, отличие от прошлой ≤ 40 %). Свой отбор AS — не делаем: поддерживать его некому, а игры живут и на хостерах.
3. «Все адреса» — только 10 минут с автовозвратом; варианта «пока не выключу» нет.
4. hosts — делаем, выключено по умолчанию, ровно по правилу §3: только записи, прошедшие TLS-проверку с валидным сертификатом и чинящие то, что через DNS не работает. Пустой блок на части провайдеров — нормальный исход, так и пишем пользователю («нечего чинить»).
5. Очистка кэша Discord — берём, кнопкой в Диагностике с подтверждением (закрывает Discord — предупреждаем).
6. Зеркало вне GitHub — **вопрос пользователю** (нужен его аккаунт): Codeberg / GitLab / Cloudflare Pages. До решения — встроенные данные + ручная загрузка файла.
7. `--hostlist-auto` — закрыт для v2, вернуться в v3 только при запросе пользователей.
8. TCP timestamps — автоматически, без кнопки: перед подбором и при «Включить», если выключены. Без них стратегии с `--dpi-desync-fooling=ts` (почти половина каталога) молча не работают, и подбор их отбрасывает. Прежнее значение запоминается; «Удалить службу полностью» возвращает его. В Диагностике — строка «Временные метки TCP: включены (нужны части стратегий)».
