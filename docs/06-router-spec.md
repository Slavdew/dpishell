# ТЗ: DpiShell для роутера (OpenWRT)

Версия 0.2, 2026-10-16. Основание — `05-router-audit.md`. **Источник истины — `02-spec.md`** (ТЗ Windows-версии): алгоритм подбора, критерий «сайт работает», решения §9. Здесь — только то, что на роутере иначе. Если 02-spec меняется, этот документ догоняет его (§11). Формат управления с ПК — `07-router-api.md`.

## 1. Цель и пользователь

- Пользователь тот же, что у Windows-версии: в сетях не разбирается. Хочет: обход работает на всех устройствах дома (телефоны, ТВ, приставки, ПК), управление с телефона в браузере или из приложения на ПК.
- **Главный принцип** — как 02-spec §1: программа сама ведёт к результату. «Включить» без стратегии — берёт лучшую по прошлым подборам, а если их нет — подбирает и включает; подбор, дошедший до конца, сам включает лучшую; мешает другой обход — кнопка «Остановить».
- Что делает пакет: ставит ядро (nfqws + правила nftables из zapret), подбирает стратегию с самого роутера, применяет её на всю сеть, следит за ней, при подмене DNS провайдером — по кнопке включает защищённый DNS для всей сети.
- Что не делает: VPN, правка hosts, прошивка роутера (установка сторонняя прошивка OpenWrt — по его инструкции, вне пакета).
- Платформа — роутер (модель) на сторонняя прошивка OpenWrt (OpenWRT main, `apk`, `aarch64_cortex-a73`). Пакет не привязан к модели: любой OpenWRT 25.12+ с fw4/nftables.

## 2. Основа и зависимости

### 2.1 Ядро
- **Тот же архив, что у Windows-версии**: `zapret-v72.13.zip` из релиза bol-van, `data/core.json` (`zip_url`, `mirror_urls` — форк `Slavdew/zapret`, `zip_sha256`). В архиве есть `binaries/linux-<arch>/nfqws` и OpenWRT-скрипты; `linux-arm64/nfqws` в zip побайтно тот же, что в `openwrt-embedded.tar.gz` (sha256 `75fc3d6352eb9ebf510dfa470797c5ea079c475755ae3c0a79b1e9aaaf0c37a6`, сверено 2026-10-16).
- В `core.json` добавляется раздел для роутера (Windows его игнорирует):
  ```json
  "linux": { "zip_dir": "zapret-v72.13/",
    "nfqws": { "arm64": "75fc3d63…37a6", "arm": "…", "mipsel": "…", "mips": "…", "x86_64": "…" },
    "extract": ["binaries/linux-<arch>/nfqws", "common/", "init.d/openwrt/", "ipset/", "files/fake/", "install_bin.sh", "install_easy.sh", "config.default"] }
  ```
  Хеши остальных архитектур — из архива при подготовке манифеста.
- Поставка — как 02-spec §9.2: в пакете ядра нет. При первом запуске роутер качает zip (основной адрес, затем `mirror_urls`), проверяет sha256 архива и `nfqws`, извлекает только пути из `extract` в `/opt/zapret`. Не вышло — «Загрузить файл ядра» на странице или из приложения ПК (у приложения есть копия того же zip), проверка та же.
- Установка zapret — повторением шагов `install_easy.sh` для OpenWRT без его вопросов и cron (§6). Служба `/etc/init.d/zapret` и таблица `inet zapret` — штатные zapret. Мы пишем только `/opt/zapret/config`.

### 2.2 Зависимости пакета
`curl` (TLS 1.3 через mbedtls), `unzip`, `nftables`, `kmod-nft-queue`, `kmod-nft-nat`, `ucode`, `ucode-mod-fs`, `ucode-mod-uci`, `rpcd-mod-ucode`, `luci-base`. Проверено в эмуляторе (OpenWRT 25.12.5 x86_64, 2026-10-17): все есть в официальных фидах; curl 8.22.0 / mbedTLS 3.6.7, без DoH и HTTP/3. Наличие в фиде сторонняя прошивка OpenWrt — проверить при установке.
- `https-dns-proxy` — **не зависимость**: сразу после установки он сам переключает dnsmasq на свои серверы (`noresolv=1`, `server=127.0.0.1#5053/5054`, канарейка `use-application-dns.net` — выключает DoH в Firefox) — проверено в эмуляторе. Ставится по кнопке «Включить защищённый DNS» (§3.8).

### 2.3 Данные
- Из общего репозитория без изменений: `strategies.json`, `targets.json`, `lists/*.txt`, `fake/*.bin`.
- Общий файл `options.json` — белый список параметров (сейчас в `WinwsArgs`); по нему проверяют каталог, свои стратегии и генератор глубокого поиска на обеих сторонах.
- `engine` в каталоге: `"winws"` → `"zapret1"` (один синтаксис winws/nfqws); Windows принимает оба значения на переходный период.
- Свои данные роутера в `/etc/dpishell/` (только root): `user-targets.json`, `lists/user-*.txt`, `user-strategies.json`, `stats.json`, `results/`.

## 3. Функции (страница «Службы → DpiShell» и `07-router-api.md`)

### 3.1 Главный экран
- Состояние: «Выключено / Работает (стратегия N, проверено <время>) / Подбор… (k из N) / Ошибка (текст)».
- Выбор стратегии — отдельно от выключателя (как 02-spec §3.1): список готовых и найденных, порядок и «открыла всё в N из M подборов» — по статистике. Смена при включённом обходе перезапускает zapret, при выключенном — запоминается.
- Кнопки: Включить/Выключить (одна), Подобрать, Проверить сейчас.
- Если включённая стратегия помечена «нужны метки времени»: строка «Компьютерам на Windows нужна настройка — без неё обход для них не работает» с «(i)» (команда `netsh interface tcp set global timestamps=enabled` от администратора; приложение DpiShell на ПК делает это само, 07-router-api §6).
- Предупреждения строками с кнопкой действия: flow offloading, IPv6, чужой обход («Остановить»), подмена DNS («Включить защищённый DNS»), переключение на запасную стратегию.
- Вёрстка — одна колонка карточек, читается на телефоне.

### 3.2 Включение/выключение
- «Включить» со стратегией = записать `/opt/zapret/config` (§4.2) → `/etc/init.d/zapret enable` → `restart`. Перед записью — `nfqws --dry-run <NFQWS_OPT>` (код 0).
- «Включить» без стратегии = лучшая по `stats.json`; статистики нет — быстрый подбор, затем включение.
- «Выключить» = `/etc/init.d/zapret stop` + `disable`.
- Перед любым стартом — sha256 `nfqws` против манифеста; не совпал — «Файлы ядра изменены», «Переустановить ядро».
- Что реально работает, читается из `/opt/zapret/config`, а не из памяти пакета (как 02-spec §9.18); чужое содержимое — предупреждение «config zapret изменён не нами».

### 3.3 Автоподбор
- Диалог как 02-spec §3.3: группы (YouTube, Discord, Свои адреса), режим (по умолчанию полный, быстрый — запасной), глубина (Основные / Глубокий = §4.5).
- Включённый обход — предупреждение: «На время подбора обход для всей сети переключается между стратегиями, сайты на устройствах могут открываться с перебоями».
- Ход — таблица «стратегия — % целей — время»; страницу можно закрыть, подбор идёт на роутере; «Остановить» возвращает прежнее состояние.
- **Автоприменение** (02-spec §9.17): подбор, дошедший до конца, сам включает лучшую (полный — лучшую, быстрый — первую, открывшую всё) и сохраняет до 3 рабочих в рейтинг запасных. Остановленный — ничего не меняет.
- Порядок проверки — по статистике (02-spec §9.16), `stats.json`, последние 10 подборов.
- Результат — `/etc/dpishell/results/<дата>.json`, хранить 10 последних.

### 3.4 Режим: «Все сайты, кроме исключений» или «По спискам»
Решение пользователя (2026-10-17): основной режим — **«Все сайты, кроме исключений»**, он же по умолчанию на роутере; «По спискам» — запасной.
- «Все сайты»: профили `general`/`google` без `--hostlist`, только `--hostlist-exclude` (стандартный `exclude.txt` + `user-exclude.txt`) и `--ipset-exclude` (приватные сети). Обрабатываются все соединения на портах `NFQWS_PORTS_TCP/UDP`; QUIC и Discord-профили — как в каталоге.
- «По спискам» — как сейчас: `general.txt`, `google.txt`, `user-general.txt`.
- Смена режима — перезапуск zapret с новым config, без подбора; но стратегия, подобранная в одном режиме, в другом может ломать сайты — после смены автоматически «Проверить сейчас» (полная, с контрольной группой §4.1).
- Исключения: экран «Исключения» — свой список доменов (по одному на строку, без поддоменов — `^домен`, как в zapret), стандартный — просмотр. Кнопка «Сайт не открывается с обходом» на главном экране: ввести адрес → роутер проверяет его с обходом и без; открывается только без — предлагает добавить в исключения.

### 3.4.1 Свои адреса и списки
Как 02-spec §3.4–3.5: адрес на строку, флаг «важный», домены попадают в `user-general.txt` (галочку можно снять); `user-general.txt`, `user-exclude.txt` — правка, стандартные — просмотр и «Обновить» (манифест `data.json`).

### 3.5 Проверка и запасные стратегии
Решение пользователя (2026-10-16): кнопка и таймер независимы, таймер отключаемый. На ПК фоновой проверки нет (02-spec §9.15 отменён для ПК) — автопроверка с переключением на запасные и автоподбором есть только на роутере.
- «Проверить сейчас» доступна всегда.
- «Проверять автоматически»: интервал 30 мин, 1, 3, 6, 12, 24 ч; по умолчанию включено, 1 ч. Хранится в `/etc/config/dpishell`; выключение убирает строку из cron.
- Проверка по таймеру лёгкая (как 02-spec §9.15): обязательные цели, одна версия TLS; по кнопке — полная. Не стартует во время подбора и при выключенном обходе.
- Две неудачи подряд — переключение на следующую из рейтинга запасных, предупреждение `switched_backup`; запасные кончились — «Стратегия перестала работать», кнопка «Подобрать».
- **«Подбирать автоматически»** (переключатель, по умолчанию выключен): если запасные кончились, роутер сам запускает быстрый подбор по готовым стратегиям и включает лучшую; не чаще раза в 6 ч. Нашёл — предупреждение `auto_selected`; не нашёл — `auto_select_failed`, прежняя стратегия остаётся. Во время автоподбора обход в сети переключается, как при ручном подборе (§3.3). По умолчанию выключено: подбор на ~2–3 мин даёт перебои на всех устройствах в непредсказуемый момент.
- На главном экране — время, итог и источник последней проверки (кнопка / таймер / приложение).

### 3.6 Диагностика
- Чужие обходы: службы `zapret2`, `youtubeUnblock`, `b4`, пакет `zapret-manager-beam`, процессы `nfqws`/`nfqws2` не нашего запуска. Пока работают — включение и подбор заблокированы, кнопка «Остановить» (stop + disable).
- `flow_offloading=1` в uci firewall → предупреждение и «Выключить».
- IPv6: глобальный адрес на `wan6` → «Включить обход по IPv6» (`DISABLE_IPV6=0`). У пользователя сейчас IPv6 нет.
- DNS — §3.8.
- «Сохранить отчёт»: версии, хеши, config zapret, `nft list table inet zapret`, настройки DNS, хвост `logread`.

### 3.7 Короткий адрес
`/www/dpi/index.html` — переадресация на `/cgi-bin/luci/admin/services/dpishell`. В инструкции — `http://192.168.1.1/dpi`.

### 3.8 DNS для всей сети
Причина — 02-spec §9.11: провайдер пользователя подменяет ответы обычного DNS даже к 8.8.8.8. Роутер раздаёт DNS всем устройствам, поэтому без защищённого DNS приложения на телефонах, ТВ и ПК (Discord и др.) получают подменённые адреса — обход им не помогает.
- **Анализ** («Диагностика → DNS», и автоматически перед подбором): для контрольных доменов (YouTube, Discord, свои адреса + `example.com`, `wikipedia.org`) сравнить ответ DNS провайдера (из `resolv.conf.d` WAN) с консенсусом двух DoH (`https://8.8.8.8/resolve`, `https://1.1.1.1/dns-query` в JSON-формате, сравнение по /16 и владельцу, как 02-spec §10); проверить доступность DoH и время ответа.
- **«Включить защищённый DNS»** — `apk add https-dns-proxy` в этот момент (пакет штатный OpenWRT, сам настраивает dnsmasq), затем наша проверка, что DNS отвечает: два экземпляра (Google и Cloudflare) на `127.0.0.1:5053/5054`, dnsmasq пересылает только им (`noresolv`), WAN `peerdns 0`. Прежние настройки dnsmasq/network сохраняются в `/etc/dpishell/dns-backup.json` до установки; «Вернуть как было» — `apk del https-dns-proxy`, восстановить сохранённое, **явно перезапустить dnsmasq** (после удаления пакета он сам не перезапускается и DNS роутера пропадает — проверено в эмуляторе) и убедиться, что `nslookup example.com 127.0.0.1` отвечает; нет — повторный перезапуск и предупреждение.
- Последствия, которые страница показывает **до** применения:

| Последствие | Когда | Что делаем |
|---|---|---|
| Имена устройств домашней сети (`*.lan`, имя роутера) | всегда | не страдают: их отвечает dnsmasq роутера, наружу не уходят |
| Пропадёт фильтрация провайдера (родительский контроль у провайдера) | всегда | строка в пояснении |
| Сайты чуть медленнее (CDN выбирает сервер по DNS) | всегда | замер времени ответа в анализе |
| Оба DoH-сервера недоступны — в сети нет DNS совсем | редко | перед применением — проверка доступности; таймер проверки (§3.5) проверяет и DNS; две неудачи подряд — временный возврат к DNS провайдера и предупреждение |
| Устройства с жёстко прописанным DNS (часть ТВ/приставок с 8.8.8.8) | бывает | обходят роутер; перехват порта 53 — во второй версии |

- Браузеры с собственным DoH не затрагиваются.

## 4. Подбор на роутере (отличия от 02-spec §4)

### 4.1 Цели
- **Контрольная группа «Обычные сайты»** (`id: control`) — обязательна в режиме «Все сайты» и при проверке после смены режима: адреса, которые у провайдера пользователя открываются без обхода (российские банки, Госуслуги, маркетплейсы, `ya.ru`, `wikipedia.org`, `example.com`; состав — в общем `targets.json`, Windows-сторона). Проверяются без обхода (что недоступно и без него — выбрасывается) и с каждой стратегией; стратегия, сломавшая хоть одну контрольную цель, получает `score = 0` с причиной «ломает обычные сайты: …». Эти же адреса — первые кандидаты в «Исключения», если ломаются со всеми стратегиями.
- `targets.json` общий. `handshake_only` — соединение и ответ с любым кодом, кроме 400, тело не читается. Группа «Свои адреса» — своя на роутере; с ПК — кнопкой «Скопировать с ПК» (07-router-api §6).

### 4.2 Сборка конфигурации zapret из стратегии
- `NFQWS_PORTS_TCP=80,443,2053,2083,2087,2096,8443`, `NFQWS_PORTS_UDP=443,19294-19344,50000-50100` (те же, что `--wf-*` в `WinwsArgs`).
- `NFQWS_OPT` = профили ролей в порядке ролей каталога через `--new`. **Набор ролей не зашивать в код**: роли и их фильтры (порты, списки, `--filter-l7`) читаются из данных, общих с Windows; набор будет расти (игровые профили, обновляемый ipset — аудит Windows-стороны). Пока фильтры ролей зашиты в Windows-сборщике (`WinwsArgs`) — роутер повторяет их один в один; когда переедут в данные, берёт оттуда. `{lists}` → `/etc/dpishell/lists` и `/usr/share/dpishell/lists`, `{fake}` → `/usr/share/dpishell/fake`.
- `MODE_FILTER=none`, `FLOWOFFLOAD=none`, `DISABLE_IPV6` по §3.6, `NFQWS_*_PKT_*` — по умолчанию `config.default`.
- Каждый токен — по `options.json` и шаблону значения (как `WinwsArgs.Validate`); пути — только внутри наших каталогов.

### 4.3 Проверка одной цели
- **Адрес — через DoH**, как 02-spec §9.11: `curl https://8.8.8.8/resolve?name=<host>&type=A` (запасной — `https://1.1.1.1/dns-query?name=…`, `accept: application/dns-json`), затем запрос к цели с `--resolve <host>:443:<ip>`. Оценка не зависит от DNS роутера.
- `curl -sS -o /dev/null --connect-timeout 3 --max-time 8 --tlsv1.3 --tls-max 1.3 -w '%{http_code} %{size_download} %{redirect_url}' -D <tmp> --resolve … <url>` и то же с `1.2`; Content-Length — из заголовков.
- Успех — как 02-spec §4.3 п. 3. Коды выхода curl 18 (недочитано), 56 (сброс), 35 (TLS), 28 (таймаут) — провал с причиной.
- `kind: quic` — «не проверялась» (curl без HTTP/3).
- **Временные метки TCP.** Приём `--dpi-desync-fooling=ts` (10 из 20 стратегий каталога, в т. ч. alt9/alt13) работает, только если метки включены на устройстве-клиенте ([readme.md:378-380](https://github.com/bol-van/zapret/blob/v72.13/docs/readme.md)): в Linux/Android/iOS/macOS включены, в Windows — выключены по умолчанию. Сам роутер (Linux) их шлёт, поэтому подбор с роутера без мер находил бы стратегии, молча не работающие для компьютеров на Windows. Поэтому каждая стратегия с `ts` проверяется дважды: как есть и с `sysctl net.ipv4.tcp_timestamps=0` на время проверки (как клиент Windows; прежнее значение возвращается в любом случае, включая прерывание). Оценка — по проверке без меток; стратегия, прошедшая только с метками, помечается «нужны метки времени на устройствах» и при равенстве уступает.
- Две попытки с паузой 500 мс, до 8 запросов параллельно.

### 4.4 Выполнение
- Последовательно: прогон «без обхода» (`zapret stop`) → для каждой стратегии: записать config, перезапуск демона и правил (`restart_daemons` + `restart_fw`, сверить с init-скриптом; иначе `restart`), пауза 1 с, проверка → итог → автоприменение (§3.3).
- Отдельный процесс procd `dpishell-select`, прогресс — `/tmp/dpishell/select.json`, файл-замок от повторного запуска.
- Оценка, быстрый/полный режим, «блокировок не обнаружено» — как 02-spec §4.4.
- Пауза между стратегиями ≥ 300 мс; 3 подряд полных таймаута всех целей — стоп с сообщением «провайдер, похоже, временно ограничил соединения» (02-spec §4.7 п. 6).
- Параллельный подбор и изоляция подбора от клиентов — не в v1 (05-router-audit §5).

### 4.5 Глубокий поиск
Алгоритм — 02-spec §4.7 без изменений (раздельно по ролям `google`/`general`, грубый проход ~20, уточнение до 60 на роль, финал с готовыми, предпочтение меньшему числу пакетов). Генератор — на ucode, ограничен `options.json`. Найденное — в `/etc/dpishell/user-strategies.json`. Стратегии, найденные на ПК, приходят через `strategies_user_set` (07-router-api) и проверяются тем же `Validate`.

## 6. Стек и сборка

- ucode (rpcd, логика), LuCI JS (страницы), POSIX sh только в init-скрипте. Своих бинарников нет.
- Исходники — в этом репозитории: `router/dpishell/`, `router/luci-app-dpishell/`; данные берутся из `data/` при сборке.
- Сборка: GitHub Actions, `ghcr.io/openwrt/sdk` (snapshot/25.12), `apk mkpkg --sign-key` своим ключом (образец — `extra-feed.yml` сторонняя прошивка OpenWrt). Релиз GitHub + подписанный фид в gh-pages; пользователь один раз кладёт наш ключ в `/etc/apk/keys/`, без `--allow-untrusted`.
- Эмулятор (2026-10-17): QEMU (MSYS2) + OpenWRT 25.12.5 x86_64, `C:\Dev\owrt-vm` (`run.sh`, `ssh.sh` — порт 8022, LuCI — `127.0.0.1:8080`). Проверено в нём: ядро ставится из нашего zip (хеш совпал, распаковано 804 КБ, на флеше 516 КБ), init-скрипт zapret поднимает nfqws и таблицу `inet zapret` с нашими портами; запросы curl с роутера проходят через nfqws (журнал `--debug=syslog`: fake + multisplit). **Ограничение:** сеть QEMU `user` — программный прокси, пересобирающий TCP; обманные пакеты он доставляет как данные, соединение рвётся. Действие стратегий в эмуляторе не проверяется — только на роутере.
- Установка ядра — **не `install_easy.sh`**: он интерактивный и добавляет в cron ежедневную загрузку списков со сторонних адресов (`download_list`, `crontab_add 0 6`). Повторяем его шаги для OpenWRT сами: копия `common/`, `init.d/openwrt/`, `files/`, `ipset/`, `config.default` в `/opt/zapret`, `nfqws` нужной архитектуры → `/opt/zapret/nfq/nfqws`, наш `config`, ссылки `/etc/init.d/zapret` и `/etc/hotplug.d/iface/90-zapret`, `enable` + `restart`. Проверено в эмуляторе.
- Тесты: сборщик config на ucode — те же примеры, что тесты `WinwsArgs` (одна стратегия → одинаковые профили); проверка цели — на записанных ответах curl; страница и ubus — в эмуляторе OpenWRT (x86_64 в QEMU/Hyper-V) до появления роутера.

## 7. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Нет `kmod-nft-queue`/`curl`/`https-dns-proxy` | Пакет не ставится (зависимости); удалены позже — диагностика с текстом |
| GitHub и форк недоступны | Сообщение + «Загрузить файл ядра» (страница или приложение ПК) |
| Хеш архива/nfqws не совпал | Ядро не ставится, «файл повреждён или подменён» |
| `--dry-run` ≠ 0 | Стратегия «ошибка аргументов», подбор продолжается |
| Чужой обход работает | Включение и подбор заблокированы, «Остановить» |
| `flow_offloading=1` | Предупреждение, «Выключить»; подбор без подтверждения не стартует |
| Всё открывается без обхода | «Блокировок не обнаружено» |
| DoH недоступен при подборе | Резолв через DNS роутера с пометкой «DNS не проверен» в результатах |
| WAN упал во время подбора | Подбор прерван, прежнее состояние восстановлено |
| Перезагрузка во время подбора | `dpishell` при старте видит незавершённый подбор и восстанавливает прежнюю стратегию |
| Оба DoH-сервера пропали при включённом защищённом DNS | §3.8: временный возврат к DNS провайдера, предупреждение |
| sysupgrade | `/etc/config/dpishell`, `/etc/dpishell/` сохраняются (`/lib/upgrade/keep.d/dpishell`); пакеты и ядро — переустановка, страница подскажет |
| Нехватка места в overlay | Проверка `df` перед загрузкой ядра (zip ~8 МБ качается в `/tmp`, на флеш — ~2 МБ) |

## 8. Вне рамок первой версии

- zapret2/nfqws2; параллельный подбор; изоляция подбора от клиентов.
- Проверка QUIC на роутере (curl с HTTP/3), голос Discord.
- Разные стратегии для разных устройств; перехват DNS устройств с жёстко прописанным DNS.
- Синхронизация своих адресов и результатов ПК ↔ роутер (только ручное копирование).
- Правка hosts на роутере — **не трогать** (на ПК решено в `09-features-spec.md` §3; аналог на роутере — записи dnsmasq — во вторую версию, по тем же правилам проверки).
- Игровой режим и IP-списки (`09-features-spec.md` §1–2) — во вторую версию роутера: роли `game_tcp`/`game_udp` (порты 1024–65535 в `NFQWS_PORTS_*`, `--dpi-desync-any-protocol`), `ipset-all.txt` через `--ipset` в nfqws (не nft set — память, 05-router-audit §2), тот же валидатор списка. Набор ролей уже расширяемый (§4.2).
- `ipk`/`opkg` для OpenWRT 24.10; Keenetic/Entware; Merlin; заводская прошивка производитель (05-router-audit §1).
- Установка прошивки из нашего пакета.

## 9. Решения

1. Движок — nfqws из zapret v1 bol-van, тот же архив и манифест, что у Windows.
2. Интерфейс — LuCI + ucode; Windows-приложение управляет роутером через тот же ubus (`07-router-api.md`).
3. Каталог, цели, белый список параметров — общие с Windows.
4. Zapret Manager из сторонняя прошивка OpenWrt не используем.
5. Подбор — последовательно, с переключением боевого обхода; автоприменение лучшей.
6. Прошивка — сторонняя прошивка OpenWrt на роутер (модель, CN, x.y.z); установка после готовности Windows-приложения. Заводскую прошивку до этого не обновлять.
7. Проверка — кнопка и отключаемый таймер; при неудачах — запасные стратегии; автоподбор — по желанию, выключен по умолчанию (§3.5). Только на роутере: на ПК фоновой проверки нет.
8. Защищённый DNS для всей сети — в v1, по кнопке, с показом последствий и возвратом (провайдер пользователя подменяет DNS).
9. IPv6 у пользователя нет; проверка остаётся на случай смены провайдера. Wi-Fi 6 достаточно.

## 10. Проверка заимствованного

- Ядро: только `zapret-v72.13.zip` bol-van (или та же копия в форке с тем же хешем); хеш `nfqws` каждой архитектуры — из архива, зашит в манифест. Извлекаются только пути из `extract`.
- Скрипты zapret (`common/`, `init.d/openwrt/`, `install_*.sh`) исполняются как есть — часть того же архива; при смене версии — просмотр диффа.
- `https-dns-proxy` — пакет из официальных фидов OpenWRT (собирается фидом Beam из закреплённых коммитов); перед включением зависимости — сверить его наличие и версию в фиде Beam.
- Из готовых проектов (remittor, StressOzz, Beam, b4, nfqws2-ui) код не копируем — только схемы.
- Фид сторонняя прошивка OpenWrt — только для системных пакетов; подписан, собирается в CI (05-router-audit §4).
