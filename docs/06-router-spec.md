# ТЗ: DpiShell для роутера (OpenWRT)

Версия 0.1, 2026-10-16. Основание — `05-router-audit.md`; алгоритм подбора и критерий «сайт работает» — `02-spec.md` §4, здесь только отличия. Имена опций и скриптов zapret сверять с закреплённым релизом v72.13 перед реализацией.

## 1. Цель и пользователь

- Пользователь тот же, что у Windows-версии: в сетях не разбирается. Хочет: обход работает на всех устройствах дома (телефоны, ТВ, приставки, ПК), настраивается с телефона в браузере.
- Что делает пакет: ставит ядро обхода (nfqws + правила nftables из zapret), подбирает рабочую стратегию с самого роутера по проверяемым адресам, применяет её на всю сеть, показывает состояние на странице в меню роутера.
- Что не делает: VPN, смена DNS, правка hosts, прошивка роутера (установка OpenWRT — по инструкции сторонняя прошивка OpenWrt, вне пакета).
- Первая целевая платформа — роутер на сторонняя прошивка OpenWrt (OpenWRT main, `apk`, `aarch64_cortex-a73`). Пакет не привязан к модели: любой OpenWRT 25.12+ с nftables (fw4).

## 2. Основа и зависимости

### 2.1 Ядро
- Из релиза `bol-van/zapret` v72.13, файл `zapret-v72.13-openwrt-embedded.tar.gz` (sha256 `b2a9f454523264899e0e7ba19c662e59e29fb20ebb354aa3631cd76885f4c2e6`): `binaries/linux-<arch>/nfqws`, каталоги `common/`, `init.d/openwrt/`, `ipset/`, `files/fake/`, `install_bin.sh`, `install_easy.sh`, `config.default`.
- Манифест `data/core-router.json`: версия, URL, sha256 архива, sha256 `nfqws` по архитектурам (`linux-arm64/nfqws` = `75fc3d6352eb9ebf510dfa470797c5ea079c475755ae3c0a79b1e9aaaf0c37a6`; остальные — при подготовке манифеста из архива), список извлекаемых путей.
- Поставка — как на Windows (02-spec §9.2): ядро не кладём в пакет. При первом запуске роутер качает архив с GitHub bol-van, проверяет sha256 архива и `nfqws`, извлекает только файлы из списка в `/opt/zapret`. Если GitHub недоступен — загрузить архив через страницу (кнопка «Загрузить файл ядра»), проверка та же.
- Установка zapret — его же скриптами в неинтерактивном режиме (переменные окружения `install_easy.sh`), без `install_prereq.sh`: зависимости ставит наш пакет. Служба `/etc/init.d/zapret` и таблица `inet zapret` — штатные zapret. Мы пишем только `/opt/zapret/config`.

### 2.2 Зависимости пакета
`curl` (TLS 1.3 через mbedtls), `nftables`, `kmod-nft-queue`, `kmod-nft-nat`, `ucode`, `ucode-mod-fs`, `ucode-mod-uci`, `rpcd-mod-ucode`, `luci-base`. Все есть в фиде сторонняя прошивка OpenWrt и в официальных фидах 25.12.

### 2.3 Данные
- Из общего репозитория без изменений: `strategies.json`, `targets.json`, `lists/*.txt`, `fake/*.bin` (5 файлов Flowseal, которых нет в zapret; проверены в `03-vetting.md`).
- Новый общий файл `options.json` — список разрешённых параметров nfqws/winws (сейчас зашит в `Strategies.cs`). Windows и роутер проверяют каталог по нему.
- Поле `engine` в каталоге: `"winws"` → `"zapret1"` (один синтаксис у winws и nfqws). Windows-сборщик принимает оба значения на переходный период.

### 2.4 Лицензии
`/usr/share/dpishell/licenses/`: zapret (MIT), Flowseal (MIT). Наш пакет — MIT.

## 3. Функции (страница «Службы → DpiShell»)

### 3.1 Главный экран
- Состояние: «Выключено / Работает (стратегия N, проверено <время>) / Подбор… (k из N) / Ошибка (текст)».
- Кнопки: Включить/Выключить, Подобрать, Проверить сейчас.
- Строки предупреждений (если есть): «Включён flow offloading», «Провайдер выдаёт IPv6, обход по IPv6 выключен», «Рядом работает другой обход: …», «DNS провайдера подменяет адреса».
- Вёрстка — одна колонка карточек, читается на телефоне без масштабирования.

### 3.2 Включение/выключение
- «Включить» = записать `/opt/zapret/config` из выбранной стратегии (§4.2) → `/etc/init.d/zapret enable` → `restart`. Перед записью — проверка аргументов `nfqws --dry-run <NFQWS_OPT>` (код 0).
- «Выключить» = `/etc/init.d/zapret stop` + `disable`.
- Перед любым стартом — sha256 `/opt/zapret/nfqws/nfqws` (путь сверить с `install_bin.sh`) против манифеста; не совпал — «Файлы ядра изменены», кнопка «Переустановить ядро».

### 3.3 Автоподбор
- Диалог как в 02-spec §3.3: группы (YouTube, Discord, Свои адреса), режим (Быстрый / Полный), глубина (Основные / Глубокий).
- Предупреждение перед стартом: «На время подбора (~2–5 мин) обход для всей сети переключается между стратегиями; сайты на устройствах могут открываться с перебоями».
- Ход — прогресс и таблица «стратегия — % целей — время»; страницу можно закрыть, подбор продолжается на роутере; «Остановить».
- По завершении — рекомендация и «Применить»; без нажатия через 10 мин восстанавливается прежняя стратегия (или выключенное состояние). Результат — `/etc/dpishell/results/<дата>.json` (хранить 10 последних).

### 3.4 Свои адреса для проверки
Как 02-spec §3.4: домен или URL на строку, флаг «важный». Добавленные домены попадают в `user-general.txt`, галочку можно снять. Хранятся в `/etc/dpishell/user-targets.json` и `/etc/dpishell/lists/`.

### 3.5 Списки
Просмотр/правка `user-general.txt`, `user-exclude.txt`; стандартные — только просмотр и «Обновить» (манифест `data.json`, как Windows).

### 3.6 Проверка по расписанию
Варианты — вопрос 3 (§9). По умолчанию (до ответа): только по кнопке. Если включено — cron раз в N часов запускает «Проверить сейчас». Две неудачи подряд — статус «Стратегия перестала работать», кнопка «Подобрать». Автоматически стратегию не меняем.

### 3.7 Диагностика
- Чужие обходы: службы `zapret2`, `youtubeUnblock`, `b4`, пакет `zapret-manager-beam`, процессы `nfqws`/`nfqws2` не нашего запуска. Предложение остановить и отключить, с подтверждением.
- `uci get firewall.@defaults[0].flow_offloading` = 1 → предупреждение и кнопка «Выключить» (это делает и `install_easy.sh`).
- IPv6: глобальный адрес на `wan6` → «Включить обход по IPv6» (`DISABLE_IPV6=0`).
- DNS: сравнение ответа системного резолвера и DoH (`curl --doh-url`, если curl собран с DoH; иначе `nslookup <домен> 77.88.8.88`) — только предупреждение.
- «Сохранить отчёт»: версии, хеши, config zapret, `nft list table inet zapret`, хвост `logread`.

### 3.8 Короткий адрес
`/www/dpi/index.html` — переадресация на `/cgi-bin/luci/admin/services/dpishell`. В инструкции — `http://192.168.1.1/dpi` (или адрес роутера в сети пользователя).

## 4. Подбор на роутере (отличия от 02-spec §4)

### 4.1 Цели
`targets.json` общий. `handshake_only` = успешное соединение и ответ с любым кодом, кроме 400, тело не читается. Группа «Свои адреса» — своя на роутере, с ПК не синхронизируется (v1).

### 4.2 Сборка конфигурации zapret из стратегии
- `NFQWS_PORTS_TCP=80,443,2053,2083,2087,2096,8443`, `NFQWS_PORTS_UDP=443,19294-19344,50000-50100` (те же, что `--wf-*` в `WinwsArgs`).
- `NFQWS_OPT` = профили ролей в порядке `RoleOrder` через `--new`, с теми же `--filter-tcp/--filter-udp/--filter-l7/--hostlist/--ipset`, что в Windows-сборщике. `{lists}` → `/etc/dpishell/lists` и `/usr/share/dpishell/lists`, `{fake}` → `/usr/share/dpishell/fake`.
- `MODE_FILTER=none`, `FLOWOFFLOAD=none`, `DISABLE_IPV6` — по §3.7, `NFQWS_TCP_PKT_OUT/IN`, `NFQWS_UDP_PKT_OUT` — по умолчанию `config.default`.
- Сборщик проверяет каждый токен по `options.json` и шаблону значения (как `WinwsArgs.Validate`); пути — только внутри наших каталогов.

### 4.3 Проверка одной цели
- `curl -sS -o /dev/null --connect-timeout 3 --max-time 8 --tlsv1.3 --tls-max 1.3 -w '%{http_code} %{size_download} %{redirect_url} %{content_type}' -D <tmp> <url>` и то же с `1.2`. Content-Length — из заголовков `-D`.
- Успех — как 02-spec §4.3 п. 3: код ≠ 400, редирект только на тот же базовый домен, `size_download >= Content-Length` и `>= min_bytes`. Коды выхода curl 18 (недочитано), 56 (сброс), 35 (TLS) — провал с причиной.
- `kind: quic` — «не проверялась» (curl без HTTP/3).
- Две попытки с паузой 500 мс, до 8 запросов параллельно (`xargs -P` или фоновые процессы ucode).

### 4.4 Выполнение
- Последовательно: запомнить текущее состояние → прогон «без обхода» (`/etc/init.d/zapret stop`) → для каждой стратегии: записать config, `restart_daemons` + `restart_fw` (сверить с командами init-скрипта; полный `restart` — если быстрых нет), пауза 1 с, проверка целей → итог → восстановить прежнее, пока пользователь не нажал «Применить».
- Подбор идёт отдельным процессом procd (`dpishell-select`), прогресс пишет в `/tmp/dpishell/select.json`, страница читает его раз в секунду через ubus. Повторный запуск при идущем подборе запрещён (файл-замок).
- Оценка стратегии, быстрый/полный режим, «блокировок не обнаружено» — как 02-spec §4.4.
- Изоляция подбора от клиентов (отдельная очередь + `tcp sport`) — эксперимент после v1 (05-router-audit §5).

## 5. Архитектура

```
dpishell (PKGARCH:=all, apk)
  /usr/share/dpishell/        strategies.json, targets.json, options.json, core-router.json, lists/, fake/, licenses/
  /usr/libexec/dpishell/
    core.uc                   загрузка ядра по манифесту, проверка хешей, установка zapret
    catalog.uc                чтение каталога, проверка по options.json, сборка config zapret
    probe.uc                  проверка цели через curl, разбор результата
    select.uc                 подбор (запускается procd-инстансом)
    diag.uc                   диагностика, отчёт
  /usr/share/rpcd/ucode/dpishell.uc       ubus-объект dpishell (методы ниже)
  /usr/share/rpcd/acl.d/luci-app-dpishell.json   права: только ubus dpishell.*
  /etc/init.d/dpishell        procd: статус, status.json, cron-проверка
  /etc/config/dpishell        uci: enabled, strategy, groups, schedule, ipv6
  /etc/dpishell/              user-targets.json, lists/user-*.txt, results/  (сохраняются при sysupgrade)
  /www/dpi/index.html         переадресация
  /www/dpishell/status.json   публичный статус для Windows-версии (§5.2)
luci-app-dpishell (PKGARCH:=all)
  /www/luci-static/resources/view/dpishell/{status,select,targets,lists,diag}.js
  /usr/share/luci/menu.d/luci-app-dpishell.json
```

### 5.1 ubus-методы `dpishell`
Чтение: `status`, `select_progress`, `targets_get`, `lists_get`, `results`, `diag`. Запись: `enable`, `disable`, `check_now`, `select_start`, `select_cancel`, `apply`, `targets_set`, `lists_set`, `core_install`, `report`. Каждый метод проверяет входные данные сам; ни один не принимает командную строку или путь от клиента. В ACL нет `file.exec`, `file.write` и чужих ubus-объектов (образец — `luci-app-youtubeUnblock`).

### 5.2 `status.json` для Windows-версии
```json
{ "product": "dpishell-router", "version": "0.1.0", "engine": "zapret1", "core": "v72.13",
  "enabled": true, "strategy": "alt10", "catalog_version": 3, "checked_at": "2026-10-16T21:00:00Z", "last_check_ok": true }
```
Обновляется при изменении состояния. Без адресов, списков, логов. Доступен из LAN (uhttpd по умолчанию слушает LAN; с WAN закрыт fw4).

### 5.3 Изменения в Windows-версии
- `DpiShell.Core/RouterDetect`: при запуске и смене сети — `GET http://<основной шлюз>/dpishell/status.json`, таймаут 1 с, `product == "dpishell-router"`.
- `enabled: true` → главный экран «Обход делает роутер (стратегия N)»; «Включить» на ПК — с предупреждением о двойной обработке. Подбор на ПК в такой сети не предлагается, «Проверить сейчас» доступна (проверяет путь клиента).
- Каталог: `engine` `zapret1`, список параметров — из `options.json`.

## 6. Стек и сборка

- ucode (rpcd, логика), LuCI JS (страницы), POSIX sh только в init-скрипте. Своих бинарников нет.
- Исходники — в этом же репозитории: `router/dpishell/Makefile`, `router/luci-app-dpishell/Makefile`, файлы данных берутся из `data/` при сборке.
- Сборка: GitHub Actions, `ghcr.io/openwrt/sdk` (snapshot/25.12), `apk mkpkg --sign-key` своим ключом (образец — `extra-feed.yml` сторонняя прошивка OpenWrt). Публикация — релиз GitHub + подписанный фид в gh-pages. Пользователь один раз кладёт наш публичный ключ в `/etc/apk/keys/`; `--allow-untrusted` в инструкции нет.
- Тесты: unit-тесты сборщика config на ucode (`ucode -L … test/*.uc`) с теми же примерами, что тесты `WinwsArgs` в C#: одна стратегия → одинаковый набор профилей.

## 7. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Нет `kmod-nft-queue`/`curl` | Пакет не ставится (зависимости); если удалены позже — диагностика, текст «установите …» |
| GitHub недоступен при загрузке ядра | Сообщение + загрузка архива через страницу |
| Хеш архива/nfqws не совпал | Ядро не ставится, сообщение «файл повреждён или подменён» |
| `--dry-run` ≠ 0 | Стратегия «ошибка аргументов», подбор продолжается |
| Чужой обход работает | Подбор и включение не стартуют, предложение остановить |
| `flow_offloading=1` | Предупреждение, кнопка «Выключить»; подбор не стартует без подтверждения |
| Всё открывается без обхода | «Блокировок не обнаружено» (или у роутера VPN на WAN) |
| WAN упал во время подбора | Подбор прерван, прежнее состояние восстановлено |
| Перезагрузка во время подбора | При старте `dpishell` видит незавершённый подбор → восстанавливает прежнюю стратегию |
| Прошивка обновлена (sysupgrade) | `/etc/config/dpishell` и `/etc/dpishell/` сохраняются (`/lib/upgrade/keep.d/dpishell`); пакеты и ядро — переустановка из фида, страница подскажет |
| Нехватка места в overlay | Проверка `df` перед загрузкой ядра (нужно ~4 МБ), сообщение |

## 9. Решения и открытые вопросы

Принято (по 05-router-audit): движок — nfqws из zapret v1 bol-van по закреплённому хешу; интерфейс — LuCI + ucode; каталог и цели — общие с Windows; Zapret Manager из сторонняя прошивка OpenWrt не используем; подбор — последовательно, с переключением боевого обхода.

## 10. Проверка заимствованного

- Ядро: только `zapret-v72.13-openwrt-embedded.tar.gz` с GitHub bol-van; хеш архива — как в digest GitHub (сверено 2026-10-16); хеш `nfqws` каждой архитектуры — из архива, зашит в манифест. Извлекаются только перечисленные пути.
- Скрипты zapret (`common/`, `init.d/openwrt/`, `install_*.sh`) исполняются как есть — это часть того же проверенного архива; перед закреплением новой версии — просмотр диффа между версиями.
- Из готовых проектов (remittor, StressOzz, Beam, b4, nfqws2-ui) код не копируем — только схемы.
- Фид сторонняя прошивка OpenWrt используем только для системных пакетов (`curl`, `kmod-nft-queue` и т. п.); он подписан и собирается в CI из закреплённых коммитов (05-router-audit §4).
