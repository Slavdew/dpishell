# Выгрузка и загрузка настроек — формат пакета (версия 1)

Пакет — **папка текстовых файлов**: по файлу на раздел и `manifest.json`. Один формат для DpiShell на Windows и для роутера с OpenWrt (LuCI «Выгрузить/Загрузить»): настройки переносятся ПК ↔ роутер и между людьми. Формат не привязан к путям Windows: имена файлов в нём — только `латиница`, цифры, `_`, `-`, `.`.

Код на стороне Windows — `src/DpiShell.Core/Export/` (`SettingsExport`, `SettingsImport`), команды помощника `settings_export_read` и `settings_import` (протокол 1.11, `docs/dev/helper-protocol.md`).

## Общие правила

- Кодировка UTF-8 без BOM, переводы строк LF (читаются и CRLF).
- Текстовые файлы: **одна запись в строке**, пустые строки и строки, начинающиеся с `#`, — комментарии (в `hosts.txt` комментарий допустим и после записи). Выгрузка пишет первой строкой `# DpiShell settings: …`.
- Где запись — не строка (профиль игры, «свои настройки для сайтов», DNS), файл — JSON. Поля `snake_case`, лишние и повторяющиеся поля — ошибка файла (раздел пропускается).
- **Читающий не доверяет файлу.** Размер файла и число строк ограничены до разбора; ссылки (reparse point/symlink), вложенные папки и файлы с чужими именами не читаются; текст — строгий UTF-8, без нулевых байтов. Раздел с ошибкой пропускается целиком с причиной, остальные читаются. Запись с ошибкой внутри раздела отбрасывается с причиной (номер строки), остальные принимаются.
- Пустые разделы не выгружаются (иначе «заменить» стёрло бы чужие настройки); раздел без единой принятой записи при загрузке пропускается.
- **Никогда не выгружаются**: системный прокси, пароль и адрес роутера, историю и результаты подборов, статистику стратегий, адреса этого ПК и сети, журналы, токены, состояние подбора («итог» для `auto`).

## manifest.json

```json
{
  "format": 1,
  "app": "DpiShell",
  "app_version": "0.10.0",
  "created": "2026-10-20T12:00:00Z",
  "sections": ["sites", "exclude", "strategies"],
  "provider": "Название провайдера (необязательно, без адресов)",
  "note": "Заметка автора (необязательно)"
}
```

- `format` — версия формата. Читающий принимает ровно свою (1). Больше — «выгрузка сделана более новой версией, обновите программу»; нет или меньше 1 — «неизвестный формат». Папка целиком не читается.
- `app`, `app_version` — кто и какой версией сделал (для информации; роутер пишет свои). `created` — ISO 8601 UTC.
- `sections` — какие разделы есть (из списка ниже). Читаются только перечисленные; неизвестные имена игнорируются.
- `provider`, `note` — свободный текст в одну строку (до 60 и 500 знаков, управляющие знаки убираются). Показывается при загрузке.
- Размер файла не больше 16 КБ.

## Разделы

| Раздел | Файл | Формат | Записей и размер (предел) | Риск |
|---|---|---|---|---|
| `sites` — свои сайты | `sites.txt` | домен в строке | 1000; 100 КБ | |
| `exclude` — «Открывать без оптимизации» | `exclude.txt` | домен в строке | 200; 50 КБ | |
| `strategies` — свои и найденные стратегии | `strategies/<имя>.txt` | см. ниже | 50 файлов; 16 КБ на файл | |
| `advanced` — «свои настройки для сайтов» | `advanced.json` | JSON | 20 строк; 64 КБ | |
| `apps` — профили игр и программ | `apps/<имя>.json` | JSON, файл на профиль | 8 файлов; 64 КБ на файл | |
| `subnets` — свои IP-подсети и исключения | `subnets.txt`, `subnets-exclude.txt` | CIDR в строке | 10 000 в каждом; 512 КБ | |
| `hosts` — свои строки hosts | `hosts.txt` | `адрес имя` в строке | 500; 64 КБ | **risky** |
| `dns` — выбранный DNS | `dns.json` | JSON | 1 вариант; 4 КБ | risky при `custom` |

Строк в текстовом файле допускается не больше «записей + 200» (на комментарии), иначе файл отклоняется.

### Домены (`sites.txt`, `exclude.txt`)
Строгий разбор, как у «Своих сайтов»: `example.com`; регистр приводится к нижнему, `https://` и `www.` снимаются, русские имена — в punycode. Всё, что не имя сайта (пробелы, `*`, `^`, путь, порт), — строка отбрасывается. Повторы убираются.

### Стратегии (`strategies/<имя>.txt`)
Файл — **один** текст в формате «Скопировать параметры»/«Вставить стратегию»: строка `dpishell:1:<base64url(deflate(json))>`, где json — `{"title": …, "roles": {роль: параметры}}`. Перед ней — строки-комментарии (`# DpiShell strategy: <название>`). Строка из `.bat` Flowseal в пакете не принимается.
- Имя файла — `<имя>.txt`, имя: `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`, без `..`, без точки в конце. Путь, слеши, диски, абсолютные пути — файл отклоняется.
- Параметры проверяются белым списком winws (роли, разрешённые параметры; файлы фейков — только `{fake}/имя.bin` **из папки фейков этого ПК** — иначе стратегия пропускается с причиной «файла нет в папке программы»).
- Выгружаются свои (`user`, `pasted`) и найденные поиском (`search`); готовые из каталога и смешанные (их собирает программа) — нет.

### Свои настройки для сайтов (`advanced.json`)
```json
{ "enabled": true, "others": "lists",
  "rows": [
    { "domains": ["example.com", "example.org"], "strategy": "auto" },
    { "domains": ["video.example"], "strategy": "direct" },
    { "domains": ["game.example"], "strategy_file": "my-strategy" }
  ] }
```
- `others`: `direct` | `lists` | `all`. `strategy`: `auto`, `direct` или id готовой стратегии каталога. Своя/найденная стратегия — ссылкой `strategy_file` на имя файла из `strategies/` (id своих стратегий у людей разные). Одновременно `strategy` и `strategy_file` нельзя.
- Ссылка на стратегию, которой нет ни в пакете (и не выбран раздел `strategies`), ни среди имеющихся на этом ПК такой же по параметрам, — строка пропускается с причиной.
- Сайты — как выше; не больше 50 в строке, 20 строк.

### Профили игр и программ (`apps/<имя>.json`)
```json
{ "title": "Игра", "tcp": "443,27015", "udp": "27015-27030",
  "addresses": ["203.0.113.0/24", "198.51.100.7/32"],
  "tcp_desync": "--dpi-desync=fake …", "udp_desync": "--dpi-desync=fake …" }
```
- Порты — канонический вид «443,27015-27030» (до 16 диапазонов); хотя бы TCP или UDP. Адреса — подсети/адреса (1–500), без служебных сетей и шире /16 (IPv4) / /48 (IPv6).
- `tcp_desync`/`udp_desync` — параметры игровых ролей, проходят тот же белый список winws. На этом ПК профиль привязывается к варианту параметров, у которого параметры **совпадают**; нет подходящего — профиль пропускается с причиной.

### Подсети (`subnets.txt`, `subnets-exclude.txt`)
CIDR (`203.0.113.0/24`) или одиночный адрес в строке; канонический вид, без служебных сетей (частные, loopback, мультикаст…), без слишком широких (шире /16 для IPv4, /32 для IPv6).

### hosts (`hosts.txt`) — **risky**
Одна строка — `<публичный IP> <имя сайта>`, ровно два слова. Адрес обязан быть публичным: `127.*`, `0.0.0.0`, частные, link-local и прочие служебные сети отклоняются — значит подмена `localhost` и системных имён не проходит. Имя — настоящее имя сайта (есть точка, без маски, порта и пути). Подмена адресов в hosts — путь к фишингу, поэтому окно **снимает галочку раздела по умолчанию и показывает строки**; помощник каждую новую строку ещё проверяет живым подключением (сертификат должен быть выдан этому сайту).

### DNS (`dns.json`)
```json
{ "choice": "google" }
{ "choice": "custom", "ips": ["1.1.1.1", "9.9.9.9"], "doh": "https://dns.example/dns-query" }
```
`choice` — id готового варианта (`auto`, `google`, `cloudflare`, `quad9`, `yandex`) или `custom` (тогда 1–4 адреса сервера и необязательный шаблон `https://…`). У готового варианта своих `ips`/`doh` быть не может. Своя пара адресов — тоже `risky` (чужой DNS-сервер видит и может подменять ответы).

## Как сливать

| Раздел | «Добавить к своим» | «Заменить» |
|---|---|---|
| sites, exclude, hosts, subnets (оба файла) | свои + новые (без повторов), пока не упрёмся в предел; сверх предела — пропуск | остаются только пришедшие; своих, которых нет в пакете, не остаётся |
| strategies | добавляются те, которых ещё нет (сверка по параметрам со всеми имеющимися); сохраняются как «вставленные» под новым id | то же: **стратегии не удаляются** (выбранная и запасные ссылаются на них) |
| advanced | к своим строкам добавляются новые (одинаковая пара «сайты + стратегия» не повторяется, до 20); режим работы свой, если своих строк нет и режим выключен — пакета | строки и режим (`enabled`, `others`) — пакета |
| apps | добавляются профили, которых нет (до 8) | профили, которых нет в пакете, убираются; пришедшие добавляются |
| dns | выбор один: ставится пришедший вариант, если он не тот, что уже стоит | то же |

Перед записью окно показывает **план**: по каждому разделу — что добавится, что заменится/уйдёт, что уже есть, что пропущено и почему.

## Применение на Windows

Данные пишет только помощник (папка данных закрыта для окна). Окно отправляет проверенный план командой `settings_import`; помощник **проверяет его заново и окну не доверяет** (любая запись, не прошедшая правила без правки, — отказ целиком), сам считает план по своему состоянию и применяет разделы теми же правилами, что и обычные кнопки. Запись в журнале изменений (тип `settings_import`, «Загружены настройки из файлов: …») делается до первой правки; «Отменить всё» возвращает прежние сайты, исключения, подсети, убирает добавленные стратегии (кроме выбранной) и возвращает профили, убранные «заменить». Профили, продвинутый режим, hosts и DNS откатываются своими записями журнала.
