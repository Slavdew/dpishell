# Аудит: DpiShell на роутере (OpenWRT)

Дата: 2026-10-16. Только чтение источников, на роутере и в сети пользователя ничего не делалось. Роутер пользователя — **роутер**. Подробные заметки со ссылками — `docs/research/router-*.md`.

## Итог

1. **Делаем.** роутер (Qualcomm SoC, 4×A73, 1 ГБ ОЗУ, 128 МБ NAND) — ресурсов с огромным запасом.
2. **Официального OpenWRT для роутер нет**; есть неофициальный порт **сторонняя прошивка OpenWrt** (автор прошивки): два слота, сток остаётся во втором, откат кнопкой. Главный риск — проекту меньше месяца, релизы почти ежедневно, один автор.
3. **Движок — тот же nfqws из zapret v1 (bol-van v72.13)**, что и winws на Windows: один исходник, все параметры нашего каталога есть. Бинарник берём из релиза bol-van по закреплённому хешу (сверен: `linux-arm64/nfqws` = `75fc3d63…37a6`).
4. **Каталог стратегий и цели — общие с Windows.** Меняется только обвязка: `--wf-tcp/--wf-udp` → порты в config zapret.
5. **Готового решения под наше ТЗ нет.** remittor/luci-app-zapret — без автоподбора и с широкими правами; Zapret Manager (StressOzz, он же встроен в сторонняя прошивка OpenWrt) — без лицензии, исполняет скачанный код без проверки. Берём идеи, делаем своё.
6. **Своё = пакет `dpishell` (LuCI-страница на JS + rpcd на ucode + подбор на curl)**, официальные скрипты zapret для правил nftables. Без своих бинарников: один пакет на все архитектуры.
7. **Подбор — с самого роутера**: трафик роутера идёт через те же правила nfqws, что и трафик клиентов. curl 8.22 в OpenWRT 25.12 умеет TLS 1.3 и чтение тела; HTTP/3 не умеет — QUIC на роутере «не проверялся».
8. **Веб-интерфейс** — в меню роутера (LuCI), вход по паролю роутера; короткий адрес `http://192.168.1.1/dpi`.
9. **Windows-версия видит роутер** по файлу `http://<шлюз>/dpishell/status.json` и не включает свой обход.
10. Запасной путь, если сторонняя прошивка OpenWrt не подойдёт: мини-плата NanoPi R3S (~$30–40) с OpenWRT как шлюз, производитель остаётся на стоке; тот же пакет.

## 1. Роутер пользователя: роутер

| Параметр | Значение |
|---|---|
| SoC / арх. | Qualcomm SoC rev 1.1, 4×Cortex-A73, `aarch64_cortex-a73` ([PR #20604](https://github.com/openwrt/openwrt/pull/20604)) |
| ОЗУ / флеш | 1 ГиБ DDR4 / 128 МиБ SPI-NAND |
| Плата | модель (код в [эксплойт](https://github.com/openwrt-производитель/эксплойт/blob/main/xqmodel.py)) |
| Порты | 4×2.5G, USB 3.0 |

**Официальный OpenWRT** — нет. Единственный PR в основной репозиторий ([#20604](https://github.com/openwrt/openwrt/pull/20604)) открыт с 2025-10, не влит, Wi-Fi в нём нет; в firmware-selector устройства нет.

**сторонняя прошивка OpenWrt** ([автор прошивки/роутер](https://example.org/firmware)) — неофициальный порт:
- Создан 2026-09-21, 28★, v1.4.8 (2026-10-11), пять релизов за неделю. Сборка в GitHub Actions из открытых исходников, `sha256sums.txt` в релизе. Ядро 6.18, OpenWRT main, пакетный менеджер `apk`, свой подписанный фид (600+ пакетов).
- Работает: гигабит ~940 Мбит/с, 2.5G, Wi-Fi 2.4/5 ГГц, Wi-Fi 7 EHT80, PPPoE, обновление с сохранением настроек. Не работает: 6 ГГц. При коде страны RU радио отключает Wi-Fi 7 — работает как Wi-Fi 6.
- Копии репозитория (zh8416, iroham «MiWRT», anupamme, xiaoqi2020) — это GitHub-форки оригинала, а не подделки, но образы у каждой копии собраны отдельно и не совпадают по хешам. **Ставить только оригинал.** MiincK из выдачи поиска уже удалён.
- `/overlay` ~20 МБ — нашему пакету хватит (мы занимаем 2–4 МБ); больше — через USB-extroot.

**Как ставится и чем рискуем** ([инструкция](https://example.org/firmware)):
- SSH на заводской прошивке — через эксплойт (эксплойт + пароль root). На стоке x.y.z эксплойт иногда не срабатывает ([#169](https://github.com/openwrt-производитель/эксплойт/issues/169)) — совет: откатиться на x.y.z.
- Два слота: сторонняя прошивка OpenWrt пишется во второй, сток остаётся. Если не загрузилась — автоматический откат; ручной откат — страница «Слоты», скрипт или заводской интерфейс Repair Tool.
- Смертельно только трогать загрузчик (APPSBL); штатная установка его не трогает. Единственный известный «кирпич» в обсуждениях — от ручной записи U-Boot.

**zapret на стоковой прошивке без OpenWRT** — готовых инструкций нет, ядро закрытое (5.4), обновление прошивки всё сотрёт. Не рекомендуется.

Другие модели производитель (на случай замены роутера) — в `research/router-производитель.md`. Ловушки: AX3000T выпуска 2025 (RD03V2, IPQ5018) и BE3600/BE5000 (IPQ53xx) OpenWRT не поддерживают.

## 2. zapret на OpenWRT

**Установка по документации bol-van v72.13** ([quick_start.md](https://github.com/bol-van/zapret/blob/v72.13/docs/quick_start.md)):
- Релиз `zapret-v72.13-openwrt-embedded.tar.gz` (sha256 `b2a9f454…c2e6`, совпадает с digest GitHub): бинарники `binaries/linux-{arm,arm64,mips,mipsel,…}/nfqws`, скрипты, фейки.
- `install_bin.sh` выбирает архитектуру; `install_easy.sh` ставит в `/opt/zapret`, понимает и `opkg`, и `apk` (OpenWRT 25.12 перешёл на apk).
- Пакеты: `curl nftables kmod-nft-nat kmod-nft-offload kmod-nft-queue`. В базовом образе сторонняя прошивка OpenWrt нет `kmod-nft-queue` и `curl` — ставятся из фида Beam.
- Служба — procd (`/etc/init.d/zapret`). Конфиг `/opt/zapret/config`: `NFQWS_OPT` (профили через `--new`), `NFQWS_PORTS_TCP/UDP`, `MODE_FILTER`, `FLOWOFFLOAD`, `DISABLE_IPV6`. Своя таблица nft `inet zapret`, правила fw4 не трогаются.
- Официального пакета zapret в репозиториях OpenWRT нет.

**Как ловится трафик** ([nft.sh](https://github.com/bol-van/zapret/blob/v72.13/common/nft.sh)):
- Правило `oifname @wanif tcp dport {…} ct original packets 1-9 queue num 200 bypass` в цепочке postrouting после NAT. nfqws видит только первые пакеты соединения, поэтому нагрузка на CPU мала. На слабых MIPS без этого ограничения nfqws подвешивал роутер ([#56](https://github.com/bol-van/zapret/issues/56)) — к роутер не относится.
- Hook postrouting видит **и транзитный трафик клиентов, и трафик самого роутера**; фильтра по пользователю у правил nfqws нет. Поэтому curl на роутере проходит через ту же стратегию, что и устройства в сети. На этом держится подбор с роутера.
- Отличия «с роутера» и «через роутер»: `badsum` на роутерах MediaTek через роутер не проходит (для Qualcomm роутер — не проверено); `datanoack` ломает NAT только с iptables. Наш каталог использует `ts`, `badseq`, `md5sig` — не затронуты.
- **Системный flow offloading несовместим с nfqws**: соединение, попавшее в flowtable, nfqws больше не видит. Установщик zapret выключает его сам. В сторонняя прошивка OpenWrt есть аппаратная разгрузка NAT (PPE) — по умолчанию выключена, должна оставаться выключенной или не должна мешать (не проверено).
- IPv6 в zapret по умолчанию выключен. Если провайдер даёт IPv6, YouTube пойдёт мимо обхода — нужно включать IPv6 в zapret или предупреждать.

**blockcheck.sh на роутере** — умеет работать без вопросов (`BATCH=1 DOMAINS=… SCANLEVEL=quick`), вывод можно разобрать. Но HTTPS по умолчанию проверяет запросом HEAD, тело не читает; нет групп целей, нет порога 20 КБ, нет стратегий из нескольких профилей (QUIC + Discord + TCP разом). **Как основа подбора не годится**; полезен как источник порядка перебора (tier 2 нашего каталога) и проверки подмены DNS.

**curl в OpenWRT 25.12** ([Makefile](https://github.com/openwrt/packages/blob/openwrt-25.12/net/curl/Makefile)): версия 8.22, TLS через mbedtls 3.6 — TLS 1.3 есть. HTTP/3 выключен при сборке (нужна OpenSSL-сборка) → QUIC-цели на роутере «не проверялись», как и на Windows без HTTP/3. Отпечаток TLS у curl не такой, как у браузера, — стратегия может отличаться в редких случаях; проверка с ПК закрывает это (раздел 5).

## 3. Перенос каталога winws → nfqws

- `nfqws.c` и `winws` — один исходник; Windows-только опции: `--wf-*`, `--ssid-filter`, `--nlm-filter`. **Все десинк-параметры `data/strategies.json` (около 30) есть в nfqws v72.13** — таблица в `research/router-nfqws.md` §5.
- В сборщике командной строки меняется:
  - `--wf-tcp=80,443,2053,2083,2087,2096,8443` → `NFQWS_PORTS_TCP` в config;
  - `--wf-udp=443,19294-19344,50000-50100` → `NFQWS_PORTS_UDP`;
  - `--qnum`, `--user`, `--dpi-desync-fwmark` добавляет init-скрипт zapret;
  - профили ролей (`--filter-tcp/udp … --hostlist … --new`) идут в `NFQWS_OPT` без изменений, `MODE_FILTER=none`.
- `{fake}/*.bin`: в zapret есть 3 из 8 используемых; остальные 5 (Flowseal: `ACTIVE_DISCORD_UDP`, `max_ru`, `4pda_to`, `stun2`, `sochi_park`) везём в пакете — они уже проверены (`03-vetting.md`).
- Встроенный фейк `--dpi-desync-fake-tls=!` в каталоге записан правильно (без `^` из .bat) — проверено.

## 5. Веб-интерфейс и подбор на роутере

**LuCI-приложение против отдельного сервиса:**

| | LuCI (JS + rpcd на ucode) | Отдельный сервис (Go / shell + uhttpd) |
|---|---|---|
| Где | меню роутера «Службы → DpiShell» | свой порт |
| Вход | пароль роутера, сессии LuCI | писать самим |
| Права | ACL rpcd: только наши ubus-методы | сервис от root, проверка прав — сами |
| Размер | десятки КБ, без бинарников | Go-бинарник 2–5 МБ под каждую архитектуру |
| Телефон | тема Bootstrap адаптивная; наша страница — простые карточки | любая вёрстка |

**Берём LuCI**: вход, HTTPS при желании и права уже есть. ucode — родной язык rpcd в OpenWRT 23+: JSON и файлы без внешних зависимостей. Короткий адрес `http://192.168.1.1/dpi` — статическая страница с переадресацией в LuCI.

**Подбор с роутера:**
- curl с роутера проходит через те же правила, что и клиенты (раздел 2), поэтому проверка честная.
- Чтение тела: `curl -o /dev/null -w '%{http_code} %{size_download} %{redirect_url}'`; обрыв даёт код выхода 18/56. Тот же критерий, что `02-spec` §4.3.
- Во время подбора обход для всей сети переключается на проверяемую стратегию: тестируем ровно ту обвязку, что потом применится. Клиенты на ~3 минуты могут потерять обход — так же, как на Windows останавливается служба.
- Изоляция подбора от клиентов (отдельный nfqws на своей очереди, curl с диапазона исходных портов, `tcp sport` в nft) реалистична и проще, чем на WinDivert. Но пакет, отпущенный тестовой очередью, пойдёт дальше в боевую цепочку zapret — нужна метка-исключение. **Не проверено** → эксперимент, не v1.

## 6. Связь с Windows-версией

- **Каталог и цели — одни файлы** (`data/strategies.json`, `data/targets.json`). В каталоге поле `engine: "winws"` → `"zapret1"` (общий синтаксис winws/nfqws). Список разрешённых параметров переезжает из `Strategies.cs` в `data/options.json`, чтобы роутер проверял каталог тем же списком.
- **Windows видит роутер**: роутер публикует `http://<шлюз>/dpishell/status.json` (без секретов: версия, включено, стратегия, время последней проверки). Windows при запуске и смене сети читает его с таймаутом 1 с. Если обход на роутере включён — статус «Обход делает роутер», кнопка «Включить» с предупреждением: двойная обработка ломает соединения.
- Проверка «без обхода» на Windows (02-spec §4.4) в домашней сети покажет «блокировок нет» — это и есть подтверждение, что роутер работает. «Проверить сейчас» на ПК проверяет путь клиента — закрывает расхождение отпечатков curl и браузера.

## 7. Альтернативы, если сторонняя прошивка OpenWrt не подойдёт

- **Мини-плата как шлюз** (NanoPi R3S, $25–42, OpenWRT/FriendlyWrt; GL.iNet MT3000/MT6000, $99–170, OpenWRT из коробки): производитель на стоке работает как точка доступа или за платой. Наш пакет ставится без изменений. Минус — лишняя коробка, нужно перестроить подключение.
- **Keenetic + Entware**: nfqws-keenetic + веб, официальная прошивка стабильна; страницу в меню роутера не встроить — только отдельный порт.
- **ASUS Merlin + Entware**: zapret вручную, готового интерфейса нет.
- **Готовое b4 вместо своего**: закрывает задачу уже сейчас, но движок не zapret — каталог и проверка из `03-vetting` не переносятся.

## 8. Подводные камни

| Что | Чем грозит | Что делаем |
|---|---|---|
| сторонняя прошивка OpenWrt молодой и с частыми релизами | регрессии, проект может заглохнуть | ставить проверенный релиз, обновлять не сразу; запасной путь — мини-плата; сток во втором слоте |
| Zapret Manager из Beam или чужой zapret рядом | два nfqws на одних очередях | диагностика ищет `zapret`, `zapret2`, `youtubeUnblock`, `b4`, Zapret Manager и предлагает остановить |
| Flow offload / PPE | обход не срабатывает на части соединений | при старте проверять `flow_offloading` в uci, предупреждать |
| Тариф пользователя ~800 Мбит/с, NAT без разгрузки | упор в CPU роутера | сторонняя прошивка OpenWrt даёт ~940 Мбит/с по кабелю при выключенной по умолчанию PPE-разгрузке; nfqws видит только первые пакеты. Замерить скорость до и после включения обхода (не проверено) |
| IPv6 от провайдера | обход идёт мимо по v6 | при глобальном адресе на wan6 — включать IPv6 в zapret |
| Подмена DNS провайдером | стратегия «не работает» на правильном IP | предупреждение (как 02-spec §4.3); DNS роутера не меняем в v1 |
| Регион RU в сторонняя прошивка OpenWrt | Wi-Fi 7 работает как Wi-Fi 6 | пользователю Wi-Fi 6 достаточно; упомянуть в инструкции |
| Обновление прошивки затирает пакеты | обход пропал | пакет из фида переустанавливается; конфиг в `/etc/config/dpishell` сохраняется sysupgrade |
